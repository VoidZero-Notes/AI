11 把一轮次收成 `Agent.invoke`：调用方丢进一句 `q`，内部跑完 ReAct 才返回。13 / 14 分别给提示词和外部工具做了按需接入。一轮次里的圈数仍由模型决定——任务一大，同一条 Session 会堆进 ORM、DTO、接口、测试、报错重试，上下文爆炸。16 要收的是：把大任务切成若干独立轮次，每段自己一条 Session，父代理只拿各段的最终结果。名字叫子代理。

考虑这么一种场景：完成一个业务功能开发，并暴露为 FastAPI 接口。如果让一个 Agent 单独做完，在**一个轮次**里它会经历：

- reasoning：需求分析、方案设计
- 一个超级庞大的 ReAct 循环
  - 建立 ORM 数据层
  - 实现数据迁移
  - 执行迁移命令
  - 创建 DTO
  - 创建 Service
  - 创建接口
  - 创建多个测试脚本
  - 运行测试脚本
  - 解决错误（循环）

你最终会得到一个超级庞大的上下文。每一圈 Thought 都要把前面所有 assistant / tool 再发给模型——07 的历史不可改，10 的 Observation 只会追加、不会清掉。圈数一多，窗口被过程占满，后面的决策反而更差。

刚才的例子，更友好的设计是：

- reasoning：仅宏观需求分析、方案设计
- ReAct 循环
  - 子代理：实现数据层
  - 子代理：实现 DTO
  - 子代理：实现接口
  - 子代理：完成测试
  - 等待所有子代理完成，汇总结果

父代理的 Session 里，中间那些读文件、写文件、跑测试**不会出现**。它只看见 `create_agent` 的 Observation：各子代理各自的最终 `content`。

## 子代理是什么

子代理：由父 Agent **再 new 出来的 Agent**。心跳仍是 11 的一轮次（内部还是 10 的 ReAct），零件也一样（自己的 Session、自己的 Model、同一套 registry）。差别只有两处：

- **目标更窄**：父代理把大任务切成若干切片，每个切片变成一句 `query`，交给一个子代理
- **记忆隔离**：每个子代理一条新 Session。它自己转十几圈，那些 tool 结果只活在它自己的 `messages` 里；父代理的账本不收这些中间过程

11 写过：LLM 不是 Agent；给它工具、让它能调，也还不是。子代理也不是新循环、不是新模型——它就是再跑一次 `Agent.invoke`。新的是**谁启动它、结果回谁、上下文和谁隔离**。

| 理论部件 | 含义 | 这篇里 |
| --- | --- | --- |
| 父代理 | 宏观拆任务、汇总 | 外面那个 `Agent.invoke`；Action 是 `create_agent` |
| 子代理 | 独立完成一个切片 | `create_agent` 里 `Agent()` + `invoke(query)` |
| 隔离的记忆 | 子任务的圈不污染父会话 | 每个子代理自己的 `Session`；`save(f"{name}-")` 分开落盘 |
| 并行 | 切片之间无依赖时可同时跑 | `threading.Thread` + `join` |
| 汇合 | 父代理只拿各段最终答复 | `[{name, result}, ...]`，`result` 是子代理停圈时的 `content` |

和 11 的轮次叠在一起：

```text
父 Session
  ── 父轮次（一次 invoke）──
  user: 做完这个业务功能
  assistant: tool_calls = create_agent
      ┌─ 子 Session A（独立轮次）── 数据层，N 圈 ── 最终 content A
      ├─ 子 Session B（独立轮次）── DTO，M 圈 ── 最终 content B
      └─ ……线程里同时跑，join 后合并
  tool: [{name, result: content A}, {name, result: content B}, ...]
  assistant: 汇总                    ← 父轮次停圈
```

| 名字 | 边界 | 谁看见 |
| --- | --- | --- |
| 父轮次 | 外面那次 `invoke` | 用户 / 调用方 |
| 子轮次 | `create_agent` 里每个 `agent.invoke(query)` | 该子代理自己；父代理只看见最终 `result` |
| 圈 | 任一 Agent 内部的 Thought → Action → Observation | 该 Agent 自己的 Session |

容易混的两处：

| 说法 | 实际指的 | 为什么容易混 |
| --- | --- | --- |
| 「开几个子代理」 | 几个**独立轮次**，几条新 Session | 不是父轮次里多转几圈，也不是 07 的「下一轮对话」 |
| 子代理也在调工具 | 子轮次内部的圈 | 那些 tool 消息进的是子 Session；父 Session 只有一条 `create_agent` 的 Observation |

相对 11：

| 11 | 现在 | 为什么 |
| --- | --- | --- |
| 一个 `Agent` 包办整句 `q` | 父代理可把 `q` 切成多份，每份再 `Agent()` | 大任务不该挤在同一条 `messages` 里 |
| `session.save()` 文件名只有 uuid | `save(prefix)`，子代理用 `f"{name}-"` | 落盘后才分得清是谁的会话 |
| 工具是读文件、跑命令、MCP…… | 多一个 `create_agent` | 启动子代理本身也是 09 的一次 Action |

下面按依赖落地：Session 能带前缀存盘 → 一个函数里并行跑多个 `Agent.invoke` → 挂成工具 → 父代理调度。

## Session：存盘带前缀

11 的 `save` 写成 `sessions/{id}.json`。子代理也是 `Agent()`，也有自己的 Session，也会 `save`。几个 uuid 并排，事后对不上「这是数据层那个」。

`create_agent` 里会调 `agent.session.save(f"{name}-")`。11 的 `save` 不收参数，这一处必须先改。整份仍是 11 的 `session.py`，新增只在 `save`。

`agent/session.py`：

```python
import json
import uuid
from pathlib import Path
from connect_model_demo.agent.tool import registry
from connect_model_demo.agent.prompt import render_prompt

class Session:
  def __init__(self, *, system_prompt="", tools=[]):
    self.id = str(uuid.uuid4())
    self.messages: list[dict] = []
    if not system_prompt:
      system_prompt = render_prompt("system")
    self.add_message({"role": "system", "content": render_prompt("system")})
    self.tools = tools or registry.schemas()

  def add_message(self, message: dict):
    self.messages.append(message)

  def __str__(self) -> str:
    data = {"id": self.id, "messages": self.messages, "tools": self.tools}
    return json.dumps(data, ensure_ascii=False, indent=2)

  def print(self):
    print(self)

  def print_friendly(self):
    lines = []
    n = 1

    for msg in self.messages:
      role = msg.get("role")

      if role == "system":
        lines.append(f"====={n}. 系统消息======")
        lines.append(msg.get("content", ""))
        n += 1

      elif role == "user":
        lines.append(f"====={n}. 用户消息======")
        lines.append(msg.get("content", ""))
        n += 1

      elif role == "assistant":
        tool_calls = msg.get("tool_calls")
        if tool_calls:
          lines.append(f"====={n}. 工具调用======")
          for i, tc in enumerate(tool_calls):
            func = tc.get("function", {})
            name = func.get("name", "未知")
            lines.append(f"工具名{i + 1}: {name}")

            args_str = func.get("arguments", "{}")
            try:
              args = json.loads(args_str)
            except (json.JSONDecodeError, TypeError):
              args = {}

            for k, v in args.items():
              v_str = str(v)
              v_str = v_str[:70] if len(v_str) > 70 else v_str
              lines.append(f"参数{k}: {v_str}")

            if i < len(tool_calls) - 1:
              lines.append("")
          n += 1
        else:
          lines.append(f"====={n}. AI消息======")
          lines.append(msg.get("content") or "")
          n += 1

      elif role == "tool":
        lines.append(f"====={n}. 调用结果======")
        tool_name = msg.get("name", "未知")
        content = msg.get("content") or ""
        lines.append(f"工具名: {tool_name}")
        content_display = content[:50] if len(content) > 50 else content
        lines.append(f"<结果: {content_display}>")
        n += 1

      lines.append("")

    print("\n".join(lines))

  def save(self, prefix=""):
    sessions_dir = Path(__file__).parent / "sessions"
    sessions_dir.mkdir(parents=True, exist_ok=True)

    data = {"id": self.id, "messages": self.messages, "tools": self.tools}

    path = sessions_dir / f"{prefix}{self.id}.json"
    with open(path, "w", encoding="utf-8") as f:
      json.dump(data, f, ensure_ascii=False, indent=2)

  @classmethod
  def load(cls, session_id: str):
    path = Path(__file__).parent / "sessions" / f"{session_id}.json"
    with open(path, encoding="utf-8") as f:
      data = json.load(f)

    session = cls()
    session.id = data["id"]
    session.messages = data["messages"]
    return session
```

相对 11，`save` 新增的：

| 新增 | 为什么 |
| --- | --- |
| 参数 `prefix=""` | 默认不传时文件名仍是 `{id}.json`，和 11 一样；子代理传入 `"数据层-"` 这类前缀 |
| 文件名改成 `f"{prefix}{self.id}.json"` | 磁盘上能按名字找到对应子代理；`id` 仍在，不和 07 的会话标识打架 |

## 封装：跑一个子代理

有了 11 的 `Agent.invoke`，跑一个切片在概念上只需三步：new 一个 Agent、`invoke(query)`、拿出最后一圈的 `content`。

```python
def run_sub_agent(name: str, query: str) -> dict:
  agent = Agent()
  responses = agent.invoke(query)
  final_resp = responses[-1]
  content = final_resp.message.get("content", "")
  agent.session.save(f"{name}-")
  return {"name": name, "result": content}
```

| 抽进去的 | 为什么 |
| --- | --- |
| `Agent()` | 新 Session、新 Model；不复用父代理的 `messages`，隔离才成立 |
| `invoke(query)` | 子任务本身是 11 的一个轮次，不是父循环里多转一圈 |
| `responses[-1]` 的 `content` | 父代理只要停圈时的最终答复；中间那些 tool 圈丢掉 |
| `save(f"{name}-")` | 出了问题可以打开这份会话看子轮次内部，不必翻父会话 |

`Agent()` 不传 `session` / `model`，用的是 11 的默认零件。子代理因此拿到**全量** `registry`——包括马上要注册的 `create_agent` 自己。切片任务一般用不到再拆一层；真拆了就是套娃，上下文隔离还在，线程会再开一层。

`from connect_model_demo.agent.agent import Agent` 必须写在函数体内，不能写在 `create_agent.py` 文件顶上：`Agent` 构造要 import `registry`，`registry` 要 import 各个工具模块。模块加载期如果工具再 import Agent，会绕回去。14 的 `list_mcp_info` 内部才 import `list_mcp_tools`，是同一类破环。

## 封装：并行多个，合并结果

切片之间常常没有依赖（数据层和 DTO 可以同时写）。一个接一个 `run_sub_agent` 能跑，但父代理的这一圈会等很久。再收：按配置起线程，全部 `join` 完再交卷。

`agent/tool/create_agent.py`：

```python
from connect_model_demo.agent.tool.core import tool
import threading
import json

@tool(
  agent_config="每个子代理的配置。每个子代理要配置名称、用户提示词，子代理会根据提示词启动任务，然后根据提示词的要求返回任务执行结果"
)
def create_agent(agent_config: list[dict[str, str]]) -> str:
  """
  创建并启动多个子代理，每个子代理在独立线程中运行，完成任务后合并返回结果
  参数示例：
  [
    {"name": "sub-agent1", "query": "初始的用户提示词"},
    {"name": "sub-agent2", "query": "初始的用户提示词"}
  ]
  返回结果示例：
  [
    {"name": "sub-agent1", "result": "子代理1的完成结果"},
    {"name": "sub-agent2", "result": "子代理2的完成结果"}
  ]
  """

  from connect_model_demo.agent.agent import Agent

  results: list[dict[str, str]] = []
  results_lock = threading.Lock()
  threads: list[threading.Thread] = []

  def run_sub_agent(name: str, query: str) -> None:
    agent = Agent()
    responses = agent.invoke(query)
    final_resp = responses[-1]
    content = final_resp.message.get("content", "")
    agent.session.save(f"{name}-")
    with results_lock:
      results.append({"name": name, "result": content})

  for config in agent_config:
    name = config.get("name", "unnamed")
    query = config.get("query", "")
    thread = threading.Thread(target=run_sub_agent, args=(name, query))
    threads.append(thread)
    thread.start()

  for thread in threads:
    thread.join()

  return json.dumps(results, indent=2, ensure_ascii=False)
```

相对「只跑一个」多出来的：

| 多出来的 | 为什么现在加 |
| --- | --- |
| `agent_config` 是列表 | 父代理一次 Action 可切多片，不必连调好几次 `create_agent` |
| 每项 `name` + `query` | `name` 给人看、给存盘前缀；`query` 才是子轮次的目标 |
| 一配置一线程 | 切片并行；父代理这一圈的耗时约等于最慢的那个子轮次 |
| `Lock` 再 `append` | 多个线程写同一份 `results`，没有锁会丢项 |
| `join` 全部 | 09 的工具必须同步返回 Observation；没结束就不能给父模型下一圈 |
| `json.dumps(...)` | 工具返回值要进 `role: tool` 的 `content`，和 09 一样收成字符串 |

`results` 的顺序是**谁先跑完谁在前**，不是 `agent_config` 的顺序。下面直接试跑就能看见 `sub-agent-2` 排在 `sub-agent-1` 前面。父模型应按 `name` 认人，不要按数组下标。

`@tool` 的 `agent_config=...` 会进 09 的 schema，模型靠这段知道要传列表、每项有 `name` / `query`。函数 docstring 会进 schema 的 `description`——「何时开子代理」主要靠这一句。写太虚，模型该拆不拆。

> **说明：** `run_sub_agent` 没有 try/except。某个子代理抛错，那个线程死掉，`results` 里缺一项，其它线程仍会 `join` 完。父代理看到的是「少了一个 name」，不一定看得出崩在哪。课上先这样；要稳，至少把异常收成该 name 的 `result` 字符串，和 09 把工具异常收成字符串是同一个目的。

## 注册

`agent/tool/__init__.py` 只多两行。`_ToolRegistry` 本身是 09 的。

```python
from connect_model_demo.agent.tool.create_agent import create_agent

registry.register(create_agent)
```

注册之后，`session.tools` 里多一个 `create_agent`。父代理不用改 `Agent` / `Session`：构造时照旧 `registry.schemas()`，循环仍是 11 的 `invoke`。和 14 的 `use_mcp` 同一类接法——多一个 Action，不新写循环。

三层各自收了什么：

| 层 | 调用方从此不用写 | 还露在外面 |
| --- | --- | --- |
| `run_sub_agent` | 自己 new Agent、抠 `responses[-1]`、带前缀存盘 | 一次只跑一个；还是普通函数 |
| 线程 + `join` + `json.dumps` | 并行和汇合 | 还要手传 `agent_config`；模型看不见 |
| `@tool` + `register` | 当普通工具接进父轮次 | 模型只靠 schema 决定拆不拆；子代理仍持有全量工具 |

## 试跑：直接当函数调

先不经过父模型，确认并行和返回形状。这是在测工具本身，不是 11 的一轮次。

```python
from connect_model_demo.agent.tool.create_agent import create_agent

resp = create_agent(agent_config=[
  {"name": "sub-agent-1", "query": "这是一个测试，请说：你好！"},
  {"name": "sub-agent-2", "query": "this is a test, reply: Hello!"},
])
print(resp)
```

```json
[
  {"name": "sub-agent-2", "result": "Hello! 👋"},
  {"name": "sub-agent-1", "result": "你好！👋"}
]
```

对照三件事：

- 两项都回来了，`join` 没有提前交卷
- `name` 对得上；顺序不必和入参一致（这里 2 先结束）
- `result` 是子代理的最终 `content`。模型有时会在「你好」后面再跟一段自我介绍，对父代理没有信息量，上面已收掉

`sessions/` 下应出现 `sub-agent-1-<uuid>.json` 和 `sub-agent-2-<uuid>.json`。打开能看见各自独立的 system / user / assistant，互不引用——隔离成立。

## 试跑：父代理调度

真正用法：调用方只跟父 `Agent` 说话。模型自己决定要不要 `create_agent`、切成几片、每片的 `query` 怎么写。

```python
from connect_model_demo.agent.agent import Agent
from connect_model_demo.agent.printer import ModelPrinterListener

listener = ModelPrinterListener()
agent = Agent(model_listener=listener)

agent.invoke("请开启多个子代理，创建两个页面，分别画小猪佩奇和海绵宝宝。")

agent.session.save()
```

按设计，父轮次内部应是：

```text
思考中...

调用工具：create_agent

内容：
……（根据两个子代理的 result 汇总：两个页面已写好、路径是什么）……
```

Printer 打出来的 Action 是 `create_agent`，不是 `write_file`。画佩奇、画海绵宝宝发生在两条子 Session 里；父 Session 的友好打印里，工具结果应是一份 `[{name, result}, ...]`，看不到子代理那几十圈读文件 / 写文件。

这仍是 11 的一个父轮次、10 的 ReAct。变的是其中一圈 Action 又启动了若干子轮次，不是把 loop 改写成递归函数。

> **说明：** 用户消息里已经点名「开启多个子代理」，等于把触发从「只靠 schema 判断该不该拆」变成「显式指定」。正式任务里更常见的是不点名，由模型对照 `create_agent` 的 description 自己决定。两个页面互相不依赖，适合并行；若切片 B 必须先等 A 的产物，就不该塞进同一次 `agent_config`——父代理应先开 A，拿 Observation，再开 B。
