使用会话功能时，无论以何种方式实现，都应遵循两条法则：**历史上下文不可修改**、**上下文中应保留思维链**。

| 法则 | 不满足的后果 |
| --- | --- |
| **历史上下文不可修改** | 难以命中模型服务商的 prompt cache |
| **上下文中应保留思维链** | 推理上下文丢失，模型回复质量下降 |

## 历史上下文不可修改

已进入会话的历史消息不可改写、删除或重排。后续轮次只追加新消息，历史原样回传。

模型服务商的 prompt cache 按请求前缀匹配。历史一旦被改动，前缀对不上，缓存就难以命中。

**反面案例：** 压缩、改写或删掉中间某轮消息后再发给模型。

**正面案例：** 历史消息保持原样，只在末尾追加本轮新消息。

## 上下文中应保留思维链

把上一轮 assistant 写回历史时，思考内容与正文一并保留。只留可见回复、丢掉思维链，推理上下文就会丢失，后续回复质量下降。

**反面案例：** 下一轮只把 assistant 正文塞回上下文，思考段丢弃。

**正面案例：** 思考内容与正文一起作为历史回传。

## 会话 `session.py`

作用：在本地维护一条会话。模型 HTTP 接口本身不记上一轮；能「接着聊」的前提，是调用方自己把历史消息存下来，下一轮原样带上。`Session` 就是这份本地账本：进程内用列表攒消息，需要时写成 JSON，下次按 `id` 读回。

| 成员 | 作用 |
| --- | --- |
| `id` | 会话标识，`uuid4` 生成，落盘文件名用它 |
| `messages` | 按时间顺序追加的消息列表，元素是 dict |
| `add_message` | 只往末尾追加，不改已有条目 |
| `save` | 写成 `sessions/{id}.json` |
| `load` | 按 `session_id` 读回 `id` 和 `messages` |

`messages` 用 dict 而不是 06 的 `Message` 对象：JSON 直接能存；思维链是 `reasoning` / `reasoning_content` 这类额外字段，`Message` 只有 `role` + `content`，装不下。

```python
import json
import uuid
from pathlib import Path

class Session:
  def __init__(self):
    self.id = str(uuid.uuid4())
    self.messages: list[dict] = []

  def add_message(self, message: dict):
    self.messages.append(message)

  def save(self):
    sessions_dir = Path(__file__).parent / "sessions"
    sessions_dir.mkdir(parents=True, exist_ok=True)

    data = {
      "id": self.id,
      "messages": self.messages,
    }

    path = sessions_dir / f"{self.id}.json"
    with open(path, "w", encoding="utf-8") as f:
      json.dump(data, f, ensure_ascii=False, indent=2)

  @classmethod
  def load(cls, session_id: str):
    path = Path(__file__).parent / "sessions" / f"{session_id}.json"
    with open(path, encoding="utf-8") as f:
      data = json.load(f)

    session = cls()
    session.id = data["id"]
    session.messages = data["messages"]
    return session
```

> **说明：** `add_message` 只 `append`。压缩、改写、删中间某轮都不在这里做，对应文首「历史上下文不可修改」。

## 模型 `model.py`

相对 06 的改动只有调用边界，流式拆 chunk 的逻辑不变。

| 相对 06 | 现在 | 原因 |
| --- | --- | --- |
| 入参 `list[Message]` | `list[dict] \| Session` | 与 `Session.messages` 对齐；dict 才能带上思维链字段 |
| 发给 SDK 前把 `Message` 转成 dict | 入参已经是 dict，不再转换 | `Session` 里存的就是 SDK 要的形状 |
| 调用结束不回写 | 传入 `Session` 时，把本轮 assistant 追加进 `session.messages` | 下一轮才能带上完整历史 |
| 流式只拼正文 | 记下实际出现的 `reasoning_field`，思维链与正文一起回写 | 对应「上下文中应保留思维链」；不同服务商字段名不统一（`reasoning_content` 或 `reasoning`） |

传入普通 `list[dict]` 时行为与 06 相同，不回写。传入 `Session` 时：用 `session.messages` 当本次请求的 `messages`；生成结束后再 `add_message`。非流式直接 `message.to_dict()`；流式没有完整 message 对象，就自己组 `{role, content, 思维链字段}`。

```python
from collections.abc import Iterator
from dataclasses import dataclass, field
from typing import cast

from agent.config import openai_settings
from agent.session import Session
from openai import OpenAI

@dataclass
class Chunk:
  type: str = ""
  content: str = ""

@dataclass
class Model:
  model_name: str = openai_settings.model
  _client: OpenAI = field(
    default_factory=lambda: OpenAI(
      api_key=openai_settings.api_key,
      base_url=openai_settings.base_url,
    )
  )

  def invoke(self, messages: list[dict] | Session):
    session = None
    if isinstance(messages, Session):
      session = messages
      messages = session.messages

    response = self._client.chat.completions.create(
      model=self.model_name,
      messages=cast(list, messages),
    )

    if session:
      session.add_message(response.choices[0].message.to_dict())

    return response

  def invoke_stream(self, messages: list[dict] | Session) -> Iterator[Chunk]:
    session = None
    if isinstance(messages, Session):
      session = messages
      messages = session.messages

    stream = self._client.chat.completions.create(
      model=self.model_name,
      messages=cast(list, messages),
      stream=True,
    )
    is_on_reasoning = False
    full_reasoning_content = ""
    full_content = ""
    reasoning_field = ""
    for chunk in stream:
      if not chunk.choices:
        continue
      delta = chunk.choices[0].delta
      content = delta.content
      reasoning_field_temp = "reasoning_content"
      reasoning_content = getattr(delta, reasoning_field_temp, None)
      if not reasoning_content:
        reasoning_field_temp = "reasoning"
        reasoning_content = getattr(delta, reasoning_field_temp, None)
      if reasoning_content:
        reasoning_field = reasoning_field_temp

      if reasoning_content:
        full_reasoning_content += reasoning_content
        if not is_on_reasoning:
          is_on_reasoning = True
          yield Chunk(type="reasoning_start")
        yield Chunk(type="reasoning", content=reasoning_content)
      if content:
        full_content += content
        if is_on_reasoning:
          is_on_reasoning = False
          yield Chunk(type="reasoning_end", content=full_reasoning_content)
          yield Chunk(type="content_start")
        yield Chunk(type="content", content=content)

    yield Chunk(type="content_end", content=full_content)

    if session:
      msg = {"role": "assistant", "content": full_content}
      if reasoning_field:
        msg[reasoning_field] = full_reasoning_content
      session.add_message(msg)
```

> **说明：** `reasoning_field` 以流里真正出现过的字段名为准，回写时用同一个键，避免有的服务商认 `reasoning`、有的认 `reasoning_content`。

## 两次独立调用

下面两次都是新建 `Model()`，各自只带系统提示词 + 一条新 user 消息，**不传上一轮历史**，也不走 `Session`。

### 第1次调用

问「uv是什么？」。系统提示词仍是 06 那份 Agent 模板，模型按软件工程语境作答。

```python
from agent.model import Model
from agent.printer import print_stream
from agent.prompt import render_prompt

model = Model()

response = model.invoke_stream([
  {"role": "system", "content": render_prompt("system")},
  {"role": "user", "content": "uv是什么？"}
])

print_stream(response)
```

输出示例：

```text
UV stands for Unique Views, which is a metric used to measure the number of unique users who have interacted with a particular piece of content, such as an article, video, or webpage. In other words, UV tracks the
number of distinct individuals who have viewed or engaged with the content.

In a software engineering context, UV might not be a directly applicable metric. However, if we're discussing a web-based application or a content platform, UV could be an important KPI (Key Performance Indicator)
for measuring the effectiveness of content marketing strategies, content recommendation algorithms, or user engagement tracking systems.

Would you like to know more about UV or explore related topics?
====输出完毕====
```

模型把 `uv` 理解成了网页指标 Unique Views。这一轮的问答只存在于这次请求里。

### 第2次调用

再开一次全新请求，只问「如何安装？」，同样不带第1次的 messages。

```python
from agent.model import Model
from agent.printer import print_stream
from agent.prompt import render_prompt

model = Model()

response = model.invoke_stream([
  {"role": "system", "content": render_prompt("system")},
  {"role": "user", "content": "如何安装？"}
])

print_stream(response)
```

输出示例：

```text
To install Claude Code, you can follow these steps:

1. **Ensure you have Python installed**: Claude Code is a Python-based CLI tool, so you'll need to have Python installed on your machine. If you don't have Python installed, you can download it from the official Python website.
2. **Clone the .....省略一大段
====输出完毕====
```

「如何安装？」没有指明装什么。第1次刚聊过 uv，人会默认接着装 uv；模型没看到那轮对话，只看到当前这条 user 和系统提示词里的「You are Claude Code」，于是去装 Claude Code。

## 模型没有跨请求记忆

两次调用是两次独立的 HTTP 请求。Chat Completions 是**无状态**的：服务端不为「你刚才那一轮」保留记忆，也不会把第1次的 `messages` 自动接到第2次上。模型当轮能看见的，只有这次请求体里的 `messages`。

所以上面会出现：

- 第1次问 uv，第2次问「如何安装？」——模型不知道「安装」的对象是 uv
- 缺了指代对象时，它会退回系统提示词里的身份（Claude Code）来补全意图
- 进程里即使还握着同一个 `Model()` 实例也没用，client 不缓存对话；不把历史放进 `messages`，下一轮就是空白

要「接着聊」，必须由调用方在每次请求里带上截至目前的历史（含思维链）。常见做法：

| 做法 | 要点 |
| --- | --- |
| **请求内回传历史** | 每轮把完整 `messages` 提交。模型记住的是你这次带上的列表，不是上一轮连接 |
| **本地会话对象** | 用 `Session` 在进程内 `append`，需要跨进程 / 重启时 `save` / `load` |
| **服务商有状态会话** | 部分 API 提供 thread、conversation_id、`previous_response_id`，由服务端代管历史 |
| **外部记忆** | 用户偏好、长期事实写入数据库或向量库，需要时检索再注入当前 `messages` |
| **摘要续写** | 窗口不够时对旧轮次做摘要，以**新消息追加**，不要改写已有历史 |
