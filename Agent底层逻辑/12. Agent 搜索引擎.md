11 把循环收进 `Agent.invoke`，工具仍是 10 的读文件、写文件、跑命令。问「当前目录有什么」够用；问「苹果刚发布了什么」不够——模型没有眼睛，参数里的网页知识会过期。缺的不是新的循环，是一类新的 Action：上网。

问题的关键不是「怎么发 HTTP」，而是：`web_search` 的 Observation **应该长什么样**。

## 为什么需要面向 Agent 的搜索引擎

把传统搜索引擎的结果页（或目标网页的 HTML）原样塞给模型，会遇到：

- 标签、样式、JS 占掉大量 token
- 注意力被导航、广告、banner 拉开
- 很多 CSR 页面源码里没有正文
- 深层链接无法一次拿全
- 图片、菜单等与问题无关的信息混在 Observation 里

10 写过：Observation 是环境返回的**事实**，下一轮 Thought 站在这份事实上。事实太脏，不是「模型更聪明就能消化」，而是：贵、慢、看偏。Agent 要的不是给人看的结果页，而是一份**干净、短、可引用**的结构化结果：标题、URL、相关性、正文摘要。

面向 Agent 的检索 / 抓取服务按这个目标做，常见的有：

- **Firecrawl**：https://www.firecrawl.dev/
- **Tavily**：https://www.tavily.com/
- **AnySearch**：http://www.anysearch.com/
- **Brave**：https://brave.com/
- **Exa**：https://exa.ai/

这篇用 Tavily：搜索 + 按 URL 提取是一条 SDK，返回的是 JSON 而不是 HTML。Firecrawl 更偏整站爬取；能力可以并列了解，接入方式同一类。

## 和 ReAct 的对应

10 的三截没有变。变的是 Action 能碰的外部世界：从本地文件 / shell，扩到公开网页。

| ReAct         | 上网时在干什么                         | 谁产生                         |
| ------------- | -------------------------------------- | ------------------------------ |
| **Thought**   | 要不要搜、搜什么、snippet 够不够精读   | 模型                           |
| **Action**    | `web_search` / `fetch_url`             | 模型只给 query / urls          |
| **Observation** | 结构化 JSON：标题、摘要、正文、失败信息 | Tavily；再经工具变成字符串回写 |

```text
用户：帮我查一查苹果最新发布了哪些产品？

Thought: 训练数据里的发布会会过期，先搜
Action:  web_search("苹果 最新发布 产品")
Observation: 若干条 title / url / content / score

Thought: 摘要不够，打开其中一条
Action:  fetch_url(["https://..."])
Observation: 该页正文（仍是结构化文本，不是整页 HTML）

Thought: 信息够了，直接回复（不再发出 Action）
```

停圈条件和 10 / 11 相同：模型给出最终答复、**不再发出 Action**。`Agent.invoke` 一行都不用改；新能力来自新工具。09 的纪律仍然成立：工具返回值必须是字符串，失败也写成字符串，好让下一轮 Thought 看见。

Tavily 本身有三种能力，和上面两步不是一一做成三个工具：

| 能力   | API              | 这篇是否做成工具 | 为什么                                           |
| ------ | ---------------- | ---------------- | ------------------------------------------------ |
| 搜索   | `client.search`  | `web_search`     | 不知道哪条 URL，先按关键字发现                   |
| 提取   | `client.extract` | `fetch_url`      | 已有 URL，snippet 不够时精读                     |
| 爬取   | `client.crawl`   | 否               | 一次可能几十页、几十秒，单次 Observation 会撑爆 |

先把三种 API 的返回摸清楚，再按 09 的 `@tool` 包前两个。

## 爬取

`crawl`：从一个入口 URL 往下走，按深度、条数上限、自然语言指令筛页。和搜索的差别是范围：搜索面向全网关键字，爬取面向**一个站点**。

```python
response = client.crawl(
  url="https://www.yuanjin.tech/",
  max_depth=3,
  limit=50,
  instructions="找到所有和网络相关的知识",
)
print(json.dumps(response, indent=2, ensure_ascii=False))
```

## 封装成工具

09 的外壳不变：`@tool` 生成 schema，docstring 当 `description`，返回值必须是字符串。函数体里才出现 Tavily。模型仍然只看见「有一个 `web_search`，参数是 `query`」，看不到 API Key，也不自己发 HTTP。

封装了什么、为什么：

| 收进 `web.py` 的                         | 为什么现在收                                                     |
| ---------------------------------------- | ---------------------------------------------------------------- |
| `TavilyClient(api_key=...)`              | 密钥来自 settings；调用方（模型）只许填 query / urls             |
| `client.search` / `client.extract`       | 真正的对外行动在本地；和 09 的读文件、10 的 shell 是同一层       |
| `json.dumps(..., ensure_ascii=False)`    | 09 要求返回字符串；整份 JSON 进 `role: tool` 的 `content`        |
| 两个函数，而不是一个「既能搜又能抓」     | 发现和精读参数不同；拆开后模型可以先搜再决定抓哪几个 URL         |
| `extract` 时 `include_images=False`      | 图片 URL 模型看不见，百科上还特别脏；默认关掉                    |

不收 crawl：一次 Observation 太大、太慢。不把 Client 做成模块级单例：教学里每次调用 new 一次更直；要复用可以再提，这篇不拆。

`agent/tool/web.py`：

```python
import json

from tavily import TavilyClient

from connect_model_demo.agent.config import tavily_settings
from connect_model_demo.agent.tool.core import tool

@tool(query="搜索关键字")
def web_search(query: str):
  "根据关键字进行网络搜索，返回结构化的搜索结果"
  client = TavilyClient(api_key=tavily_settings.api_key)
  response = client.search(query=query)
  return json.dumps(response, ensure_ascii=False)

@tool(urls="要抓取的url链接数组")
def fetch_url(urls: list[str]):
  "根据提供的url数组，抓取网页正文，返回结构化的提取结果"
  client = TavilyClient(api_key=tavily_settings.api_key)
  response = client.extract(urls=urls, include_images=False)
  return json.dumps(response, ensure_ascii=False)
```

和 09 / 10 的文件工具同一套：装饰器旁边写参数描述，失败若抛出来，由 09 的 `Tool.__call__` 收成堆栈字符串——模型下一轮能改 query 或换 URL。

为什么要把**整份** Tavily JSON `dumps` 回去，而不是只拼 `title + content`：省掉一次我们自己的裁剪逻辑，URL、score 仍在，模型才能决定下一步 `fetch_url` 抓谁。代价是 token；结果条数由 Tavily 默认值卡住，通常可接受。真要裁，应在工具里显式丢掉 `images` / `request_id` 这类字段，不要让模型在脏 HTML 上自己裁。

> **说明：** 原稿 `fetch_url` 的 docstring 写成了「返回结构化的搜索结果」。它走的是 `extract`，不是 `search`，已改成「提取结果」。

## 注册

10 加 `bash_command` 时已经说过：只写文件不 `register`，`registry.schemas()` 里不会出现它。11 的 `Session` 构造时 `self.tools = tools or registry.schemas()`，Agent 不会再手填工具列表。所以这篇对调度中心的改动只有两行：import，然后 `register`。

`agent/tool/__init__.py`：

```python
import json

from connect_model_demo.agent.tool.bash_command import bash_command
from connect_model_demo.agent.tool.core import Tool
from connect_model_demo.agent.tool.read_file import read_file
from connect_model_demo.agent.tool.web import fetch_url, web_search
from connect_model_demo.agent.tool.write_file import write_file

class _ToolRegistry:
  _tools: dict[str, Tool] = {}

  def register(self, tool: Tool):
    """注册一个工具"""
    self._tools[tool.name] = tool

  def schemas(self) -> list[dict]:
    """返回所有工具的 Schema 列表，可直接赋值给 session.tools"""
    return [t.schema() for t in self._tools.values()]

  def invoke(self, message: dict) -> list[dict] | None:
    """从模型返回的消息中提取 tool_calls 并逐一执行"""
    tool_calls = message.get("tool_calls", [])
    if not tool_calls:
      return None
    results = []
    for tc in message.get("tool_calls", []):
      tool_id = tc["id"]
      name = tc["function"]["name"]
      args = json.loads(tc["function"]["arguments"])
      tool = self._tools.get(name)
      if not tool:
        result = "无此工具，请仔细检查你传递的工具名称是否正确"
      else:
        result = tool(**args)
      results.append(
        {
          "role": "tool",
          "tool_call_id": tool_id,
          "name": name,
          "content": result,
        }
      )
    return results

registry = _ToolRegistry()
registry.register(read_file)
registry.register(write_file)
registry.register(bash_command)
registry.register(web_search)
registry.register(fetch_url)
```

相对 10：类本身没有新职责。`invoke` 仍然是 09 那半圈 Observation——拆 `tool_calls`、执行、收成 `role: tool`。新工具一旦 `register`，同一轮里可以和 `bash_command` 并行出现（09 已按列表逐条执行，不是只跑 `tool_calls[0]`）。

> **说明：** 原稿写成 `tool = self._tools[name]`。名字不在注册表里时会 `KeyError`，09 特意改成 `.get(name)`，把「无此工具」写成字符串回传。这里已改回 09 的写法；循环变量也改回 `tool_id`，避免盖掉内置名 `id`。
