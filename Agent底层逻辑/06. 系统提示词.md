系统提示词往往出现在所有消息的最前面，大模型在训练过程中会重点关注它。编写的核心原则是五条：**精简、自洽、全局约束、保持静态、结构化**。

| 原则 | 要点 |
| --- | --- |
| **精简** | 能不说就不说，能少说就少说，绝对避免无病呻吟 |
| **自洽** | 提示词不能自我矛盾 |
| **全局约束** | 其中所有规则作用于整条对话的每一轮交互 |
| **保持静态** | 内容应当尽量固定不变 |
| **结构化** | 用 Markdown / XML（或二者混用）分层排版，隔离关键规则 |

## 精简

能不说就不说，能少说就少说，绝对避免无病呻吟。

**反面案例：**

```text
你现在要充当一名专业代码顾问，接下来我会向你提出各种各样和编程相关的问题。希望你认真仔细地阅读我每一次发送过来的内容，充分理解我的诉求之后，再进行回答。回答的时候尽量清晰易懂，方便我进行理解。如果遇到不清楚的内容，千万不要随意编造答案。
```

**正面案例：**

```text
你是代码顾问。精准解答编程问题，不懂直接说明，禁止编造信息。
```

## 自洽

提示词不能自我矛盾。

**反面案例：**

```text
你是数据分析助手。回答务必详尽，多角度展开说明；同时所有回复控制在 30 字以内。
```

**正面案例：**

```text
你是数据分析助手。回答简洁，整体控制在 30 字以内。
```

## 全局约束

系统提示词内所有规则作用于整条对话的每一轮交互。因此只放全程都该遵守的约束；场景限定、单次任务的指令不要写进去。

**反面案例：**

```text
当用户要求你写数据分析类代码的时候，你应该使用Python来编写。
```

**正面案例：** 空。此类任务级规则不应写入系统提示词。

## 保持静态

系统提示词内容应当**尽量**固定不变。用户身份、当前时间等会变的信息不写进去。

**反面案例：**

```text
当前用户是：<动态内容>，时间是：<动态内容>
```

**正面案例：** 空。动态内容不应写入系统提示词。

## 结构化

系统提示词采用 Markdown / XML（或二者混用）进行分层排版；核心指令、硬性约束、输出规范使用标记进行隔离，便于模型区分层级、识别关键规则，避免文本扁平化造成理解偏差。

**反面案例：**

```text
你是技术助手。回答必须精简，不能编造信息。输出答案尽量条理清晰。如果信息不足直接说明。禁止额外多余话术。
```

**正面案例：**

```markdown
# 角色
技术助手
## 硬性规则
1. 回答精简，严禁编造信息
2. 信息不足直接说明，不强行作答
## 输出要求
条理清晰，无多余开场白与结束语
```

## 二次封装

上一节直接用 OpenAI SDK：每次都要新建 client、手写 `{"role": ...}` 字典、自己拆 chunk。这一节要反复改系统提示词、对比效果；如果 SDK 细节仍摊在 `main.py` 里，提示词本身会被淹没。

所以把 05 的调用链拆成四个模块，`main` 只负责「组消息 → 调模型 → 打印」。后面用 Jinja2 渲染系统提示词时，也只往这套管线里塞字符串，不再碰 SDK。

```text
main.py
 ├── prompt.py      渲染 system.j2 → 系统提示词字符串
 ├── message.py     SystemMessage / UserMessage / AssistantMessage
 ├── model.py       invoke / invoke_stream
 │    └── config.py 读 .env（OPENAI_*）
 └── printer.py     打印思考 / 正文
```

| 文件 | 对应 05 | 作用 |
| --- | --- | --- |
| `config.py` | `.env` + `config.py` | 读环境变量，提供 api_key / base_url / model |
| `message.py` | 手写 `{"role", "content"}` | 用类型表示一条消息，调用时不用再填 role |
| `model.py` | `OpenAI()` + `stream_resp.py` | 持有 client，非流式 / 流式调用，流式时顺便拆 chunk |
| `printer.py` | `stream_print.py` | 按事件类型上色打印 |

### 配置 `config.py`

作用：从仓库根目录的 `.env` 读出 `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL`，给 `Model` 用。05 用 `os.environ.get`；这里改成 `pydantic-settings`，字段名 `api_key` 自动对上前缀 `OPENAI_`。

`env_file` 的 `..` 层数取决于 `config.py` 放在哪一层，换目录时要跟着改。`extra: "ignore"` 表示 `.env` 里其他变量直接忽略，避免校验报错。

```python
import os

_env_file = os.path.abspath(os.path.join(_current_dir, "..", "..", "..", ".env"))

  model_config = {"env_file": _env_file, "extra": "ignore"}

  api_key: str = ""
  base_url: str = ""
  model: str = ""

  model_config = {"env_prefix": "OPENAI_"}

openai_settings = OpenAISettings()
```

### 消息 `message.py`

作用：把一条对话消息收成对象。基类约定 `content` + `role`；三个子类把 `role` 写死，所以 `SystemMessage("...")` 不用再填角色。

dataclass 规定：没有默认值的字段必须写在有默认值的前面。基类里 `content`、`role` 都必填；子类给 `role` 默认值，因此 `SystemMessage("你好")` 只传正文即可。

```python
from abc import ABC
from dataclasses import dataclass
from typing import Literal

Role = Literal["system", "user", "assistant"]

@dataclass
class Message(ABC):
  content: str
  role: Role

@dataclass
class SystemMessage(Message):
  role: Role = "system"

@dataclass
class UserMessage(Message):
  role: Role = "user"

@dataclass
class AssistantMessage(Message):
  role: Role = "assistant"
```

### 模型 `model.py`

作用：包住 OpenAI client。`invoke` 一次拿完整回复；`invoke_stream` 边生成边吐自己的 `Chunk` 事件（把 05 的 `chunk_generator` 收进来），调用方不再抠 `delta`。

`invoke_stream` 还会把思考 / 正文拼成完整字符串，挂在 `reasoning_end`、`content_end` 的 `content` 上，后面若要记日志可以直接用。

事件类型与 05 相同：

| type | 含义 |
| --- | --- |
| `reasoning_start` | 思考段开始 |
| `reasoning` | 思考内容（一小段 token） |
| `reasoning_end` | 思考段结束（`content` 为完整思维链） |
| `content_start` | 正文开始 |
| `content` | 正文内容（一小段 token） |
| `content_end` | 整段输出结束（`content` 为完整正文） |

```python
from collections.abc import Iterator
from dataclasses import dataclass, field
from typing import cast

from agent.config import openai_settings
from agent.message import Message
from openai import OpenAI

@dataclass
class Chunk:
  type: str = ""
  content: str = ""

@dataclass
class Model:
  model_name: str = openai_settings.model
  _client: OpenAI = field(
    default_factory=lambda: OpenAI(
      api_key=openai_settings.api_key,
      base_url=openai_settings.base_url,
    )
  )

  def invoke(self, messages: list[Message]):
    response = self._client.chat.completions.create(
      model=self.model_name,
      messages=cast(
        list, [{"role": m.role, "content": m.content} for m in messages]
      ),
    )
    return response

  def invoke_stream(self, messages: list[Message]) -> Iterator[Chunk]:
    stream = self._client.chat.completions.create(
      model=self.model_name,
      messages=cast(
        list, [{"role": m.role, "content": m.content} for m in messages]
      ),
      stream=True,
    )
    is_on_reasoning = False
    full_reasoning_content = ""
    full_content = ""
    for chunk in stream:
      if not chunk.choices:
        continue
      delta = chunk.choices[0].delta
      content = delta.content
      reasoning_content = getattr(delta, "reasoning_content", None)
      if not reasoning_content:
        reasoning_content = getattr(delta, "reasoning", None)

      if reasoning_content:
        full_reasoning_content += reasoning_content
        if not is_on_reasoning:
          is_on_reasoning = True
          yield Chunk(type="reasoning_start")
        yield Chunk(type="reasoning", content=reasoning_content)
      if content:
        full_content += content
        if is_on_reasoning:
          is_on_reasoning = False
          yield Chunk(type="reasoning_end", content=full_reasoning_content)
          yield Chunk(type="content_start")
        yield Chunk(type="content", content=content)

    yield Chunk(type="content_end", content=full_content)
```

发给 SDK 之前，把 `Message` 列表还原成它要的字典。`cast(list, ...)` 只是让类型检查放过，运行时就是普通 `list[dict]`。

### 打印 `printer.py`

作用：把模型输出打到终端。`print_response` 吃非流式的完整 `response`；`print_stream` 吃 `invoke_stream` 的事件。颜色和是否显示思考由 `PrinterConfig` 控制，默认思考青色（`36`）、正文红色（`31`）。

```python
from dataclasses import dataclass
import sys

@dataclass
class PrinterConfig:
  show_reasoning: bool = True
  reasoning_color: str = "36"
  content_color: str = "31"

def print_response(response, config: PrinterConfig | None = None):
  if config is None:
    config = PrinterConfig()
  message = response.choices[0].message
  reasoning_content = getattr(message, "reasoning_content", None)
  if not reasoning_content:
    reasoning_content = getattr(message, "reasoning", None)
  if reasoning_content and config.show_reasoning:
    print(f"\033[{config.reasoning_color}m{reasoning_content}\033[0m")
    print()
  content = message.content
  if content:
    print(f"\033[{config.content_color}m{content}\033[0m")

def print_stream(chunk_iterator, config: PrinterConfig | None = None):
  if config is None:
    config = PrinterConfig()
  for chunk in chunk_iterator:
    if chunk.type == "reasoning_start":
      if config.show_reasoning:
        print("思考：")
    elif chunk.type == "reasoning_end":
      if config.show_reasoning:
        print()
    elif chunk.type == "content_start":
      print()
      print("内容：")
    elif chunk.type == "content_end":
      print()
      print("====输出完毕====")
    elif chunk.type == "reasoning":
      if config.show_reasoning:
        print(f"\033[{config.reasoning_color}m{chunk.content}\033[0m", end="")
    elif chunk.type == "content":
      print(f"\033[{config.content_color}m{chunk.content}\033[0m", end="")
    sys.stdout.flush()
```

## 渲染系统提示词

真实 Agent 的系统提示词很长，而且有少量运行时信息（界面语言、工作目录、是否 git）。骨架写成 Jinja2 模板保持不动，变的值在渲染时注入——模板文件静态，注入值动态，对应前面「保持静态」。

| 变量 | 来源 | 模板里怎么用 |

### 采集与渲染 `prompt.py`

作用：采集三个运行时值，加载 `prompt/{name}.j2`，填充后返回完整字符串。

| 函数 | 作用 |
| --- | --- |
| `get_cwd()` | 当前工作目录 |
| `get_is_git()` | 当前目录是否在 git 仓库内（`returncode == 0` 且 stdout 为 `true`） |
| `get_language()` | 系统界面语言：macOS 读 `AppleLocale`，Windows 用 `GetLocaleInfoW`（如 `zh-CN`），其他平台返回空串 |
| `render_prompt(name)` | 渲染 `prompt/{name}.j2`，注入上面三个值 |

```python
import os
import platform
import subprocess

from jinja2 import Environment, FileSystemLoader

def get_cwd() -> str:
  return os.getcwd()

def get_is_git() -> bool:
  result = subprocess.run(
    ["git", "rev-parse", "--is-inside-work-tree"],
    capture_output=True,
    text=True,
    timeout=5,
  )
  return result.returncode == 0 and result.stdout.strip() == "true"

def get_language() -> str:
  system = platform.system()
  if system == "Darwin":
    result = subprocess.run(
      ["defaults", "read", "-g", "AppleLocale"],
      capture_output=True,
      text=True,
      timeout=5,
    )
    return result.stdout.strip()
  elif system == "Windows":
    import ctypes

    lcid = ctypes.windll.kernel32.GetUserDefaultLCID()
    buf = ctypes.create_unicode_buffer(256)
    ctypes.windll.kernel32.GetLocaleInfoW(lcid, 0x5C, buf, 256)
    return buf.value
  return ""

def render_prompt(prompt_name: str) -> str:
  template_dir = os.path.join(os.path.dirname(__file__), "prompt")
  env = Environment(loader=FileSystemLoader(template_dir))
  template = env.get_template(f"{prompt_name}.j2")
  return template.render(
    language=get_language(),
    cwd=get_cwd(),
    is_git=get_is_git(),
  )
```

### 渲染结果

`print(render_prompt("system"))` 会打出整份提示词。静态段落与模板一字不差，不必再贴一遍；只看被填充的文末即可。

```python
from agent.prompt import render_prompt

print(render_prompt("system"))
```

占位符 → 填充后（值随机器变化，下面是一份 Windows 示例）：

| 占位符 | 填充后 |
| --- | --- |
| `{{ language }}` | `zh-CN`（空则整段 `# Language` 消失） |
| `{{ cwd }}` | `F:\python\connect-model-demo` |
| `{{ is_git }}` | `True` |

```text
# Language

Always respond in zh-CN. Use zh-CN for all explanations, comments, and communications with the user. Technical terms and code identifiers should remain in their original form.

# Environment

You have been invoked in the following environment:
 - Primary working directory:
   F:\python\connect-model-demo
 - Is a git repository: True
```

> **说明：** 每次调用 `render_prompt` 都按**当前**环境重新采集。模板文件本身不变，变的是注入值。
