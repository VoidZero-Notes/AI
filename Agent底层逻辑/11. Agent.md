10 把「想 → 干 → 看结果 → 再想」收进 `while True`，循环仍摊在 `main.py` 的 `query` 里：调用方自己 new `Session`、new `Model`、绑 Listener，再把三件套传进函数。能跑，还不是一个运行单元。

11 要收的就是这个运行单元。名字就叫 Agent。

## Agent 是什么

AI Agent（智能体）：通过自主规划、调用工具、持续观察反馈并迭代行动，独立推进复杂任务直至目标达成的人工智能运行单元。

大模型一次请求只做「输入 → 输出」。没有眼睛、没有手、也不记上一轮——这些都要调用方补。前面几篇分别补过：

| 能力             | 哪篇有            | 还缺什么                         |
| ---------------- | ----------------- | -------------------------------- |
| 会话记忆         | 07 `Session`      | 只是账本，不会自己推进任务       |
| 对外行动         | 08 / 09 Tool      | 一轮就停，或只走半圈             |
| 交错推理与行动   | 10 ReAct 循环     | 循环和零件散落在 `main.py`       |
| 收成运行单元     | 11 `Agent`        | 调用方只丢任务进来               |

LLM 不是 Agent。给它工具、让它能调，也还不是：08 那种一次 `tool_calls` 没有下一轮。10 的 ReAct 已经是 Agent 的心跳——Thought / Action / Observation 循环直到不再发出 Action。缺的是把心跳和零件（记忆、模型、工具、展示）收进同一个对象，对外只暴露「给定目标，去完成」。

常见拆法，和这篇代码一一对应：

| 理论部件        | 含义                         | 这篇里                                      |
| --------------- | ---------------------------- | ------------------------------------------- |
| 目标            | 用户交付的任务               | `invoke(q)` 的 `q`                          |
| 记忆            | 跨轮保留的上下文             | `Session`                                   |
| 规划 / 推理     | 根据已知决定下一步           | `Model`（Thought）                          |
| 行动            | 对外部世界动手               | `registry` + 工具                           |
| 观察            | 行动的真实返回               | `role: tool` 追回会话                       |
| 感知 / 展示     | 过程怎么被看见               | `ModelListener` / `ModelPrinterListener`    |

![image-20260826234913820](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-08-26-154914.png)

停的条件和 10 相同：模型给出最终答复、**不再发出 Action**。不是外面规定转几圈。Agent 类并不发明新循环，只是让循环不再需要调用方每次手拼。

相对 10：

| 10                                      | 11                                              | 为什么                                           |
| --------------------------------------- | ----------------------------------------------- | ------------------------------------------------ |
| `query(q, session, model)`              | `agent.invoke(q)`                               | 调用方不应每次拼装三件套                         |
| `ModelPrinterListener(model)` 构造时绑死 | Listener 后绑，Agent 构造时 `listen(model)`     | 先有 Agent 再有 model；监听器可换                |
| 订阅逻辑写在 Printer 构造函数里         | 抽成 `ModelListener`                            | 以后加日志、UI 监听器，不必复制扫 Event 的循环   |
| `session.print()` 整份 JSON             | 增加 `print_friendly()`                         | 同一轮次里圈数一多，JSON 不可读，要对人看节奏    |

## 轮次

对外看 Agent，边界不是「调了一次模型」，而是一句用户请求从进到出：

```text
query → agent(loop) → 结果
```

这叫一个**轮次**。代码上就是一次 `invoke(q)`（10 里是一次 `query(...)`）。调用方丢进 `q`，等到最终答复才返回；中间模型被调了几次、工具跑了几次，都不算新的轮次。

里面的 `while True` 是这一轮次**内部**的 ReAct 循环。可能只转 1 圈（直接回答、不调工具），也可能转十几圈（读文件、改路径、再写文件）。圈子数由模型决定：不再发出 Action 就停。调用方不该每圈停下来等人——那是 09 用 `# %%` cell 对人演示半圈的做法，不是 Agent。

```text
query
  └─ Agent.invoke（1 个轮次）
        写入 user
        loop
          圈1  Thought → Action → Observation
          圈2  Thought → Action → Observation
          ...
          停圈 Thought → 最终答复（无 Action）
        返回结果
结果
```

| 名字   | 边界                                       | 代码                         | 谁看见           |
| ------ | ------------------------------------------ | ---------------------------- | ---------------- |
| **轮次** | 用户问一句，等到最终答复                   | 一次 `invoke(q)`             | 用户 / 调用方    |
| **圈**   | Thought → Action → Observation，再决定是否继续 | `while True` 的一次迭代      | Agent 内部       |

容易混的三处：

| 说法                         | 实际指的     | 为什么容易混                                       |
| ---------------------------- | ------------ | -------------------------------------------------- |
| 08 的「一轮就停」            | 一次模型调用 | 当时没有 loop，一次 `tool_calls` 任务常常没做完    |
| 10 说循环会跑「十几轮」      | 圈           | 同一句用户请求里，模型被调了十几次                 |
| 07 的「下一轮对话」          | 轮次         | 用户再发一句，同一条 Session 上再 `invoke` 一次    |

同一条 Session 可以跑多个轮次。第一次 `invoke` 分析目录并写出文件；用户再问「把第二节扩写」，是第二个轮次。第二个轮次开始时，第一条用户消息、所有 tool 结果、最终答复都还在 `messages` 里——07 的历史不可改。新轮次只是再追加一条 user，再进一次 loop。

```text
Session
  system
  ── 轮次 1 ──
  user: 分析 ./agent，写到 分析2.md
  （N 圈 assistant / tool）
  assistant: 写完了          ← 轮次 1 的结果
  ── 轮次 2 ──
  user: 把第二节扩写
  （又 M 圈 assistant / tool）
  assistant: 扩写完了        ← 轮次 2 的结果
```

停圈不等于会话结束。圈停了，这一轮次才出结果；用户不再发问，会话才停。计费、限流、最大步数保护的都是**一轮次里的圈数**，不是会话里有几个轮次。

下面按依赖顺序落地：身份（提示词）→ 监听器基类 → 打印 → 会话可读化 → Agent 类。

## 监听器基类

08 / 10 的 `ModelPrinterListener` 构造函数里做了两件事：扫一遍 `Event`、对每个事件 `model.on(...)`，以及「听到之后 print」。订阅方式和展示策略缠在一起。

Agent 要自己持有 `Model`。监听器不该在构造时就必须拿到一个已经存在的 model；换一种展示（只打日志、推到前端）还得把那段 for 循环再写一遍。

抽基类 `ModelListener`：只封装「订哪些事件、闸门、转发到 `_handler`」。子类只实现听到之后干什么。

封装了什么、为什么：

| 抽出去的                         | 为什么现在抽                                                     |
| -------------------------------- | ---------------------------------------------------------------- |
| 扫 `Event` 并 `model.on(...)`    | 所有监听器都要订同一组事件，不应每个子类复制                     |
| `listening` 闸门                 | 08 已有「暂时不监听」；基类统一拦截，子类不必再写                |
| 构造时不收 `Model`               | Agent 先 new 零件再接线；监听器可先创建、后 `listen(model)`      |
| `_handler` 做成抽象方法          | 强制子类声明展示策略，基类不 print                               |

`agent/listener.py`：

```python
from abc import ABC, abstractmethod
from connect_model_demo.agent.model import Model
from connect_model_demo.agent.events import Event

class ModelListener(ABC):
  def __init__(self) -> None:
    self.listening = True

  def listen(self, model):
    events = [v for k, v in Event.__dict__.items() if not k.startswith("__")]
    for e in events:
      model.on(event=e, callback=self._model_print_callback)

  def _model_print_callback(self, e: str, **args):
    if not self.listening:
      return
    self._handler(e, **args)

  @abstractmethod
  def _handler(self, e: str, **args):
    pass
```

| 成员                     | 作用                                                         |
| ------------------------ | ------------------------------------------------------------ |
| `listen(model)`          | 把 `Event` 里所有事件订到这个 model 上                       |
| `listening`              | 闸门；`False` 时回调直接 return                              |
| `_model_print_callback`  | 统一入口：先看闸门，再交给 `_handler`                        |
| `_handler`               | 抽象方法，子类决定怎么展示                                   |

`listen` 扫的是 `Event` 类上的公开常量，和 08 / 10 Printer 构造函数里那几行相同，只是换了地方。`Model` 的 `on` 来自 08 的 `EventEmitter`：模型只负责 `emit`，谁听、听到干什么，模型不知道。

> **说明：** 方法名仍叫 `_model_print_callback`，是从 Printer 里提上来的。基类已经不 print，只是转发。

## 打印

10 已把展示收成「思考中... / 内容 / 调用工具：名字」。11 只改接线：Printer 变成 `ModelListener` 的子类，构造时不再收 `Model`，订阅交给基类的 `listen`。

相对 10：

| 10                                         | 现在                                      | 为什么                         |
| ------------------------------------------ | ----------------------------------------- | ------------------------------ |
| 构造函数收 `model`，内部自己 `on`          | 无 `Model`；只实现 `_handler`             | 订阅已在基类；Agent 负责接线   |
| 不处理 `CONTENT_END`                       | `CONTENT_END` 时补一个空行                | 正文结束和下一圈「思考中」分开 |
| 思考分片整段注释掉                         | 同样不打 reasoning 分片                   | 循环要看的是决策节奏           |

`agent/printer.py`：

```python
import sys
from connect_model_demo.agent.events import Event
from connect_model_demo.agent.listener import ModelListener

class ModelPrinterListener(ModelListener):
  def _handler(self, e: str, **args):
    if e == Event.REASONING_START:
      print("思考中...")
    elif e == Event.REASONING_END:
      print()
    elif e == Event.CONTENT_START:
      print()
      print("内容：")
    elif e == Event.CONTENT_END:
      print()
    elif e == Event.TOOL_CALL_END:
      tool_calls = args["value"]["tool_calls"]
      for call in tool_calls:
        print(f"\033[36m调用工具：{call["function"]["name"]}\033[0m")
    elif e == "content":
      print(f"\033[32m{args["chunk_value"]}\033[0m", end="")
    sys.stdout.flush()
```

调用方变成两步：先 `ModelPrinterListener()`，再由 Agent 在构造里 `listener.listen(self.model)`。Printer 不再知道 model 从哪来，只对事件做终端展示。

要对照思维链时，在 `_handler` 里加回 `Event.REASONING` 分支即可，和 10 把那行注释打开是同一件事。

## 会话友好打印

10 的 `print()` 把 `id` / `messages` / `tools` 打成 JSON。一圈能看；同一轮次里转十几圈之后，人眼要对的是「调了谁、结果大概是什么、最后怎么答」，不是整份 `messages`。

`print_friendly` 不改 `messages`，只是另一种视图——满足 07「历史不可改」。按 `role` 分段编号：system / user / assistant（有 `tool_calls` 则标成工具调用）/ tool。参数截到 70 字符、工具结果截到 50 字符，避免 `write_file` 的 `content` 把终端刷爆。

构造、`save` / `load` 与 10 相同：新建时自动注入 system 和 `registry.schemas()`；落盘仍只写 `id` + `messages`。下面整份贴出，方便对照多出来的方法：

`agent/session.py`：

```python
import json
import uuid
from pathlib import Path
from connect_model_demo.agent.tool import registry
from connect_model_demo.agent.prompt import render_prompt

class Session:
  def __init__(self, *, system_prompt="", tools=[]):
    self.id = str(uuid.uuid4())
    self.messages: list[dict] = []
    if not system_prompt:
      system_prompt = render_prompt("system")
    self.add_message({"role": "system", "content": system_prompt})
    self.tools = tools or registry.schemas()

  def add_message(self, message: dict):
    self.messages.append(message)

  def __str__(self) -> str:
    data = {"id": self.id, "messages": self.messages, "tools": self.tools}
    return json.dumps(data, ensure_ascii=False, indent=2)

  def print(self):
    print(self)

  def print_friendly(self):
    lines = []
    n = 1

    for msg in self.messages:
      role = msg.get("role")

      if role == "system":
        lines.append(f"====={n}. 系统消息======")
        lines.append(msg.get("content", ""))
        n += 1

      elif role == "user":
        lines.append(f"====={n}. 用户消息======")
        lines.append(msg.get("content", ""))
        n += 1

      elif role == "assistant":
        tool_calls = msg.get("tool_calls")
        if tool_calls:
          lines.append(f"====={n}. 工具调用======")
          for i, tc in enumerate(tool_calls):
            func = tc.get("function", {})
            name = func.get("name", "未知")
            lines.append(f"工具名{i + 1}: {name}")

            args_str = func.get("arguments", "{}")
            try:
              args = json.loads(args_str)
            except (json.JSONDecodeError, TypeError):
              args = {}

            for k, v in args.items():
              v_str = str(v)
              v_str = v_str[:70] if len(v_str) > 70 else v_str
              lines.append(f"参数{k}: {v_str}")

            if i < len(tool_calls) - 1:
              lines.append("")
          n += 1
        else:
          lines.append(f"====={n}. AI消息======")
          lines.append(msg.get("content") or "")
          n += 1

      elif role == "tool":
        lines.append(f"====={n}. 调用结果======")
        tool_name = msg.get("name", "未知")
        content = msg.get("content") or ""
        lines.append(f"工具名: {tool_name}")
        content_display = content[:50] if len(content) > 50 else content
        lines.append(f"<结果: {content_display}>")
        n += 1

      lines.append("")

    print("\n".join(lines))

  def save(self):
    sessions_dir = Path(__file__).parent / "sessions"
    sessions_dir.mkdir(parents=True, exist_ok=True)

    data = {
      "id": self.id,
      "messages": self.messages,
    }

    path = sessions_dir / f"{self.id}.json"
    with open(path, "w", encoding="utf-8") as f:
      json.dump(data, f, ensure_ascii=False, indent=2)

  @classmethod
  def load(cls, session_id: str):
    path = Path(__file__).parent / "sessions" / f"{session_id}.json"
    with open(path, encoding="utf-8") as f:
      data = json.load(f)

    session = cls()
    session.id = data["id"]
    session.messages = data["messages"]
    return session
```

assistant 一条消息只会落在「工具调用」或「AI消息」之一：有 `tool_calls` 就是这一圈的 Action，没有就是这一轮次的最终答复（停圈条件）。同一圈里模型先说一句再调工具，这条里 `content` 和 `tool_calls` 会同时存在——`print_friendly` 此时只展示工具名，正文要看流式打印，或回头用 `print()` 看 JSON。

> **说明：** 原稿 `add_message` 写的是 `render_prompt("system")`，构造里算出来的 `system_prompt` 被丢掉，传入自定义提示词不会生效。上面已改成与 10 一致：写入 `system_prompt`。

## Agent 类

零件齐了。Agent 持有 `session`、`model`、可选的 `listener`；`invoke` 就是 10 的 `query`，也就是一个轮次：进来一句 `q`，内部跑完 loop，出去一个结果。循环一行没改语义。

封装了什么、为什么：

| 原先在 `main.py` 里的                | 收进 Agent 之后                         | 为什么                                           |
| ------------------------------------ | --------------------------------------- | ------------------------------------------------ |
| `Session()` / `Model()`              | 构造时默认创建，也可传入已有实例        | 默认能跑；要接自定义会话或模型时仍能覆盖         |
| `ModelPrinterListener(model)`        | 可选 `model_listener`，构造里 `listen`  | 展示不是 Agent 的必需品；不传就不订阅            |
| `query` 的 `while True`              | `invoke(q)`                             | 一轮次对外只暴露「丢一个任务」                   |
| 每一圈的返回值丢掉                   | `responses` 攒起来返回                  | 攒的是这一轮次里每一圈的模型返回，不是多个轮次   |

`agent/agent.py`：

```python
from connect_model_demo.agent.model import Model
from connect_model_demo.agent.printer import ModelPrinterListener
from connect_model_demo.agent.session import Session
from connect_model_demo.agent.tool import registry
from connect_model_demo.agent.listener import ModelListener

class Agent:
  def __init__(
    self,
    *,
    session: Session | None = None,
    model: Model | None = None,
    model_listener: ModelListener | None = None,
  ) -> None:
    self.session = session or Session()
    self.model = model or Model()
    self.listener = model_listener
    if self.listener:
      self.listener.listen(self.model)

  def invoke(self, q: str):
    self.session.add_message({"role": "user", "content": q})
    responses = []
    # ReAct Loop
    while True:
      resp = self.model.invoke_stream(self.session)
      call_msg = registry.invoke(self.session.messages[-1])
      if call_msg is None:
        responses.append(resp)
        break
      else:
        self.session.messages += call_msg
        responses.append(resp)
    return responses
```

循环每一行仍对应 10 的三截：

| 行                                      | ReAct           | 谁做                         |
| --------------------------------------- | --------------- | ---------------------------- |
| `add_message(user)`                     | 目标            | 一轮次只在进 loop 前做一次   |
| `invoke_stream(session)`                | Thought / Action | 模型；assistant 已回写会话  |
| `registry.invoke(session.messages[-1])` | Observation     | 本地执行；`None` 表示没有工具 |
| `None` → `break`                        | 停圈            | 这一轮次的最终回复已写出     |
| `session.messages += call_msg`          | 观察进记忆      | 下一圈请求能看见工具结果     |

`invoke_stream` 仍走 08 的回写：这一圈的 assistant（含 `tool_calls`）已经在 `session.messages` 末尾。`registry.invoke` 读的就是这条。追回的是 `role: tool` 列表，不是覆盖 assistant。

没有圈数上限，和 10 相同：工具一直被调用，这一轮次就会一直转。演示可以，接到开放输入时要加最大步数——限制的是一轮次里的圈数。

`printer` 的 import 在 `agent.py` 里没用到，真正用的类型是 `ModelListener`；运行时传入的是 `ModelPrinterListener` 实例。留着那行不影响行为，删掉更干净。

流式输出示例（中间大量重复的「思考中... / 调用工具：read_file」已省略，只保留节奏和收尾）：

```text

调用工具：read_file
思考中...

内容：
让我先查看当前目录结构，找到 `agent` 目录的位置。
调用工具：read_file
调用工具：read_file
```
