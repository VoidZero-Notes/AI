08 / 09 的工具是本进程里的 Python 函数：读文件、写文件、跑命令，12 又加了上网。每接一种外部能力，就要自己写一套适配。13 收的是提示词，工具这边没变。

14 要收的是另一件事：Agent 和**外部工具**之间的通信标准。对方只要是 MCP Server，客户端用同一套发现 / 调用，不必为每个服务写一套 SDK。名字叫 MCP。

[https://modelcontextprotocol.io/](https://modelcontextprotocol.io/)

## MCP 是什么

MCP（Model Context Protocol，模型上下文协议）：一套开放协议，规定 AI 应用如何向外部程序发现能力、调用工具、读取资源。它只管**怎么交换上下文**，不管模型怎么推理、会话怎么存——那些仍是 07 / 10 / 11 的事。

09 的 `registry` 解决的是「本仓库里的函数，怎么变成模型能调的 schema」。MCP 解决的是「函数根本不在这个进程里」：可能是本机另一个进程（`uvx mcp-server-time`），也可能是网上一台 HTTP 服务（Microsoft Learn）。schema 的权威在 Server；Client 只负责问和调。

|               | 09 本地 Tool                         | 14 MCP                                    |
| ------------- | ------------------------------------ | ----------------------------------------- |
| 函数在哪      | 本进程 Python                        | Server 进程 / 远程 HTTP                   |
| schema 从哪来 | 从函数签名生成，`registry.schemas()` | 问 Server：`tools/list`                   |
| 怎么执行      | `registry.invoke` 直接调函数         | JSON-RPC：`tools/call`，执行发生在 Server |
| 新增一种能力  | 在本仓库再写一个 `@tool`             | 连一台已有的 Server                       |

常见拆法，和这篇代码一一对应：

| 理论部件 | 含义                                      | 这篇里                                                            |
| -------- | ----------------------------------------- | ----------------------------------------------------------------- |
| Host     | 装客户端的 AI 应用，协调一台或多台 Server | 课上先用 Inspector / 脚本；将来接到 11 的 Agent                   |
| Client   | Host 里、对**一台** Server 的连接器       | SDK 的 `ClientSession`；后面收成 `MCPClient`                      |
| Server   | 提供工具 / 资源 / 提示词的程序            | `mcp-server-time`、Microsoft Learn                                |
| 传输     | 报文怎么走                                | 本地 stdio；远程 Streamable HTTP                                  |
| 数据层   | 报文长什么样、有哪些方法                  | JSON-RPC 2.0；本课只用 `initialize` / `tools/list` / `tools/call` |

规范里 Host 和 Client 是分开的：Cursor、Claude Desktop、我们的 Agent 是 Host；Host 每连一台 Server 就 new 一个 Client。课上常把「Agent = Client」说在一起，指的是 Host 里那个连接器，不是协议少了一个角色。

Server 还能提供 **Resources**（只读上下文）和 **Prompts**（交互模板）。本课只走 Tools，和 08 / 09 同一条 Action 路：模型给出名字和参数，环境去执行，结果当 Observation 回来。

## 传输与报文

两层：外面是传输，里面是 JSON-RPC。换传输，方法名和参数不变。

| 传输                | 场景                                  | 这篇里                                     |
| ------------------- | ------------------------------------- | ------------------------------------------ |
| **stdio**           | 本机拉起一个子进程，走 stdin / stdout | `stdio_client` + `uvx mcp-server-time`     |
| **Streamable HTTP** | 远程服务，HTTP POST，可选 SSE 流式    | `streamable_http_client` + Microsoft Learn |

还有更早的 HTTP+SSE，规范已弃用，课上不用。口里说「HTTP」时，代码用的是 Streamable HTTP，不是随便一个 REST 接口。

报文是 JSON-RPC 2.0：

```json
{
  "jsonrpc": "2.0",
  "id": "req-123",
  "method": "tools/call",
  "params": {
    "name": "get_current_time",
    "arguments": { "timezone": "Asia/Shanghai" }
  }
}
```

SDK 把这层挡住了：调用方写 `session.call_tool(...)`，看不到原始帧。调试时用 Inspector 才能看清线上跑的是这些方法。

本课会碰到的三个方法：

| 方法         | 做什么                                                                           |
| ------------ | -------------------------------------------------------------------------------- |
| `initialize` | 握手：协商协议版本、交换能力。SDK v1 **必须先做**，否则后面的 list / call 会失败 |
| `tools/list` | 发现这台 Server 有哪些工具、参数 schema 是什么                                   |
| `tools/call` | 按名字调用，带上 arguments                                                       |

## 协议版本和 SDK 版本

容易混成「MCP 1.0 / 2.0」。协议本身**不用** 1.0、2.0 编号，用日期：`YYYY-MM-DD`，表示最近一次不兼容变更的日期。Python 包 `mcp==1.28.1` 是 **SDK 的** 1.x，不是协议 1.0。

| 东西               | 版本                                                                                        | 这篇用不用                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 协议（握手时代）   | `2024-11-05` → `2025-11-25`                                                                 | 用。连接先 `initialize`                                                      |
| 协议（无状态时代） | `2026-07-28`（2026-07-28 已正式发布）                                                       | 不用。无握手，改走 `server/discover`，每条请求自带 `_meta`                   |
| Python SDK v1      | `mcp==1.28.1`（[v1.28.1](https://github.com/modelcontextprotocol/python-sdk/tree/v1.28.1)） | **本课锁定这个**                                                             |
| Python SDK v2      | `mcp` 2.x，与 `2026-07-28` 同日发布                                                         | 不用。API 已换成 `Client(target)`，不再手写 `ClientSession` + `initialize()` |

`2026-07-28` 是协议至今最大的一次改动，社区和媒体常口头叫「MCP 2.0」，官方名称仍是日期。主变化：去掉 `initialize` / `initialized` 和会话 ID，请求可打到负载均衡后面任意实例；需要先探能力时用 `server/discover`。旧版 Server 仍可用，规范保证至少 12 个月重叠。v1 SDK 进入维护，只收安全和关键修复；新项目才考虑 2.x。

本课全部代码都走 v1 握手：`await session.initialize()` 这一行不是样板，是这个时代的协议要求。

## stdio：连本地 time 服务器

先声明「怎么拉起 Server」。stdio 没有 URL，参数是命令行：

```python
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

server_params = StdioServerParameters(
  command="uvx",
  args=["mcp-server-time"],
)
```

`uvx` 会临时拉起 `mcp-server-time` 子进程；Client 的 stdin/stdout 接到这个进程上。进程在，连接在；上下文退出，进程关掉。

### 发现工具

```python
async def main():
  async with stdio_client(server_params) as (read, write):
    async with ClientSession(read, write) as session:
      await session.initialize()
      tools = await session.list_tools()
      print(tools.model_dump_json(indent=2, ensure_ascii=False))
```

三层套在一起，每一层都有事做：

| 层              | 做什么                          |
| --------------- | ------------------------------- |
| `stdio_client`  | 起进程，交出读写流              |
| `ClientSession` | 在流上讲 JSON-RPC               |
| `initialize()`  | 握手。v1 里漏了这步，后面会报错 |

Notebook 里已经有事件循环，不能再 `asyncio.run()`。后面每个异步示例都用同一段收尾，只写一次：

```python
try:
  loop = asyncio.get_running_loop()
except RuntimeError:
  asyncio.run(main())
else:
  loop.create_task(main())
```

> **说明：** 没有循环（普通脚本）就 `asyncio.run`；已有循环（Notebook）就 `create_task`。重新跑那个 cell 即可。

输出里真正要看的是 `tools[]`：名字、说明、入参 schema。其余 `meta` / `icons` / `execution` 先忽略。

```json
{
  "tools": [
    {
      "name": "get_current_time",
      "description": "Get current time in a specific timezone",
      "inputSchema": {
        "type": "object",
        "properties": {
          "timezone": {
            "type": "string",
            "description": "IANA timezone name (e.g. 'America/New_York'). 本地用 'Asia/Shanghai'"
          }
        },
        "required": ["timezone"]
      },
      "annotations": {
        "readOnlyHint": true,
        "destructiveHint": false,
        "idempotentHint": true
      }
    },
    {
      "name": "convert_time",
      "description": "Convert time between timezones",
      "inputSchema": {
        "type": "object",
        "required": ["source_timezone", "time", "target_timezone"]
      }
    }

```

和 09 生成出来的 schema 是同一类东西：模型靠 `name` + `description` + `inputSchema` 决定调不调、参数填什么。差别是这份 schema **Server 给的**，Client 没有函数可 `inspect`。


## HTTP：连远程 Microsoft Learn

方法名不变，只换传输。没有 `command` / `args`，改传 URL。

```python
import asyncio
from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client

async def main():
  async with streamable_http_client("https://learn.microsoft.com/api/mcp") as (
    read_stream,
    write_stream,
    _,
  ):
    async with ClientSession(read_stream, write_stream) as session:
      await session.initialize()
      tools = await session.list_tools()
      print(tools.model_dump_json(indent=2, ensure_ascii=False))
```

`initialize` 一次 HTTP，`tools/list` 再一次。stdio 时这两步走的是同一对管道，这里变成两次请求，语义不变。

这台 Server 暴露三个工具（description 很长，只留名字和入参）：

| `microsoft_docs_search`        | `query`                  | 搜官方文档，返回若干条 title / URL / 摘要 |
| `microsoft_code_sample_search` | `query`，可选 `language` | 搜官方代码示例                            |
| `microsoft_docs_fetch`         | `url`                    | 把指定文档页拉成 Markdown                 |

`microsoft_docs_search` 的 schema 骨架：

```json
{
  "name": "microsoft_docs_search",
  "title": "Microsoft Docs Search",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": {
        "type": "string",
```

完整返回里 `content[0].text` 往往是一整页检索结果，十几条 × 每条数百 token。结构如下，正文用省略号收掉：

```json
{
  "content": [
    {
      "type": "text",
      "text": "[{\"title\": \"...Excel...\", \"contentUrl\": \"https://learn.microsoft.com/...\", \"content\": \"在 C# 中用 Open XML / EPPlus 读取工作簿...\"}, ...共约 10 条]"
    }
```

stdio 和 HTTP 对照：

|          | stdio（time）                             | HTTP（Learn）                                 |
| -------- | ----------------------------------------- | --------------------------------------------- |
| 连接参数 | `command` + `args`                        | `url`                                         |
| 读写流   | `stdio_client` → `(read, write)`          | `streamable_http_client` → `(read, write, _)` |
| 会话     | 都是 `ClientSession`                      | 同左                                          |
| 之后     | `initialize` → `list_tools` / `call_tool` | 同左                                          |

第三项 `_` 是 HTTP 传输多出来的（会话/握手回调一类），本课用不到。调用方真正重复写的，是「选传输 → 建 Session → initialize」。这就是第一层封装要收的。

## 封装：连接

到这里，list 和 call 各写了一遍 stdio、一遍 HTTP，四段代码前半截几乎一样。抽 `connect_mcp`：配置里用 `type` 选传输，交出**已经 initialize 完**的 `session`。

配置先写成一份 dict，后面的类直接吃它：

```python
import asyncio
from contextlib import asynccontextmanager

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client
from mcp.client.streamable_http import streamable_http_client

mcp = {
  "servers": {
    "time": {
      "type": "stdio",
      "command": "uvx",
      "args": ["mcp-server-time"],
    },
    "microsoft-learn": {
      "type": "http",
      "url": "https://learn.microsoft.com/api/mcp",
    },
  }
}

@asynccontextmanager
async def connect_mcp(server_config: dict):
  """按配置连接一台 MCP Server，yield 已 initialize 的 ClientSession。"""
  if server_config["type"] == "stdio":
    params = StdioServerParameters(
      command=server_config["command"],
      args=server_config.get("args", []),
    )
    async with stdio_client(params) as (read, write):
      async with ClientSession(read, write) as session:
        await session.initialize()
        yield session
  elif server_config["type"] == "http":
    async with streamable_http_client(server_config["url"]) as (read, write, _):
      async with ClientSession(read, write) as session:
        await session.initialize()
        yield session
  else:
    raise ValueError(f"不支持的服务器类型: {server_config['type']}")
```

| 抽进去的                         | 为什么现在抽                                        |
| -------------------------------- | --------------------------------------------------- |
| 按 `type` 选 stdio / HTTP        | 调用方不该在每个 list / call 里写一遍分支           |
| `ClientSession` + `initialize()` | v1 每次连接都要握手；漏写会在下一层才爆             |
| 生命周期（`async with`）         | 进程 / HTTP 流必须进得去出得来，不能只 connect 不关 |

`@asynccontextmanager` 让 `yield session` 前后的 `async with` 仍然包住整段调用。调用方只看到：

```python
async with connect_mcp(config) as session:
  ...
```

传输和握手已经发生过了。

## 封装：单台 Server 的 list / call

有了连接，获取工具和调用还可以再收一层：调用方如果只想「问这台要列表 / 调一个工具」，不必自己碰 `session`。

```python
async def list_server_tools(server_config: dict):
  async with connect_mcp(server_config) as session:
    return await session.list_tools()

async def call_server_tool(
  server_config: dict,
  tool_name: str,
  arguments: dict | None = None,
):
  async with connect_mcp(server_config) as session:
    return await session.call_tool(tool_name, arguments or {})
```

验证仍用 time，确认封装没有改语义：

```python
async def main():
  tools = await list_server_tools(mcp["servers"]["time"])
  print(tools.model_dump_json(indent=2, ensure_ascii=False))
```

输出与前面 stdio 的 `tools/list` 相同（`get_current_time`、`convert_time`），不重复贴。

```python
async def main():
  result = await call_server_tool(
    mcp["servers"]["time"],
    "get_current_time",
    {"timezone": "Asia/Shanghai"},
  )
  print(result.model_dump_json(indent=2, ensure_ascii=False))
```

```json
{
  "content": [
    {
      "type": "text",
      "text": "{\"timezone\": \"Asia/Shanghai\", \"datetime\": \"2026-08-29T20:04:14+08:00\", \"day_of_week\": \"Saturday\", \"is_dst\": false}"
    }
```

## 封装：多 Server 的 MCPClient

把完整配置收进一个对象。调用方记 Server 的**名字**（`time`、`microsoft-learn`），不再传那一段 config。

先只写异步：`alist_tools` 遍历全部 Server；`acall_tool` 按名字打到其中一台。

```python
class MCPClient:
  def __init__(self, config: dict):
    self.servers = config["servers"]

  async def alist_tools(self) -> list:
    results = []
    for name, config in self.servers.items():
      async with connect_mcp(config) as session:
        tools = await session.list_tools()
        results.append({"server": name, "tools": tools})
    return results

  async def acall_tool(
    self,
    server_name: str,
    tool_name: str,
    arguments: dict | None = None,
  ):
    config = self.servers[server_name]
    async with connect_mcp(config) as session:
      return await session.call_tool(tool_name, arguments or {})

client = MCPClient(mcp)
```

| 相对上一层                     | 为什么加这一层                                                 |
| ------------------------------ | -------------------------------------------------------------- |
| 不再传 `mcp["servers"]["xxx"]` | 配置在构造时收齐；调用处只留名字                               |
| `alist_tools` 一次扫全部       | Agent 要给模型的是「所有可用工具」，不是某一台                 |
| 每条结果带 `server`            | 两台 Server 可能都有叫 `search` 的工具，调用时必须知道打到哪台 |

```python
async def main():
  all_tools = await client.alist_tools()
  for item in all_tools:
    print(f"===== {item['server']} =====")
    names = [t.name for t in item["tools"].tools]
    print(names)
```

```text
===== time =====
['get_current_time', 'convert_time']
===== microsoft-learn =====
['microsoft_docs_search', 'microsoft_code_sample_search', 'microsoft_docs_fetch']
```

原来 `model_dump_json` 会把两台 Server 的完整 schema 再倒一遍，和前面 list 重复。接到 09 的 `session.tools` 时才需要完整 schema；这里先确认「名字按 Server 归堆」即可。

```python
async def main():
  result = await client.acall_tool(
    "time",
    "get_current_time",
    {"timezone": "Asia/Shanghai"},
  )
  print(result.model_dump_json(indent=2, ensure_ascii=False))
```

结果与 `call_server_tool` 那次相同，略。差别只是第一个参数从 config 变成了 `"time"`。

## 封装：同步

09 的 `registry.invoke`、11 的 `agent.invoke` 都是**同步**函数。MCP SDK 的 API 全是 async。最后一层把异步包成同步，将来才能当普通 Tool 接进 registry。

`asyncio.run()` 能跑协程并返回结果，但要求**当时没有别的事件循环**。Jupyter 自己占着主循环，直接 `asyncio.run` 会报错。前面用 `create_task` 是「在已有循环里再丢一个任务」，调用方拿不到返回值——Notebook 演示可以，当函数用不行。

办法：新开一个线程，在那个线程里 `asyncio.run`。每个线程自己的循环，不碰 Jupyter 的主循环。

```python
import threading

def run_async(coro):
  """在独立线程里跑协程，阻塞等到结果。"""
  result = None
  error = None

  def _run():
    nonlocal result, error
    try:
      result = asyncio.run(coro)
    except Exception as e:
      error = e

  t = threading.Thread(target=_run)
  t.start()
  t.join()

  if error:
    raise error
  return result
```

给 `MCPClient` 加两个同步入口，内部转去已有的异步方法：

```python
class MCPClient:
  def __init__(self, config: dict):
    self.servers = config["servers"]

  async def alist_tools(self) -> list:
    results = []
    for name, config in self.servers.items():
      async with connect_mcp(config) as session:
        tools = await session.list_tools()
        results.append({"server": name, "tools": tools})
    return results

  async def acall_tool(
    self,
    server_name: str,
    tool_name: str,
    arguments: dict | None = None,
  ):
    config = self.servers[server_name]
    async with connect_mcp(config) as session:
      return await session.call_tool(tool_name, arguments or {})

  def list_tools(self) -> list:
    return run_async(self.alist_tools())  # type: ignore

  def call_tool(
    self,
    server_name: str,
    tool_name: str,
    arguments: dict | None = None,
  ):
    return run_async(self.acall_tool(server_name, tool_name, arguments))
```

异步方法保留：本来就在 async 上下文里时，不必绕一圈线程。同步方法给 09 / 11 那种调用方。`# type: ignore` 是因为类型检查不一定认「协程当参数传给 `run_async`」。

四层各自收了什么：

| 层 | 调用方从此不用写 | 还露在外面 |
| --- | --- | --- |
| `connect_mcp` | 选传输、建 Session、`initialize` | 仍要 `async with`，仍要自己 list / call |
| `list_server_tools` / `call_server_tool` | 碰 `session` | 仍要传某一台的 config |
| `MCPClient` | 传 config 片段 | 仍是 async |
| `run_async` + `list_tools` / `call_tool` | async / 事件循环 | 配置仍在构造时传入；工具还没进 09 的 registry |

## Agent 接入 MCP

客户端零件齐了。下面接到 11 的 Agent：配置离开代码、收成 09 能注册的 Tool、让模型在 system 里看见远程工具目录。和 13 是同一类接法——13 接的是提示词模块，这里接的是外部工具。

| 13 Skill | 14 MCP | 为什么同一类 |
| --- | --- | --- |
| 磁盘上的 `SKILL.md` | 磁盘上的 `mcp.json` | 增删不改 Python |

## 网关工具

09 的 schema 来自函数签名。MCP 工具的签名在 Server 上，**import 时还不知道**，不能在本仓库给 `get_current_time` 写一个 `@tool`。于是本仓库只暴露一个网关：`use_mcp(server_name, tool_name, arguments)`。真正有哪些远程工具，写在 system 的目录里，模型对着目录填这三个参数。

`agent/tool/use_mcp.py`：前面的 `connect_mcp` / `run_async` / `MCPClient` **原样搬进来**，不要改。多出来的是读 json、模块级单例、以及两个给外面用的函数：

```python

# connect_mcp / run_async / MCPClient 与上一节相同，略

  tool_name="工具名称",
```

## 渲染时拉取 MCP 目录

13 的 `list_skills()` 只读磁盘。MCP 的目录在 Server 上，启动时必须真的去 `tools/list`。`prompt.py` 其余（环境三项、`list_skills`、Jinja 加载）与 13 相同；新增的是 `list_mcp_info`，以及 `render` 多一个关键字参数。

```python
def list_mcp_info() -> str:
  try:
    from connect_model_demo.agent.tool.use_mcp import list_mcp_tools

    raw = list_mcp_tools()
    result = []
    for item in raw:
      tools = []
      for t in item["tools"].tools:
        tools.append(
          {
            "name": t.name,
            "description": t.description or "",
            "inputSchema": t.inputSchema,
          }
        )
      result.append({"server": item["server"], "tools": tools})
    return json.dumps(result, ensure_ascii=False, indent=2)
  except Exception:
    return ""

def render_prompt(prompt_name: str) -> str:
  template_dir = os.path.join(os.path.dirname(__file__), "prompt")
  env = Environment(loader=FileSystemLoader(template_dir))
  template = env.get_template(f"{prompt_name}.j2")
  return template.render(
    cwd=get_cwd(),
    os=get_os(),
    is_git=get_is_git(),
    skills=list_skills(),
    mcp_servers=list_mcp_info(),
  )
```

`list_mcp_info` 在干什么：

| 步骤 | 作用 |
| --- | --- |
| 调 `list_mcp_tools()` | 对 json 里每一台 Server 握手 + `tools/list`（同步，走 `run_async`） |
| 只留 name / description / inputSchema | 丢掉 `icons`、`annotations` 等模型填参用不到的字段 |
| `json.dumps` 成字符串 | 模板是 `{{ mcp_servers }}`，不是循环；必须是已经序列化的文本 |
| `except` 返回 `""` | 某一台挂了不把 `Agent()` 打崩；模型会看见空目录，以为没有 MCP |

> **说明：** 构造 `Session` / `Agent` 时就会连一遍所有 Server。stdio 的 time 会拉起 `uvx` 子进程，HTTP 会打到 Microsoft Learn。这和 cwd 一样是**启动快照**：会话中途你改了 `mcp.json`，当前这条 Session 看不见。某台失败被吞掉之后，system 里 json 围栏是空的，排查时先单独跑 `list_mcp_tools()`，不要只看 Agent 打出来的提示词。

函数内部才 `import list_mcp_tools`，是为了避免 `prompt.py` 和 `tool` 包在模块加载期互相绕。`render_prompt` 仍只在 `Session` 构造时调一次，07：历史不可改。
