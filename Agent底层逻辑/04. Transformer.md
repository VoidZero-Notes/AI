上一篇把文本切成了 **Token ID** 序列，但编号没有语义，也不能做加减乘除来表达词与词的关系。本篇从**词嵌入**讲起，走完 Transformer 的前向传播（注意力、Block、线性层），讲清训练目标其实就是「预测下一个 Token」，再补上推理（预填充 / KV 缓存 / 采样）以及预训练、后训练与持续学习。一条主线贯穿：词嵌入 → 注意力 → Transformer Block → 线性层 → 下一词预测 → 推理 → 训练阶段。

| 概念 | 含义 |
| --- | --- |
| **词嵌入** | 按 Token ID 查表，得到高维向量 |
| **注意力** | 用 Q / K / V 让每个位置按上下文改写自身 |
| **因果掩码** | 每个位置只能看自己和左边，不能看未来 |
| **Transformer Block** | 多头注意力 + 残差 / 归一化 + 前馈网络，可堆叠 |
| **线性变换层** | 映射到词表大小，得到下一个 Token 的 logits |
| **推理** | 预填充、K-V 缓存、采样（或贪心） |
| **预训练 / 后训练** | 先在海量文本上预测下一词，再学对话、价值观与专项能力 |

后续贯穿同一个玩具尺寸：4 个 Token、每个 6 维，词表大小记为 $120000$。

## 词嵌入（Word Embedding）

> 词嵌入是 Transformer 架构前向传播的**第一个阶段**。

### Token 的问题

上一篇已经把文本切成一串 **Token ID** 序列。但 Token ID 不能直接拿来训练，根源在于：

- **Token ID 无法表示语义**：它只是文字符号的编号。仅凭一个编号无法承载其背后丰富的含义——比如你未必知道 `كِتاب` 这个 Token 对应的文字是什么意思。
- **Token ID 无法表达语义之间的数学关系**：假设「吃苹果」对应的 Token 序列是 `[33256, 11789]`，那么 `33256 + 11789` 是什么含义？显然毫无意义。

因此我们需要用**更多的维度**来刻画一个 Token。

### 用向量描述 Token

以「苹果」为例，可以从多个角度描述它：

- 是一种食物；
- 和科技有关系；
- 比较昂贵。

数字化后可表示为一个 3 维向量：

- 维度 1（可被食用的程度）：0.9
- 维度 2（科技程度）：0.6
- 维度 3（消费水平）：0.5

若另一个 Token 被描述为 $[0.7, 0.8, 0.3]$，把它们放进同一个三维空间，可以想象这两个点在空间中比较接近——**语义相近的词，向量距离也相近**。

> 向量可视化工具：<https://projector.tensorflow.org/>

当 Token 被转成多维数字向量后，它们之间就能形成有趣的数学关系：

- $\text{苹果} \approx \text{Apple}$
- $\text{国王} - \text{王后} \approx \text{男人} - \text{女人}$
- $\text{男人} + \text{医生} \approx \text{男医生}$
- $2 \times \text{开心} \approx \text{狂喜}$
- ……

把一个 Token 转换成多维数字向量的过程，就称为**词嵌入（Word Embedding）**。

> **说明：** 「嵌入（Embedding）」的本意，是把低维离散对象「镶嵌、植入」到一个连续的高维几何空间里，从而让离散符号获得可计算的几何结构。

### 维度由谁决定

那么每个 Token 该有多少维度？每个维度表达什么含义？每个维度的值又是多少？

**在深度学习中，我们只规定学习方法，永远不要告诉机器答案。**

因此我们只规定**维度的数量**（如 768、4096 维），至于每个维度代表什么、取值多少，全部交给机器在训练中自行学习填写。训练完成后，这些维度往往不具备人类可解释的明确含义，但整体上确实编码了语义。

本篇玩具例子里，这个数量取 $6$。

### 嵌入就是查表

实现上，词嵌入是一张形状为 **词表大小 × 隐藏维度** 的矩阵。玩具例子里就是 $120000 \times 6$：每一行对应一个 Token ID，一行就是该 Token 的向量。

输入 `[33256, 11789, …]` 时，并不对 ID 做加减，而是把第 $33256$ 行、第 $11789$ 行……抽出来，叠成 $4 \times 6$ 的矩阵。这就是为什么上一篇说：换分词器等于换了一套 ID，嵌入矩阵对不上，模型立刻失效。

> **说明：** 有的模型会把后面「线性变换层」的权重与这张嵌入表共享（转置使用），称为权重绑定（weight tying），用来减小参数量、让输入输出空间对齐。不是所有模型都这么做。

### 额外术语

- **上下文长度（Context Length）**：一次实际传入 Transformer 的 Token 数量。
- **上下文窗口长度（Context Window）**：Transformer 能容纳的**最大** Token 数量。超出窗口的部分进不去，只能截断或滑走。

## 注意力机制（Attention）

Google 2017 年论文：[《Attention Is All You Need》](https://arxiv.org/pdf/1706.03762)

原论文是编码器 + 解码器，用来做机器翻译。目前大模型通常只保留 **Decoder**：任务不是「读一句外文再写一句中文」，而是「根据已经出现的 Token，写下一个 Token」。

![transformer_decoder](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-08-23-150955.png)

接下来先按**训练**的前向传播往下讲；推理机制放到后文单独说。

假设现在已经得到一个 $4 \times 6$ 的矩阵（4 个 Token、每个 6 维），它来自上一阶段 Embedding 的输出，记为 $X$。

### Embedding 的局限

Embedding 层为**每个词单独**编码了语义。但同一个词在不同上下文中，含义会发生变化，Embedding 无法体现这种「随上下文而变」的动态语义。例如：

- 「他一把把把把住了」——同一个「把」字承担了完全不同的角色。
- 「你这是什么**意思**？」「没什么意思，就是**意思意思**」「你这就不够**意思**了」「小意思小意思」「你这人真有**意思**」「其实也没有别的意思」「那我就不好意思了」「是我不好意思」。
- 「请问你要几**等**座？」「你们有几**等**」「一等、二等、特等**等等**，特等要多**等等**」「我看一下，**等一等**」。
- 「衣服上除了校徽，不要**别别**的」「**别**啊，我就喜欢**别别**的」「那你就**别别**了！」

同一个字/词，语义随上下文剧烈变化——这正是仅靠静态 Embedding 无法解决的问题。

### 注意力要解决的问题

注意力机制的目标：**输入一个 $4 \times 6$ 的矩阵，输出一个 $4 \times 6$ 的矩阵**，且输出矩阵要表达——

**每个 Token 在受到上下文影响之后，应该如何调整自身的值。**

也就是说，注意力让每个 Token「环顾」序列中的其他 Token，按相关程度（注意力权重）汇聚信息，从而把静态的词向量重塑为**融入上下文语义的动态表示**。

### Query、Key、Value

环顾不是把 4 行平均一下。每个位置会先被投影成三种角色：

- **Query（Q，查询）**：我在找什么。
- **Key（K，键）**：我身上有什么可被别人检索的标签。
- **Value（V，值）**：我真正要传递出去的内容。

对应三张可学习的权重矩阵 $W_Q$、$W_K$、$W_V$。以玩具尺寸为例，它们都可以是 $6 \times 6$，于是：

$$
Q = X W_Q,\quad K = X W_K,\quad V = X W_V
$$

$Q$、$K$、$V$ 都是 $4 \times 6$。第 $i$ 行属于第 $i$ 个 Token。

第 $i$ 个 Token 对第 $j$ 个 Token 的关注程度，用第 $i$ 个 Query 和第 $j$ 个 Key 的内积来衡量，再除以 $\sqrt{d_k}$ 防止点积过大、Softmax 挤成「赢家通吃」：

$$
S = \frac{Q K^{\top}}{\sqrt{d_k}}
$$

$S$ 是 $4 \times 4$：$s_{ij}$ 越大，表示位置 $i$ 越该去读位置 $j$ 的 Value。对每一行做 Softmax，得到注意力权重 $A$，再按权重把 Value 加起来：

$$
A = \mathrm{softmax}(S),\qquad \mathrm{Attention}(Q, K, V) = A V
$$

结果仍是 $4 \times 6$：每一行都是「被上下文改写过」的新向量。

### 因果掩码：不能看未来

大模型训练的目标是预测**下一个** Token。如果位置 $i$ 在算注意力时已经看见了位置 $i+1, i+2, \ldots$ 的内容，等于考试时把答案印在卷面上，损失会假低，上线后也不会写。

因此要在 $S$ 上加**因果掩码（causal mask）**：位置 $i$ 只能看见 $j \le i$ 的 Key / Value；对 $j > i$ 的分数记为 $-\infty$，Softmax 之后权重就是 $0$。

4 个 Token 时，每个位置能看见的范围是：

| 当前位置 | 可以看 |
| --- | --- |
| 第 1 个 | 只有自己 |
| 第 2 个 | 第 1、2 个 |
| 第 3 个 | 第 1、2、3 个 |
| 第 4 个 | 全部 4 个 |

这就是 Decoder-only 的核心约束，也叫**自回归（autoregressive）**：生成第 $t$ 个词时，世界里只存在前 $t-1$ 个词。

> **说明：** 原论文的 Encoder 没有这层掩码，因为翻译时源句子可以一次看完。LLM 丢掉 Encoder，不是架构偷懒，是任务从「双向理解源句」变成了「从左往右续写」。

## Transformer Block

<img src="https://resource.duyiedu.com/yuanjin/202607201528441.svg" alt="transformer_decoder" style="zoom:60%;" />

单个 Transformer Block 接收一个 $4 \times 6$ 的矩阵，输出一个 $4 \times 6$ 的矩阵。中间经过大量运算后，输出矩阵的**每一行**都包含了大量上下文信息，再交给下一个 Block，循环往复。

> DeepSeek V4 Pro 拥有 61 个 Transformer Block。

最后一个 Block 的输出，每一行都表达了一个**完整的上下文**。Block 堆得越深，表示通常越抽象：浅层多是局部搭配，深层才把整段语义捏到一起。

Block 内依次经过以下阶段。

### 多头注意力

上一节是「一套」Q / K / V。**多头（Multi-Head）**是把同一段 $X$ 平行送进若干套较小的注意力，再拼回来。

玩具例子里若做 2 个头，每个头的 $d_k = 3$：两套注意力各自输出 $4 \times 3$，拼成 $4 \times 6$。不同头可以盯不同类型的关系——有的偏向相邻搭配，有的偏向远程指代——总维度不变，表达能力更宽。

现代大模型还会在多头注意力阶段注入 Token 的**位置信息**。

### 为什么需要位置编码

注意力本身只看内容相似度：把四个 Token 换个顺序，只要向量还是那四个，配对关系可以不变。可语言不是袋子，「狗咬人」和「人咬狗」必须能分开。

因此要在 Q、K 里写入位置。本篇用的算法是**旋转位置编码（RoPE）**：针对的矩阵是 Q 和 K（不改 V），时机是多头切分之后、注意力得分计算之前。它按位置给向量做旋转，点积里自然带上相对距离，外推到更长上下文时也比早期的「把位置向量加进 Embedding」更稳。

### 注意力之后的残差连接（Add）

将多头注意力阶段得到的输出，和它的**输入**相加，得到 $4 \times 6$ 的矩阵：

$$
X \leftarrow X + \mathrm{Attention}(X)
$$

相加的那份原输入就是「残差」。没有它，注意力一旦改坏某一维，后面几十个 Block 很难把原信息找回来；梯度也更难穿过深网络——这和第 02 篇里激活函数避免「整网塌成一次线性变换」是同一类考虑：给信息留一条直路。

### 注意力之后的归一化（Norm）

通过 RMSNorm（均方根归一化），把各向量的数值量级压到比较稳定的范围（课件里大部分会落到 $[-3, 3]$ 附近）。这一步主要是为了防止梯度爆炸和梯度消失，得到 $4 \times 6$ 的矩阵。

RMSNorm 按均方根缩放，不做 LayerNorm 那种减均值。效果是：无论上一层输出整体偏大还是偏小，送进下一层时尺度大体可控。

> **说明：** 上面顺序是先算子层、再 Add、再 Norm（Post-Norm），与课件图一致。很多现代实现改成先 Norm 再进注意力 / FFN（Pre-Norm），深网络更好训。读 Llama 一类结构图时，Norm 的位置可能和本篇相反，不要按错。

### 前馈网络（FFN）

注意力混的是「Token 与 Token 之间」的信息。FFN 则在**每一个位置上单独**做一层（通常是两层）全连接：先把 6 维升到更大（常见约 4 倍），过非线性激活，再投回 6 维。位置之间不在这里互相看书。

这一层主要是为了提升模型的复杂度。FFN 的中间神经元相当于存储了不同的「知识片段」或「模式模板」。当模型看到一个特定的上下文时，相关的 FFN 神经元会被激活，输出对应的知识。

不同大模型在这一层的设计不一样。例如 DeepSeek V4 Pro 使用 **MoE（混合专家）**：不是所有 Token 都走同一个大 FFN，而是准备多组专家 FFN，每个 Token 只激活其中少数几个。参数量可以很大，单次前向的计算量却不必按专家总数线性涨。

得到 $4 \times 6$ 的矩阵（该矩阵仍然表达的是一个残差）。

### FFN 之后的残差连接（Add）

将 FFN 阶段得到的输出和它的输入相加，得到 $4 \times 6$ 的矩阵。理由与注意力后的残差相同：保住 FFN 改写之前的表示，并给梯度留直路。

### FFN 之后的归一化（Norm）

再次通过 RMSNorm，把量级压稳，防止梯度爆炸和梯度消失，得到 $4 \times 6$ 的矩阵。

到这里，**单个 Transformer Block 全部完成**。下一个 Block 吃的就是这个 $4 \times 6$，不再回看原始 Embedding。

## 线性变换层

大多数模型的线性变换层（也叫解嵌入、lm_head）就是一个单层全连接，没有这一层的激活函数。它把最后一个 Block 的 $4 \times 6$，变成 $4 \times 120000$。

输入每行 6 维、输出每行 $120000$ 维（词表里每一个 Token 一个分数），权重矩阵 $W$ 的形状是 **$6 \times 120000$**：

$$
\mathrm{Logits} = X W
$$

$120000$ 不是随便写的数，就是词表大小 $|V|$。第 $i$ 行的 $120000$ 个数，是位置 $i$ 对「**下一个 Token 是词表里哪一个**」的打分，称为 **logits**，数值越大，可能性越高。

线性变换后，对每一行做 Softmax，就把一行 logits 变成该位置上的下一个 Token 概率分布（一行加起来为 1）。

> **说明：** 推理时真正用来选词的，通常只是**最后一行**（当前序列末尾）。训练时 4 行都有用：第 1 行预测第 2 个 Token，第 2 行预测第 3 个，第 3 行预测第 4 个，第 4 行预测再往后一个（若没有标签则不算损失）。

## 下一个 Token 预测与反向传播

大模型在 Transformer 里做的监督学习，几乎都收束成同一件事：**已知左边，预测下一个 Token**。

程序读取原始语料，把「当前位置右边那个 Token」当作标签。例如序列是 $[t_1, t_2, t_3, t_4]$，则：

| 位置看到的上下文（含因果掩码） | 标签 |
| --- | --- |
| $t_1$ | $t_2$ |
| $t_1, t_2$ | $t_3$ |
| $t_1, t_2, t_3$ | $t_4$ |
| $t_1, t_2, t_3, t_4$ | $t_5$（若有） |

标签已经写在文本里，不必人工标注，所以预训练叫**自监督**。损失用**交叉熵**：正确那个 Token 的预测概率越接近 1，损失越小。这和第 02 篇的 MSE 不同——那里是回归连续值，这里是在词表上做分类。

反向传播把交叉熵对所有参数（嵌入表、$W_Q$ / $W_K$ / $W_V$、FFN、线性层……）求梯度，再按学习率更新。训练时 4 个位置可以**一次并行**算完，因为因果掩码保证它们谁也没偷看未来；这和第 02 篇「前向 → 损失 → 反向 → 更新」是同一套循环，只是标签定义成了「下一个 Token」。

## 推理机制

> 推理可视化：<https://poloclub.github.io/transformer-explainer/>

训练是「整段输入、并行预测每一个下一词」。推理是**自回归生成**：已经有一段提示，模型只取序列末尾那一行的概率，选出（或采样出）一个新 Token，接到后面，再跑一遍，直到遇到结束符或达到长度上限。

结束符就是词表里的特殊 Token（如 `<|im_end|>`），分词器在上一篇已经出现过。生成到它就停。

若每出一个新 Token 都把整段从头算一遍注意力，第 $t$ 步的代价大约随 $t$ 正比增长，会极慢。所以推理要抓住三点：**预填充（Prefill）**、**K-V 缓存**、**采样策略**。

### 预填充（Prefill）

用户提示（prompt）往往有很多 Token。第一步不是立刻逐字生成，而是把**整段提示**一次送进模型，算出每一个提示位置的隐状态，并得到「提示之后第一个新 Token」的概率分布。这一步叫预填充。提示越长，预填充越重；它通常是对话里第一次开口前的主要等待。

### K-V 缓存

注意力要用到历史上每一个位置的 K 和 V。生成第 $t$ 个新 Token 时，前 $t-1$ 个位置的 K、V **不会因为后面多了一个词而改变**（因果掩码下，过去看不到未来）。因此预填充以及此后每一步算出的 K、V 都可以存下来，下一步只对**新来的那一个 Token** 算 Q / K / V，再拿新的 Q 去和缓存里的全部 K 做点积。

没有缓存：每步重复处理整段历史。有缓存：每步近似只处理 1 个 Token，历史用查表。这就是长对话还能边说边出字的主要原因。代价是显存：层数 × 头数 × 已生成长度，都会堆在这份缓存里，上下文窗口不能无限拉长，也有这一层原因。

### 采样策略

得到最后一行概率之后，还要决定「选出哪一个 Token」。

**贪心（Greedy）**

每一步取概率最大的那个。确定、可复现，但容易死板、重复。温度 $T \to 0$ 时，效果接近贪心。

**温度（Temperature）**

控制输出概率分布的「锐利」或「平滑」程度。在 Softmax **之前**，将所有 logits 除以温度值 $T$。

- $T = 1$：标准概率分布，不作干预。
- $T < 1$（如 0.5）：分布变得更尖锐，高概率的词概率更高，低概率的词概率更低。文本更稳定、保守、确定。
- $T > 1$（如 1.5）：分布变得更平滑，各词之间的概率差距缩小。文本更具随机性、多样性、创造力。

**Top-K 采样**

只从概率最高的 **K** 个词中随机抽取，其余词的采样概率直接被置零。比如设置 $K = 50$，模型会先选出概率最高的 50 个词，过滤掉剩余海量词汇，然后在这 50 个词中按新的概率分布采样。

**Top-P（核采样，Nucleus Sampling）**

从累积概率达到 **P** 的最小词集合中采样。

比如设置 $P = 0.9$，模型会按概率从高到低累加词，直到累积概率超过 0.9，然后仅从这个动态的「核心」词汇子集中采样。

这是目前最主流、效果最好的采样方式之一。它比 Top-K 更灵活，因为 K 是固定的，而 P 是动态的：当概率分布很集中时，采样集很小，输出更确定；当分布很分散时，采样集很大，输出更多样。

实践中常把温度、Top-K、Top-P 一起用：先除以 $T$，再截断候选，再采样。

## 训练阶段

![image-20260721163657184](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-08-23-151029.png)

预训练和后训练用的是**同一套** Transformer 权重，差别在数据和目标：前者在海量生文本上预测下一词，后者在更少、更贵的数据上把模型拧成能对话、安全、会推理的助手。

### 预训练特点

- **耗时最长**（通常占总计算时间的 90% 以上）
- **自监督学习**：标签就是文本里的下一个 Token
- **算力是主要成本**

通过预训练，模型具备了以下能力：

- **理解人类语言的语法规律**
- **能感知上下文语境**，能识别不同语境下词语含义的变化
- **知晓世界的基本事实**：太阳系有几大行星、第二次世界大战是哪一年结束的、Python 语言的创始人是谁
- **拥有基础的推理能力**：凡人均有一死，苏格拉底是人，所以苏格拉底会死
- **拥有基础的模式识别能力**：$2, 4, 6, 8, ?$
- **拥有基础的上下文学习能力**：你是一个智能客服，请在回答问题的时候称用户为「宝宝」。用户的问题是：还有货吗？

这些能力不是单独的模块，而是「总在猜下一个词」时被逼出来的：猜对下一词，必须同时用到语法、事实和一点推理。

### 后训练特点

- **耗时很短**（几小时、几天、几个月）
- 主要依靠**监督微调（SFT）**和**强化学习**
- **数据与人力是主要成本**
- 也会注入**专业领域知识**（用领域对话 / 文档继续做下一词预测或 SFT）

**让模型学会对话格式（SFT）**

```text
输入：
<|im_start|>system<|im_sep|>你是一个AI聊天助手，你的名字叫袁大炮<|im_end|><|im_start|>user<|im_sep|>你好，你是谁？<|im_end|><|im_start|>assistant<|im_sep|>

输出：
我是袁大炮<|im_end|>
```

模型学会：对话格式、对话中的角色身份、对话语气、……。损失函数仍是交叉熵，只是语料从网页正文换成了「按角色切好的对话」，并且常常只在 assistant 要说的那些 Token 上算损失。

**树立价值观（奖励模型 + 强化学习）**

什么回答是安全的、有用的、诚实的。通过人类标注的「好 / 坏」回答对比，训练**奖励模型**，再用强化学习让策略（也就是这个 Transformer）趋利避害。这一套常统称为 **RLHF**。第 02 篇提到的 SFT，通常是 RLHF 之前那一步。

**能力校准**

加入大量「承认无知」的问答对，比如：用户问「你知道明天会发生什么吗？」，助手答「作为 AI，我无法预测未来，很抱歉无法回答这个问题。」这个过程能有效降低 AI 幻觉问题。

**思维链（Chain of Thought, CoT）**

通过训练和引导，让模型在给出最终答案之前，先把内部的推理步骤「说出来」，即先输出思考过程，再输出最终回答。对模型来说，这仍然是在生成 Token；只是我们要求它先生成一段推理，再生成答案，中间步骤占用上下文，后面的下一词预测才有地方落脚。

```text
输入：
<|im_start|>user<|im_sep|>小明有10个苹果，他给了小红3个，又买了5个，现在他有多少个苹果？<|im_end|>
<|im_start|>assistant<|im_sep|>
<think>

输出：
开始有10个。给了小红3个，还剩 10 - 3 = 7 个。又买了5个，现在有 7 + 5 = 12 个。所以，答案是12个。
</think>
最终答案是 12。<|im_end|>
```

### 持续学习

**持续学习（Continual Learning）** 或 **增量学习（Incremental Learning）**，是指现在的很多大模型厂商会把 AI 和用户之间的对话内容作为语料，持续对大模型进行训练。

这和第 02 篇的**灾难性遗忘**是同一件事的工程面：只拿新对话硬训，旧的通用能力会被改掉。常见对策是混入旧数据、或只用 LoRA 等改少量参数，避免把底座冲掉。

## 和后续的衔接

到这里，大模型在数学上就是：**查表得到向量 → 带因果掩码的深层 Transformer → 对词表做分类 → 一次写出一个 Token**。它不会「先理解再行动」，只会续写。

Agent 要在这之上加循环、工具和外部状态：把工具返回的文本再填进上下文，让同一套下一词预测去决定「调用哪个工具」或「对用户说什么」。那是后面的笔记。
