08 走到一次 `tool_calls` 就停了，文末只留了说明：执行完要把 `role: tool` 追回会话，再调一次模型。09 把「拆调用 → 执行 → 收成 tool 消息」收进 `registry.invoke`，`main.py` 里仍是手工两步：调模型、追回结果、再调一次。

真实任务很少一轮就能做完。缺的不是新的 API，是把「想 → 干 → 看结果 → 再想」收成循环。这个循环有名字：ReAct。

## ReAct 是什么

ReAct = **Reason + Act**（推理 + 行动）。Yao 等人 2022 年的论文 [ReAct: Synergizing Reasoning and Acting in Language Models](https://arxiv.org/abs/2210.03629) 提出：让语言模型把**推理轨迹**和**对外行动**交错进行，而不是只想不干，或只干不想。

04 写过思维链（Chain of Thought, CoT）：答题前先把推理步骤说出来。CoT 全程不碰外部世界——算术、逻辑可以在上下文里算完；「当前目录有哪些文件」「命令跑出来是什么」模型没有眼睛，只能靠参数里的记忆猜，猜错了也无法被事实打断。

另一端是只行动：直接调工具，不把「为什么调、看到了什么、下一步怎么改」留在上下文里。08 那种一次 `tool_calls` 就是半圈行动：模型给出意图，本地执行完如果不再调模型，对话停在 `finish_reason: tool_calls`，推理没有机会吃到真实结果。

ReAct 把每一步拆成三截，然后循环：

| 步              | 含义                                     | 谁产生                     |
| --------------- | ---------------------------------------- | -------------------------- |
| **Thought**     | 根据目前已知，决定下一步干什么、为什么   | 模型                       |
| **Action**      | 对外部世界动手：搜、读文件、跑命令……     | 模型只给意图，环境真正执行 |
| **Observation** | 行动的真实返回：文件内容、命令输出、报错 | 环境                       |

```text
用户：分析 ./agent 目录，把结论写进 分析.md

Thought: 不知道目录里有什么，先列出来
Action:  列出 ./agent
Observation: session.py  model.py  tool/  ...

Thought: 有 session.py，先读它弄清消息怎么存
Action:  读 session.py
Observation: class Session: messages、save、load ...

Thought: 路径猜错了 / 还缺入口，继续读
Action:  再读 / 再列目录
Observation: ……

Thought: 核心模块齐了，可以写文档
Action:  写入 分析.md
Observation: 写入成功

Thought: 任务完成，直接回复用户（不再发出 Action）
```

停的条件是模型给出最终答复、**不再发出 Action**。不是外面规定转几圈，而是模型自己判断「信息够了 / 已经干完」。

![image-20260826234812263](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-08-26-154812.png)

交错的意义：

- Thought 把「下一步干什么」写进上下文，后面的 Action 更稳，少无目的乱调
- Observation 是环境返回的事实，不是模型编的；下一轮 Thought 站在这份事实上，幻觉会被打脸（读到的路径不对，下一轮就会改）
- 失败也可以进下一轮：09 把异常收成字符串回传，就是给下一圈 Thought 用的

| 做法               | 推理             | 行动       | 缺什么                             |
| ------------------ | ---------------- | ---------- | ---------------------------------- |
| 只 CoT             | 有，一次想完     | 无         | 碰不到文件、命令、搜索；事实全靠猜 |
| 只调一次工具（08） | 弱，且吃不到结果 | 有一次     | 结果不回写，无法再想、再调         |
| ReAct              | 每圈都有         | 每圈都可以 | 三截都在，用循环串起来             |

论文里 Action 写成 `Search[query]` 这种文本格式；Chat Completions 里对应的就是 `tool_calls`，Observation 对应 `role: tool` 的 `content`。格式变了，三截没变。

## 和 08 / 09 的对应

三截在前面几篇里已经分别有了，缺的是循环。

| ReAct       | 代码里已经有的                                               | 谁做         |
| ----------- | ------------------------------------------------------------ | ------------ |
| Thought     | 模型本轮生成（思考 / 正文）                                  | 模型         |
| Action      | 返回 `tool_calls`                                            | 模型只给意图 |
| Observation | `registry.invoke` 的执行结果，以 `role: tool` 追回 `session` | 调用方       |

08 文末「追回再调一次」是半圈 ReAct。09 把半圈收成 `registry.invoke`。10 把半圈收进 `while True`，直到本轮没有 `tool_calls`。

循环本身只是那几行。要让它在工程任务上跑得起来，09 的 `read_file` / `write_file` 还不够，调用处也还有样板。先补这几块，再写循环：

| 09                                                                    | 10                                  | 为什么                                                  |
| --------------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------- |
| 只有读 / 写文件                                                       | 增加 `bash_command`                 | 列目录、查路径、跑命令，08 一开始就列过「执行一段命令」 |
| 系统提示词只有 `cwd` / `is_git`                                       | Environment 再注入操作系统          | 有了 shell 工具，模型必须知道该写 bash 还是 cmd         |
| `main.py` 里手写 system 消息、再 `session.tools = registry.schemas()` | 新建 `Session` 时自动注入           | 循环才是这篇的主角，样板不应再占调用处                  |
| 打印完整思考流 + `tool_calls` 整段 JSON                               | 思考只打「思考中...」，工具只打名字 | 循环会跑十几轮，08 那种详细打印会把过程淹没             |

下面先落地支撑循环的封装，最后用代码把 ReAct 跑起来。

## bash 工具

08 把「执行一段命令」列为 Agent 常见需求，当时只实现了读 / 写文件。分析目录、猜路径失败后改用 `ls` / `dir`，都落在 shell 上。按 09 的 `@tool` 再包一个函数即可，函数体用 `subprocess.run`。

`agent/tool/bash_command.py`：

```python
import subprocess
from sys import platform

from connect_model_demo.agent.tool.core import tool

@tool(command="要执行的 bash/shell 命令")
def bash_command(command: str) -> str:
  """执行 bash/shell 命令，返回命令输出结果"""

  shell_flag = "cmd" if platform == "win32" else "/bin/bash"

  result = subprocess.run(
    command,
    shell=True,
    executable=shell_flag,
    capture_output=True,
    text=True,
    timeout=30,
  )

  if result.returncode == 0:
    return result.stdout.strip() or "(命令执行成功，无输出)"
  else:
    return f"[退出码 {result.returncode}]\n{result.stderr.strip() or result.stdout.strip()}"
```

和 09 两个文件工具同一套外壳：装饰器生成 schema，docstring 当 `description`，返回值必须是字符串（空输出也要给模型一句人话，不能回 `""` 让它以为没执行）。失败不抛到 Agent 进程外，而是把退出码和 stderr 写成字符串——与 09 里 `__call__` 把异常收成堆栈是同一意图：模型看到失败原因，下一轮才能改命令。

`executable` 按平台分支：Windows 走 `cmd`，其余走 `/bin/bash`。`timeout=30` 防止 `ping` 一类命令把循环卡死。

还要在 `agent/tool/__init__.py` 里 `register`，和 09 的 `read_file` / `write_file` 一样；只写文件不注册，`registry.schemas()` 里不会出现它。

> **说明：** `shell=True` 会把整串命令交给系统 shell，能力完整，风险也完整。教学演示可以；接到真实用户输入时要另做白名单或确认步骤，这篇不展开。

## 系统提示词注入操作系统

06 的 Environment 只有工作目录和是否 git 仓库。模型写相对路径、判断能不能用 git 够用；现在多了 `bash_command`，同一条「列出当前目录」在 Windows 是 `dir`，在 Unix 是 `ls`。操作系统不写进提示词，模型只能猜。

`agent/prompt/system.j2` 的 Environment 段补一行 `{{ os }}`（其余静态段落与 06 相同，不必再贴）：

```text
# Environment

You have been invoked in the following environment:
 - Primary working directory:
   {{ cwd }}
 - Operating system: {{ os }}
 - Is a git repository: {{ is_git }}
```

模板多一个占位符，`render_prompt` 必须把值传进去，否则渲染出来是空的。06 的 `prompt.py` 再注入一项即可：

```python
return template.render(
  language=get_language(),
  cwd=get_cwd(),
  is_git=get_is_git(),
  os=platform.system(),
)
```

`platform.system()` 得到 `"Windows"` / `"Linux"` / `"Darwin"`，和上面 `bash_command` 用的 `sys.platform == "win32"` 是同一件事的两种写法：提示词给人（模型）看完整名字，执行时用平台判断选哪个 shell。

> **说明：** 06 要求系统提示词「保持静态」。操作系统、cwd、是否 git 是会话开始时采集的环境快照，不是每轮都变的用户身份或当前时间；换机器会变，同一次进程里通常不变。动态内容仍然不要写进模板。

## Session 自动注入工具和提示词

09 的完整测试流程里，每次新建会话都要写两行样板：

```python
session = Session()
session.add_message({"role": "system", "content": render_prompt("system")})
session.tools = registry.schemas()
```

漏写 system，模型没有角色和环境；漏写 tools，请求里没有函数可调，ReAct 循环第一步就会空转。这两件事对「能跑的 Agent 会话」是默认配置，不是某次实验的特例，适合收进构造函数。

相对 08 / 09 的 `Session`：

| 08 / 09                           | 现在                                                                      | 为什么                                                        |
| --------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 调用方自己 `add_message(system)`  | 构造时若未传入 `system_prompt`，就 `render_prompt("system")` 并写入第一条 | 07 起 system 就固定在最前；漏写等于没有 Agent 身份            |
| `self.tools = tools`（默认 `[]`） | `self.tools = tools or registry.schemas()`                                | 09 已说明 `load` 之后必须重新绑 tools；新建时同样不该是空列表 |
| 构造只收 `tools`                  | 增加可选 `system_prompt`                                                  | 要换提示词时仍能覆盖默认模板                                  |

`agent/session.py`：

```python
import json
import uuid
from pathlib import Path

from connect_model_demo.agent.prompt import render_prompt
from connect_model_demo.agent.tool import registry

class Session:
  def __init__(self, *, system_prompt="", tools=[]):
    self.id = str(uuid.uuid4())
    self.messages: list[dict] = []
    if not system_prompt:
      system_prompt = render_prompt("system")
    self.add_message({"role": "system", "content": system_prompt})
    self.tools = tools or registry.schemas()

  def add_message(self, message: dict):
    self.messages.append(message)

  def __str__(self) -> str:
    data = {"id": self.id, "messages": self.messages, "tools": self.tools}
    return json.dumps(data, ensure_ascii=False, indent=2)

  def print(self):
    print(self)

  def save(self):
    sessions_dir = Path(__file__).parent / "sessions"
    sessions_dir.mkdir(parents=True, exist_ok=True)

    data = {
      "id": self.id,
      "messages": self.messages,
    }

    path = sessions_dir / f"{self.id}.json"
    with open(path, "w", encoding="utf-8") as f:
      json.dump(data, f, ensure_ascii=False, indent=2)

  @classmethod
  def load(cls, session_id: str):
    path = Path(__file__).parent / "sessions" / f"{session_id}.json"
    with open(path, encoding="utf-8") as f:
      data = json.load(f)

    session = cls()
    session.id = data["id"]
    session.messages = data["messages"]
    return session
```

`save` 仍只写 `id` + `messages`，与 08 相同：`tools` 是当次请求参数，不进历史。`load` 里 `cls()` 会先按默认注入 system 和 tools，随后 `messages` 被文件内容覆盖——system 以落盘为准（历史不可改）；tools 则借这次构造重新绑上注册表。09 要求「`load` 之后要重新 `session.tools = registry.schemas()`」，这里顺手做掉了。

`system_prompt` 和 `tools` 都做成可覆盖：传入自定义提示词或子集工具时，不要走默认。空字符串 / 空列表视为「用默认」。

> **说明：** `load` 时 `cls()` 会渲染一次 system 再立刻被覆盖，多一次磁盘读取，不影响正确性。若要避开，需要给构造函数加「不注入」的分支，这篇不拆。

## 打印精简

08 的 `ModelPrinterListener` 把思考 token 逐字打出，工具结束时把整份 `tool_calls` 打成 JSON。单次调用能看清分片；ReAct 一轮里思考 + 多次 `read_file`，十几轮下来终端全是 JSON 和思维链。

改动两处，事件订阅方式不变：

| 08                                                                | 现在                                       | 为什么                                   |
| ----------------------------------------------------------------- | ------------------------------------------ | ---------------------------------------- |
| `REASONING_START` 打「思考：」，随后把每个 reasoning 分片打到终端 | 只打「思考中...」，reasoning 分片注释掉    | 循环要看的是决策节奏，不是每一句思维链   |
| `TOOL_CALL_START` 打「工具调用：」，`END` 时 `json.dumps` 整段    | 去掉 START；END 时只打每个 `function.name` | 参数可能是整篇文件内容，打出来比正文还长 |
| 思考用青色、正文绿色                                              | 正文仍绿色；工具名改青色                   | 工具名变成唯一需要强调的短信息           |

`agent/printer.py`：

```python
import sys

from connect_model_demo.agent.events import Event
from connect_model_demo.agent.model import Model

class ModelPrinterListener:
  def __init__(self, model: Model) -> None:
    self.model = model
    self.listening = True
    events = [v for k, v in Event.__dict__.items() if not k.startswith("__")]
    for e in events:
      model.on(event=e, callback=self._model_print_callback)

  def _model_print_callback(self, e: str, **args):
    if not self.listening:
      return
    if e == Event.REASONING_START:
      print("思考中...")
    elif e == Event.REASONING_END:
      print()
    elif e == Event.CONTENT_START:
      print()
      print("内容：")
    elif e == Event.TOOL_CALL_END:
      tool_calls = args["value"]["tool_calls"]
      for call in tool_calls:
        print(f"\033[36m调用工具：{call["function"]["name"]}\033[0m")
    # elif e == Event.REASONING:
    #     print(f"\033[36m{args["chunk_value"]}\033[0m", end="")
    elif e == "content":
      print(f"\033[32m{args["chunk_value"]}\033[0m", end="")
    sys.stdout.flush()
```

被注释的 `Event.REASONING` 就是 08 那条逐字打印。要对照思维链时把注释打开即可，不必改订阅。

## ReAct 循环

前面的三截对应到代码就是：调模型（Thought / Action）→ `registry.invoke`（Observation）→ 追回后再调。09 把这半圈摊成多个 `# %%` cell，人眼确认每一步；Agent 不能每轮停下来等人按 Run Cell。用 `while True` 包住，就是论文里那张循环图的实现：

```python
def query(q: str, session: Session, model: Model):
  "根据用户提问进行处理"
  session.add_message({"role": "user", "content": q})
  # ReAct Loop
  while True:
    model.invoke_stream(session)
    call_msg = registry.invoke(session.messages[-1])
    if call_msg is None:
      break
    else:
      session.messages += call_msg
```

| 行                                      | 对应 09                             | 在循环里的角色                       |
| --------------------------------------- | ----------------------------------- | ------------------------------------ |
| `add_message(user)`                     | 发一条用户请求                      | 只在进循环前做一次                   |
| `invoke_stream(session)`                | 调模型，assistant 已由 `Model` 回写 | Thought；若有工具则同时带上 Action   |
| `registry.invoke(session.messages[-1])` | 从最后一条消息执行 `tool_calls`     | Observation；`None` 表示本轮没有工具 |
| `None` → `break`                        | 09 的 `if call_msg:` 为假就不要再调 | 模型已给出最终回复                   |
| `session.messages += call_msg`          | 09 的追回                           | 下一轮请求能看见工具结果             |

`invoke_stream` 仍走 08 的回写：本轮 assistant（含 `tool_calls`）已经在 `session.messages` 末尾。`invoke` 读的就是这条。追回的是 `role: tool` 列表，不是覆盖 assistant。

没有迭代上限。工具一直被调用就会一直转，演示可以，接到开放输入时要加最大步数。
