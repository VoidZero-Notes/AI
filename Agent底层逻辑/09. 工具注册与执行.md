08 已经走完 Tool Calling 的完整流水线：定义函数 → 手写 JSON Schema → 赋给 `session.tools` → 调模型 → 从返回里拆 `tool_calls`，用 `globals().get` 找到函数并执行。

这条链路能跑，但每一步都摊在 `main.py` 里。schema 和函数签名各写一份，容易漂；工具一多，`session.tools` 会变成两坨几乎相同的大 dict；执行还绑定在「函数恰好定义在当前模块」。08 文末也写了：执行完要把 `role: tool` 的结果追回会话再调一次模型——那一步当时只留了说明，没有收成可复用的接口。

09 要封装的就是这条流水线里「调用方重复在做」的部分。模型决定调不调、参数填什么，仍然原样；变的是 schema 怎么来、工具怎么注册、调用意图怎么落到真实函数、结果怎么写回上下文。

| 08 手工 | 09 封装 | 为什么 |
| --- | --- | --- |
| 手写一整份 `tools` JSON | 从函数签名 + 参数描述生成 schema | schema 很长，且必须和真实函数一致，手写容易漏参数、写错类型 |
| `session.tools = [大段 dict, ...]` | `session.tools = registry.schemas()` | 增删工具时只改注册表，不在调用处维护两份列表 |
| `globals().get(name)` 再 `func(**args)` | `registry.invoke(message)` | 08 自己也写了：`globals()` 只在同模块找得到；而且只执行了 `tool_calls[0]` |
| 执行完停在 `finish_reason: tool_calls` | `invoke` 返回 `role: tool` 消息，追回 `session` 再调模型 | 08 文末说明里要求的回写，这里收成返回值 |
| `arguments` 当合法 JSON 直接 `loads` 后调用 | 先经 Pydantic 模型校验再调用 | 08 写过：服务商不保证 `arguments` 一定合法 |

落地后的模块划分：

```text
agent/tool/
 ├── __init__.py        调度中心 registry：schemas() / invoke()
 ├── read_file.py       @tool 包装的读文件
 ├── write_file.py      @tool 包装的写文件
 └── core/
      ├── __init__.py   导出 Tool、tool
      ├── tool.py       Tool 类 + @tool 装饰器
      └── utils.py      从函数签名动态建 Pydantic 模型
```

`read_file` / `write_file` 的函数体与 08 相同，不再靠手写 schema 声明它们。

## Pydantic 再认识

封装的第一块依赖是 Pydantic：用模型校验入参，并用同一份模型吐出 JSON Schema。后面的 `create_params_model`、`Tool.schema()` 都建立在这两点上。

```bash
uv add pydantic==2.13.4
```

```python
import json

from pydantic import BaseModel, Field

class Counter(BaseModel):
  n: int = Field(description="计数值", default=0)

# 自动填默认值
Counter()  # Counter(n=0)

# 能转换则转换
Counter(n="123")  # Counter(n=123)

# 无法转换则报 ValidationError
# Counter(n=[1, 2, 3])

# 转成字典
Counter().model_dump()  # {'n': 0}

schema = Counter.model_json_schema()
print(json.dumps(schema, indent=2, ensure_ascii=False))
```

输出示例：

```json
{
  "properties": {
    "n": {
      "default": 0,
      "description": "计数值",
      "title": "N",
      "type": "integer"
    }
  },
  "title": "Counter",
  "type": "object"
}
```

对后面生成工具 schema 有用的三点：

| 能力 | 这里看到的 | 后面用在哪 |
| --- | --- | --- |
| 默认值 | `n` 有 `default=0`，不进 `required` | 函数参数有默认值 → 可选；无默认值 → 必填 |
| 校验 / 转换 | `"123"` 变成 `123`；列表则 `ValidationError` | 模型填的 `arguments` 先过模型，再进真实函数 |
| `model_json_schema()` | 得到 JSON Schema | 再裁成 08 那种 `type: function` 的 tools 形状 |

> **说明：** 字段带默认值时，schema 里**不会**出现在 `required` 中。后面 `create_params_model` 按「有没有默认值」分支，依据就是这件事。

### 动态创建模型

Pydantic 的 `create_model` 可以在运行时按字段定义组一个模型，不必先写 `class`。下面等价于手写一个只有 `filepath` / `content` 的模型：

      "description": "文件的绝对路径或相对于cwd的路径",

### 实现 `create_params_model`

用 `inspect.signature` 遍历参数：注解当类型（没有则 `Any`），描述从传入的 dict 取，有没有默认值决定 `Field` 要不要带 `default`。

```python
import inspect
from typing import Any

from pydantic import Field, create_model

def create_params_model(func, param_descriptions={}):
  model_name = f"{func.__name__}_params"
  args = {}
  sig = inspect.signature(func)
  for pname, param in sig.parameters.items():
    py_type = (
      param.annotation if param.annotation is not param.empty else Any
    )
    desc = param_descriptions.get(pname, "")

    if param.default is param.empty:
      # 必填参数：不设默认值
      args[pname] = (py_type, Field(description=desc))
    else:
      # 可选参数：设置默认值
      args[pname] = (
        py_type,
        Field(default=param.default, description=desc),
      )

  return create_model(model_name, **args)

param_model = create_params_model(write_file, param_descriptions={
  "filepath": "文件的绝对路径或相对于cwd的路径",
  "content": "待写入的文件内容"
})
# write_file_param_model = param_model(filepath="./uv.md")  # 校验参数
schema = param_model.model_json_schema()
print(json.dumps(schema, indent=2, ensure_ascii=False))
```

输出与上面 `create_model` 手写字段一致。描述无法从类型注解里读出来，所以仍要单独传 `param_descriptions`；后面装饰器就是为了把这份 dict 写到函数旁边。

放到 `agent/tool/core/utils.py`：

## Tool 类

有了参数模型，还差把「函数 + 描述 + schema」收成一个对象。期望 `Tool` 能做三件事：

```python
# 1. 包装一个函数，并指定每个参数的描述
tool = Tool(
  read_file,
  param_descriptions={"filepath": "文件路径"}
)

# 2. 用关键字参数调用，行为与原函数一致（先校验再执行）
tool(filepath="./uv.md")

# 3. 拿到 08 那种可直接塞进 session.tools 的 schema
tool.schema()
```

`name` 用 `func.__name__`，`description` 用函数 docstring。08 手写 schema 里的 `function.name` / `function.description` 对应这两处；docstring 在 08 里写了但没进 schema，这里自动接上。

### 实现 `tool.py`

```python
import inspect
import traceback
from typing import Any, Callable

from agent.tool.core.utils import create_params_model

class Tool:
  def __init__(
    self,
    func: Callable,
    param_descriptions: dict = {},
  ):
    self.func = func
    self.name = func.__name__
    self.description = inspect.getdoc(func) or ""
    self.param_descriptions = param_descriptions or {}
    self.param_model = create_params_model(func, param_descriptions)

  def schema(self) -> dict:
    param_schema = self.param_model.model_json_schema()
    return {
      "type": "function",
      "function": {
        "name": self.name,
        "description": self.description,
        "parameters": {
          "type": "object",
          "properties": {
            name: {
              "type": prop.get("type", "string"),
              "description": prop.get("description", ""),
            }
            for name, prop in param_schema.get("properties", {}).items()
          },
          "required": param_schema.get("required", []),
        },
      },
    }

  def __call__(self, **kwargs) -> Any:
    result = ""
    try:
      # 验证参数
      validated = self.param_model(**kwargs)
      result = str(self.func(**validated.model_dump()))  # 将结果转换为字符串
    except Exception as e:
      # 完整堆栈字符串
      result = "".join(traceback.format_exception(type(e), e, e.__traceback__))

    return result
```

`schema()` 没有把 Pydantic 的 JSON Schema 原样塞进 `parameters`。08 发给模型的形状只有 `type`、`description`、`required`；Pydantic 还会带 `title`、`default` 等字段，这里按 08 的 tools 结构裁过一遍。

`__call__` 相对 08 的 `func(**arguments)` 多两步：先 `param_model(**kwargs)` 校验，再把返回值 `str(...)`。工具消息的 `content` 必须是字符串；`write_file` 返回 `None` 时这里会变成 `"None"`。异常不往外抛，而是把堆栈写成字符串返回——后面要把这段作为 `role: tool` 回传，模型才能看到失败原因，而不是整个 Agent 进程被打断。

## 装饰器

构造 `Tool(...)` 时，参数描述和函数定义是分开的。工具一多，描述会散落在调用处。希望描述就写在函数旁边：

```python
@tool(filepath="文件的绝对路径或相对于cwd的路径", content="待写入的文件内容")
def write_file(filepath: str, content: str) -> None:
  """将内容写入文件"""
  with open(filepath, "w", encoding="utf-8") as f:
    f.write(content)
```

装饰器本身很薄：把关键字参数当成 `param_descriptions`，返回 `Tool` 实例。装饰之后，这个名字就不再是普通函数，而是 `Tool`——所以后面 `registry.register(read_file)` 注册的是工具对象。

补到 `agent/tool/core/tool.py` 末尾：

```python
def tool(**args):
  """装饰器：将普通函数包装为 Tool 对象"""

  def decorator(func):
    return Tool(func, param_descriptions=args)

  return decorator
```

`agent/tool/core/__init__.py`：

```python
from agent.tool.core.tool import Tool, tool
```

08 把两个函数写在 `main.py`；这里放到独立模块，函数体不变，只加装饰器。

`agent/tool/read_file.py`：

## 工具调度中心

现在可以定义工具了，但离 08 的调用处还有两段空档：

| 空档 | 08 怎么填 | 09 谁填 |
| --- | --- | --- |
| 工具 → `session.tools` | 在 `main.py` 里手写 schema 列表 | `registry.schemas()` |
| 模型消息 → 真正执行 | 自己拆 `tool_calls`、`json.loads`、`globals().get` | `registry.invoke(message)` |

调度中心就是补上这两段。期望的用法：

```python
session.tools = registry.schemas()
resp = model.invoke(session)
result = registry.invoke(session.messages[-1])
result  # 工具调用结果；None 表示这一轮没有 tool_calls
```

`agent/tool/__init__.py`：

```python
import json

from agent.tool.core import Tool
from agent.tool.read_file import read_file
from agent.tool.write_file import write_file

class _ToolRegistry:
  _tools: dict[str, Tool] = {}

  def register(self, tool: Tool):
    """注册一个工具"""
    self._tools[tool.name] = tool

  def schemas(self) -> list[dict]:
    """返回所有工具的 Schema 列表，可直接赋值给 session.tools"""
    return [t.schema() for t in self._tools.values()]

  def invoke(self, message: dict) -> list[dict] | None:
    """从模型返回的消息中提取 tool_calls 并逐一执行"""
    tool_calls = message.get("tool_calls", [])
    if not tool_calls:
      return None
    results = []
    for tc in message.get("tool_calls", []):
      tool_id = tc["id"]
      name = tc["function"]["name"]
      args = json.loads(tc["function"]["arguments"])
      tool = self._tools.get(name)
      if not tool:
        result = "无此工具，请仔细检查你传递的工具名称是否正确"
      else:
        result = tool(**args)
      results.append(
        {
          "role": "tool",
          "tool_call_id": tool_id,
          "name": name,
          "content": result,
        }
      )
    return results

registry = _ToolRegistry()
registry.register(read_file)
registry.register(write_file)
```

和 08 末尾那三段 cell 的对应关系：

- 08 只取 `msg["tool_calls"][0]`；这里按列表逐条执行，一次回复里多个调用也能处理
- 08 用 `globals().get(tool_name)`；这里按 `name` 查注册表，函数不必和 `main.py` 同模块
- 08 调用成功后本地出现 `uv.md`，但会话里没有工具结果；这里每条都收成 `role: tool` + `tool_call_id`，正好接 08 文末那句「追回 session 再调一次模型」
- 查不到工具时不抛异常，把错误写成 `content`，让模型有机会改名字再调

`from agent.tool import registry` 时就会把 `read_file` / `write_file` 注册上，调用处不用再 `register`。

> **说明：** `save` / `load` 仍然不读写 `tools`（08 已说明）。`load` 之后要重新 `session.tools = registry.schemas()`，否则下一轮请求没有工具。

## 完整测试流程

对照 08 的同一条用户请求：「请在当前目录新建一个 `uv.md`」。08 是手绑 schema + 手工执行；这里只操作 `registry` 和 `session`。用 `# %%` 分段，用法见 07。
