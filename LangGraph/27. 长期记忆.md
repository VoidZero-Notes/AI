长期记忆是把跨会话仍有价值的用户信息从对话中提取出来，写入不依附某一 Thread 的存储，并在新会话启动时注入模型上下文。本篇覆盖四件事：运行前检查 Store 与 `user_id`、首次运行时把管理员提示词与已有记忆渲染成系统提示词快照、模型节点改读这份快照、以及供模型调用的长期记忆写入工具。直接编译图与经 Agent Server SDK 调用，走同一套写入、跨 Thread 读取和用户隔离流程。

第24章只讲 Store 的读写 API，不把 Store 接到图节点上。本篇在编译时注入 Store，节点经 `Runtime` 读写。第07章的 Checkpointer 仍只保存某一 `thread` 的图状态；长期记忆不进检查点，进 Store。`user_id` 放在 Thread 的 `metadata` 里，作为 Store 命名空间，使同一用户的多条线程共享记忆、不同用户彼此隔离。

Agent底层逻辑第07章把「外部记忆」与 Session 并列：用户偏好、长期事实写入数据库或向量库，需要时检索再注入当前 `messages`。LangGraph 的落地分成两层：第24章的 Store 对应那份外部存储；本篇对应「检索再注入」——启动 Thread 时从 Store 读出，写入系统提示词；运行中由工具写回 Store。第12章的 `Runtime` 是节点读取 Store 的容器；第05章的 Agent Server 在服务端注入 Store，不必在图代码里自行配置。

文档：[Add memory](https://docs.langchain.com/oss/python/langgraph/add-memory) · [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) · [Stores](https://docs.langchain.com/oss/python/langgraph/stores)

| 概念               | 作用                                                                              |
| ------------------ | --------------------------------------------------------------------------------- |
| Store              | 跨线程长期键值存储（第24章）。不进图状态，不随某条 thread 的检查点走              |
| Checkpointer       | 某一 thread 的图状态快照（第07章）                                                |
| `user_id`          | Thread `metadata` 中的用户标识，用作 Store 命名空间                               |
| `system_prompt`    | 图状态字段。线程首次运行时写入，后续运行复用，不随 Store 更新                     |
| `check`            | 运行前校验 `runtime.store` 与 `metadata.user_id`                                  |
| `save_long_term_memory` | 按 `user_id` 覆盖写入 Store 的工具。命名空间 `("users", user_id)`，键为 `"memory"` |

一次 Run 的数据流如下。`user_id` 随 Thread 进入图；检查通过后，提示词节点生成快照；模型按快照调用，必要时经工具把新记忆写入 Store。

## 图上的四处改动

相对此前已有的 ReAct 图（`model ⇄ tools`）：

1. **检查节点 `check`**：确认 `runtime.store` 存在，且 Thread `metadata` 含 `user_id`。缺一则直接失败，避免后续节点在无存储或无用户身份时读写记忆。
2. **提示词节点**：向图状态写入 `system_prompt`。仅在该字段尚不存在时构建完整系统提示词（管理员指令 + Store 中的长期记忆），之后同一 Thread 上的运行一律复用这份快照。
3. **模型节点**：系统提示词改从图状态读取，不再从第12章的 `Context.system_prompt` 直接送给模型。Context 里的 `system_prompt` 只作为管理员指令，交给提示词节点去渲染。
4. **长期记忆工具**：模型在用户明确要求记住、或信息对未来会话持续有用时调用；按 `user_id` 写入 Store，整份覆盖旧值。

拓扑：

```text
START → check_user_id → initialize_system_prompt → model ⇄ tools → END
```

快照冻结是本篇的关键约束：长期记忆是在**当次 Run 期间**才写入 Store 的，当前 Thread 已经冻结的系统提示词里不会出现这条新记忆。同一 `user_id` 再开一条 Thread，提示词节点会重新渲染，此时才能读到最新 Store。

### 图状态

`langgraph_project/states/core_agent_state.py`：在原有 `messages` 与 `ContextSchema` 之外，给 `CoreAgentState` 增加 `system_prompt`。该字段保存线程首次运行时渲染好的系统提示词快照，随后由检查点随 Thread 持久化。

```python
from typing import Annotated, Any, NotRequired, Required, TypedDict
from langchain_core.messages import BaseMessage
from langgraph.graph.message import add_messages
from pydantic import BaseModel, Field

class ContextSchema(BaseModel):
  """上下文 Schema"""

  # 模型可配置字段
  model: str | None = Field(description="模型", default=None)
  temperature: float | None = Field(description="温度", default=None)
  top_p: float | None = Field(description="核采样概率", default=None)
  thinking: dict[str, Any] | None = Field(description="思考配置", default=None)

  # 提示词与工具配置
  system_prompt: str | None = Field(description="系统提示词", default=None)
  tools: list[str] | None = Field(description="工具列表", default=None)

class CoreAgentState(TypedDict):
  """核心 Agent 图状态"""

  # 消息列表，使用 add_messages reducer 自动累积
  messages: Required[Annotated[list[BaseMessage], add_messages]]

  # 线程首次运行时生成，后续运行始终复用同一份快照
  system_prompt: NotRequired[str]
```

### 检查节点

`langgraph_project/nodes/check.py`：运行前校验两件事——`Runtime` 里是否有 Store，Thread `metadata` 里是否有 `user_id`。缺一则抛错，避免后续节点在无存储或无用户身份时读写记忆。

```python
from langgraph.config import get_config
from langgraph.runtime import get_runtime

from langgraph_project.states.core_agent_state import CoreAgentState

def _check_user_id():
  "检查是否有 user_id"
  config = get_config()
  metadata = config.get("metadata") or {}
  if "user_id" not in metadata or metadata["user_id"] is None:
    raise ValueError("Thread metadata 中缺少 user_id")

def _check_store():
  "检查是否有 store"
  runtime = get_runtime()
  if runtime.store is None:
    raise RuntimeError("长期记忆功能必须在提供 Store 的 Agent Server 中运行")

def check(state: CoreAgentState) -> dict:
  """检查图运行的必要信息"""
  _check_store()
  _check_user_id()
  return {}
```

### 提示词节点

`langgraph_project/nodes/initialize_system_prompt.py`：仅在 `state["system_prompt"]` 尚不存在时渲染完整系统提示词。管理员指令来自 `runtime.context.system_prompt`；长期记忆来自 `runtime.store.aget(("users", user_id), key="memory")` 的 `value["content"]`。渲染结果写入图状态后，同一 Thread 后续 Run 直接跳过本节点，快照随第07章检查点保存，不再重读 Store。

````python
from langgraph.config import get_config
from langgraph.runtime import Runtime

from langgraph_project.states.core_agent_state import ContextSchema, CoreAgentState
from langchain_core.utils.mustache import render

SYSTEM_PROMPT_TEMPLATE = """
# 管理员指令

以下内容来自管理员注入的提示词

```text
{{assistant_system_prompt}}
```

# 用户长期记忆

长期记忆用于保存跨会话仍然有价值的用户信息，例如用户明确要求记住的事情、稳定的偏好和持续有用的背景信息。

在处理长期记忆时，请遵守以下规则：

- 当用户明确要求你记住某件事时，调用长期记忆工具保存它。
- 当信息是稳定的用户偏好、身份背景或未来会话可能反复用到的信息时，可以调用长期记忆工具保存它。
- 不要保存只对当前任务有用的临时信息，也不要保存根据对话推测出的不确定信息。
- 每个用户只保存一条键名为 `memory` 的长期记忆数据。保存新内容会完全覆盖旧内容；如果需要追加信息，请先将新旧内容合并后再保存。
- 你无须关心用户id，系统会自行追踪不同身份的用户

以下内容是当前用户的长期记忆：

```
{{long_term_memory}}
```

"""

async def initialize_system_prompt(
  state: CoreAgentState,
  runtime: Runtime[ContextSchema],
) -> dict:
  """首次运行时生成系统提示词快照，后续运行保持不变。"""
  if state.get("system_prompt") is not None:
    return {}

  assistant_system_prompt = ""  # assistant中的系统提示词
  long_term_memory = ""  # 长期记忆
  # 处理系统提示词
  if runtime.context and runtime.context.system_prompt:
    assistant_system_prompt = runtime.context.system_prompt

  # 处理长期记忆
  if runtime.store is not None:
    metadata = get_config().get("metadata") or {}
    user_id = str(metadata["user_id"])
    memory = await runtime.store.aget(("users", user_id), key="memory")
    if memory:
      long_term_memory = memory.value.get("content", "")

  system_prompt = render(
    SYSTEM_PROMPT_TEMPLATE,
    {
      "assistant_system_prompt": assistant_system_prompt,
      "long_term_memory": long_term_memory,
    },
  )
  return {"system_prompt": system_prompt}
````

### 模型节点

`langgraph_project/nodes/call_model.py`：相对第12章，`_get_system_prompts` 改为从 `state["system_prompt"]` 读取首次运行冻结的快照，不再从 `Context.system_prompt` 直接送给模型。Context 仍负责模型、工具清单，以及把模型配置转成 `configurable`。

```python
from langchain_core.messages import SystemMessage
from langchain_core.runnables import RunnableConfig
from langchain_core.tools import BaseTool
from langgraph.runtime import get_runtime
from langgraph_project.core.create_model import create_model
from langgraph_project.core.mock_model import mock_model
from langgraph_project.states.core_agent_state import ContextSchema, CoreAgentState
from langgraph_project.tools import get_tools, tools

# create_model 中声明的可配置模型字段，Context 中的同名字段需要转给模型的调用配置
_MODEL_CONFIG_FIELDS = ("model", "temperature", "top_p", "thinking")

def _get_context() -> ContextSchema:
  return get_runtime(ContextSchema).context

def _get_system_prompts(state: CoreAgentState) -> list[SystemMessage]:
  "根据 Thread 状态获取首次运行时生成的系统提示词快照"
  system_prompt = state.get("system_prompt")
  if not system_prompt:
    return []
  return [SystemMessage(system_prompt)]

def _get_model(context: ContextSchema):
  "根据 Context 获取模型对象"
  if context and context.model == "fake":
    return mock_model()
  return create_model()

def _get_tools(context: ContextSchema) -> list[BaseTool]:
  "根据 Context 获取工具列表，未配置时返回全部工具"
  if context and context.tools:
    return get_tools(context.tools)
  return tools

def _get_model_config(context: ContextSchema) -> RunnableConfig:
  "模型 invoke 只读 config.configurable，不读 Context，需手动把模型配置转成调用配置"
  if not context:
    return {}
  configurable = {
    name: getattr(context, name)
    for name in _MODEL_CONFIG_FIELDS
    if getattr(context, name) is not None
  }
  return {"configurable": configurable}

async def call_model(state: CoreAgentState) -> dict:
  """调用模型节点"""
  context = _get_context()
  messages = state["messages"]

  # 根据 Context 获取模型对象
  model = _get_model(context)
  # 根据 Context 读取系统提示词
  system_prompts = _get_system_prompts(state)
  # 根据 Context 获取工具列表
  active_tools = _get_tools(context)
  model_with_tools = model.bind_tools(active_tools)

  # 调用模型
  response = await model_with_tools.ainvoke(
    [*system_prompts, *messages],
    config=_get_model_config(context),
  )
  return {"messages": [response]}
```

### 图拓扑

`langgraph_project/graphs/core_agent_graph.py`：在既有 `model ⇄ tools` 之前插入 `check_user_id` 与 `initialize_system_prompt`。条件边、`ToolNode`、容错沿用既有实现。

```python
from langgraph.graph import END, START, StateGraph
from langgraph_project.nodes.check import check
from langgraph_project.nodes.call_model import call_model
from langgraph_project.nodes.initialize_system_prompt import initialize_system_prompt
from langgraph_project.states.core_agent_state import CoreAgentState, ContextSchema
from langgraph.prebuilt import ToolNode
from langgraph_project.tools import tools
from langgraph.types import RetryPolicy, Send, TimeoutPolicy
from langgraph.errors import NodeError
from langgraph.types import Command
from langchain.messages import AIMessage

def should_continue(state: CoreAgentState) -> str | list[Send]:
  """为每个 tool call 动态创建一个 tools 节点调用。"""
  last_message = state["messages"][-1]
  if not isinstance(last_message, AIMessage) or not last_message.tool_calls:
    return END

  return [Send("tools", [tool_call]) for tool_call in last_message.tool_calls]

def error_handler(state: CoreAgentState, error: NodeError):
  msg = f"{error.node}节点发生了错误：{error.error}"
  return Command(update={"messages": [AIMessage(msg)]}, goto=END)

def build_graph():
  """生成核心 Agent 图（未编译）"""
  workflow = StateGraph(CoreAgentState, context_schema=ContextSchema)

  # 容错机制
  workflow.set_node_defaults(
    # retry_policy=RetryPolicy(max_attempts=3),
    # timeout=TimeoutPolicy(run_timeout=3, idle_timeout=1),
    error_handler=error_handler  # type: ignore
  )

  workflow.add_node("check_user_id", check)
  workflow.add_node("initialize_system_prompt", initialize_system_prompt)
  workflow.add_node("model", call_model)
  workflow.add_node("tools", ToolNode(tools))

  workflow.add_edge(START, "check_user_id")
  workflow.add_edge("check_user_id", "initialize_system_prompt")
  workflow.add_edge("initialize_system_prompt", "model")
  workflow.add_conditional_edges("model", should_continue, ["tools", END])
  workflow.add_edge("tools", "model")
  return workflow
```

### 长期记忆工具

`langgraph_project/tools/long_term_memory.py`：供模型调用的写入工具。从 `runtime.config.metadata["user_id"]` 取用户，向 Store 的 `("users", user_id)` / `"memory"` 做 `aput`。与第24章相同：`aput` 整体替换 `value`，不会合并新旧字典；追加须由模型先合并再写入。每个用户只保留这一条。

```python
from langchain.tools import ToolRuntime, tool

from langgraph_project.states.core_agent_state import ContextSchema, CoreAgentState

@tool
async def save_long_term_memory(
  memory: str,
  runtime: ToolRuntime[ContextSchema, CoreAgentState],
) -> str:
  """
  保存当前用户的一条长期记忆。

  当用户明确要求记住某件事，或者某项稳定信息对未来会话持续有用时使用。

  此操作会完全覆盖之前的记忆，如果要追加，请和之前的记忆合并后保存。
  """
  if runtime.store is None:
    raise RuntimeError("长期记忆工具必须在提供 Store 的 Agent Server 中运行")

  metadata = runtime.config.get("metadata") or {}
  if "user_id" not in metadata or metadata["user_id"] is None:
    raise ValueError("Thread metadata 中缺少 user_id")

  user_id = str(metadata["user_id"])
  await runtime.store.aput(
    ("users", user_id),
    key="memory",
    value={"content": memory},
  )
  return f"长期记忆已保存"
```

````
# 用户长期记忆

长期记忆用于保存跨会话仍然有价值的用户信息，例如用户明确要求记住的事情、稳定的偏好和持续有用的背景信息。

在处理长期记忆时，请遵守以下规则：
- 当用户明确要求你记住某件事时，调用长期记忆工具保存它。
- 当信息是稳定的用户偏好、身份背景或未来会话可能反复用到的信息时，可以调用长期记忆工具保存它。
- 不要保存只对当前任务有用的临时信息，也不要保存根据对话推测出的不确定信息。
- 每个用户只保存一条键名为 `memory` 的长期记忆数据。保存新内容会完全覆盖旧内容；如果需要追加信息，请先将新旧内容合并后再保存。
- 你无须关心用户id，系统会自行追踪不同身份的用户
````

````text
```
我最喜欢的电影是《宇宙探索编辑部》
```
````

### 用户记忆隔离

换一个 `user_id` 即另一命名空间，读不到 `001` 的记忆：

```python
# %%
other_user_config: RunnableConfig = {
  "configurable": {"thread_id": "long-term-memory-thread-003"},
  "metadata": {"user_id": "002"},
}

result = await graph.ainvoke(  # type: ignore
  input={"messages": [HumanMessage("我最喜欢的电影是什么")]},
  config=other_user_config,
  context=context,
)
other_user_state = await graph.aget_state(other_user_config)  # type: ignore
print(other_user_state.values["system_prompt"])
result["messages"][-1].content
```

`002` 的快照里长期记忆区块为空。模型回复如下：

```text
'我目前没有关于您最喜欢电影的长期记忆记录。\n\n为了以后能更好地为您提供个性化推荐或回答相关问题，您愿意告诉我您最喜欢的电影是什么吗？或者如果您希望我帮您搜索某部电影的信息，也可以告诉我电影名称。'
```

## Agent Server API

经 LangGraph SDK 调用 Agent Server，重复验证同一套长期记忆流程。调用前须已按第05章启动本地服务（`uv run langgraph dev`），并按第13章安装 SDK。服务会注入 Store，图代码里不要再自行 `compile(store=...)`（第05章、第24章）。

本地 OpenAPI：`http://localhost:2024/docs#tag/store` · `http://localhost:2024/docs#tag/thread-runs`

`assistant_id` 使用 Studio 中该图对应的 Assistant UUID；也可传 `"agent"` 使用默认 Assistant（第13章、第15章）。

```python
# %%
from langgraph_sdk import get_client

client = get_client(url="http://localhost:2024")
assistant_id = "46bf8031-082b-4d1d-a8df-9687787d9d40"
server_user_id = "003"
```

> **说明：** 多次执行时，可先 `client.threads.search` 再逐条 `delete`，避免旧线程干扰对照。

### 创建 Thread，并通过 Run 写入长期记忆

> POST /threads · POST /threads/{thread_id}/runs/wait

```python
# %%
server_thread_1 = await client.threads.create(
  metadata={
    "user_id": server_user_id,
    "__name__": "长期记忆测试：写入",
  }
)
server_thread_1_id = server_thread_1["thread_id"]

server_result = await client.runs.wait(
  thread_id=server_thread_1_id,
  assistant_id=assistant_id,
  input={
    "messages": [
      {"role": "user", "content": "请记住：我叫黑土，今年75，属虎"}
    ]
  },
)
server_result["messages"][-1]["content"]  # type: ignore
```

返回如下：

```text
'我已经记住了：您叫黑土，今年75岁，属虎。\n\n请问有什么我可以帮您的吗？'
```

经 Store API 检查工具写入的结果：

> GET /store/items

```python
# %%
server_memory_item = await client.store.get_item(
  ("users", server_user_id),
  key="memory",
)
server_memory_item["value"]
```

返回如下：

```text
{'content': '用户名叫黑土，今年75岁，属虎。'}
```

> **说明：** 进程内 `aget` 返回 `Item` 对象；SDK `get_item` 返回字段相同的字典（第24章）。

### 检查第一个 Thread 的系统提示词快照

> GET /threads/{thread_id}/state

```python
# %%
server_thread_1_state = await client.threads.get_state(server_thread_1_id)
print(server_thread_1_state["values"]["system_prompt"])  # type: ignore
```

与进程内相同：该 Thread 的快照在写入记忆**之前**冻结，长期记忆区块为空。
