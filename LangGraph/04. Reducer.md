LangGraph 把图状态拆成若干通道；每条通道有自己的合并函数，这个函数就是 Reducer：接收当前值与本次更新，返回合并后的新值。未指定时，后一次写入覆盖前一次——第01章已经用到这一默认行为。本篇把合并规则写进类型标注，并引入消息通道专用的 `add_messages`。

Agent底层逻辑第07章用 `Session` 在列表末尾追加消息。图状态里的 `messages` 不能靠覆盖：后一个节点会覆盖整份对话历史。`add_messages` 就是这件事在 LangGraph 里的实现：无相同 `id` 则追加，有相同 `id` 则替换该条。工程部分把第03章的消息、Mustache 模板与第02章的 `create_model` 连接到图节点上，状态里的 `messages` 使用这条 reducer。

文档：[Use the graph API · Process state updates with reducers](https://docs.langchain.com/oss/python/langgraph/use-graph-api)

| 概念            | 作用                                                                       |
| --------------- | -------------------------------------------------------------------------- |
| Reducer         | `(当前值, 本次更新) → 新值`。规定同一通道上多次写入如何合并                |
| 默认覆盖        | 未标注 reducer 时，后写覆盖前写                                            |
| `Annotated`     | 把 reducer 附加到类型上；类型检查仍只看见左边的类型                        |
| `add_messages`  | 消息通道的内置 reducer：无相同 `id` 则追加，有相同 `id` 则按 `id` 替换     |
| `TypedDict`     | 用类语法声明字典的键与值类型，作为图状态 schema                            |
| `Required`      | 该键在 `invoke` 输入里必须出现                                             |
| `NotRequired`   | 该键可缺；与 `total=False` 都表示选填，粒度不同                            |

Reducer 本身与图无关：任何接受两个参数、返回一个同类型结果的函数都可以。LangGraph 只是在每条通道上调用它。

## Reducer 的本质

签名是 `(旧值, 新值) → 合并结果`。合并规则由函数体决定，不由框架决定：

```python
# 通过相加合并（int / list / str 都定义了 +）
def add(a, b):
  return a + b

# 始终使用新数据覆盖旧数据
def overwrite(a, b):
  return b

print(add(1, 2))            # 3
print(add([1, 2], [3, 4]))  # [1, 2, 3, 4]
print(add("a", "b"))        # ab

print(overwrite("旧", "新"))  # 新
```

标准库 `operator.add` 与上面的 `add` 等价，图状态里通常直接用它，不必手写：

```python
import operator

print(operator.add(1, 2))            # 3
print(operator.add([1, 2], [3, 4]))  # [1, 2, 3, 4]
print(operator.add("a", "b"))        # ab
```

LangGraph 要求 reducer 的返回类型与通道类型一致：`list + list` 仍是 `list`，`int + int` 仍是 `int`。节点若向 `list` 通道写入一个 `str`，合并会在运行时报错。

## TypedDict 与状态 schema

图状态在第01章写成 `TypedDict`：用类语法描述「这份字典有哪些键、值是什么类型」。它运行时仍是普通 `dict`，给的是静态检查与 LangGraph 读 schema 用的标注，不会在运行时强制校验缺键。

默认 `total=True`：未额外标记的键都必填。`total=False`：未额外标记的键都选填。需要混用时，用 `Required` / `NotRequired` 覆盖默认：

```python
from typing import NotRequired, Required, TypedDict

class User(TypedDict):
  """默认 total=True：未标记的键必填。"""
  id: str
  name: str
  nickname: NotRequired[str]  # 仅此项选填

u: User = {"id": "1", "name": "张三"}  # 合法
# u = {"id": "1"}  # 类型检查报错：缺 name

class Patch(TypedDict, total=False):
  """total=False：未标记的键一律选填。"""
  name: str
  nickname: str
  id: Required[str]  # 即使 total=False，id 仍必填
```

两种写法可以表达同一份 schema，选一种保持一致即可：

| 目标           | 写法 A（默认必填）        | 写法 B（`total=False`）   |
| -------------- | ------------------------- | ------------------------- |
| 键必填         | `x: T`                    | `x: Required[T]`          |
| 键选填         | `x: NotRequired[T]`       | `x: T`                    |

第01章用的是 `TypedDict, total=False`，全部选填，所以 `graph.invoke({})` 合法。本篇后面的 `CoreAgentState` 采用写法 A：`messages` 必填，其余 `NotRequired`。

`Annotated[T, reducer]` 不改变 `T`：对类型检查器，字段仍是 `T`；LangGraph 读取第二个参数，把它当作这条通道的 reducer。

## 图状态中的 Reducer

第01章：节点返回的是**更新**（若干键），不是整份状态。运行时按通道将更新合并进状态。未标注 reducer 的通道使用默认覆盖；要追加、取最大、按 id 合并，必须显式标注 reducer。

下面三条通道各用一种规则。`covered` 不写 reducer，就是覆盖：

```python
import operator
from typing import Annotated, NotRequired, TypedDict

from langgraph.graph import END, START, StateGraph

class MyState(TypedDict):
  # 覆盖：未标注 reducer，后写覆盖前写
  covered: NotRequired[str]
  # 追加：list + list
  append_list: NotRequired[Annotated[list[str], operator.add]]
  # 自定义：保留较大值
  high_score: NotRequired[Annotated[int, lambda a, b: max(a, b)]]

def node1(state: MyState):
  print("进入node1的状态：", state)
  return {
    "covered": "node1 result",
    "append_list": ["node1 result"],
    "high_score": 5,
  }

def node2(state: MyState):
  print("进入node2的状态：", state)
  return {
    "covered": "node2 result",
    "append_list": ["node2 result"],
    "high_score": 3,
  }

workflow = StateGraph(MyState)
(
  workflow.add_node(node1)
  .add_node(node2)
  .add_edge(START, "node1")
  .add_edge("node1", "node2")
  .add_edge("node2", END)
)

graph = workflow.compile()
response = graph.invoke({})
print(response)
```

打印结果结构如下：

```text
进入node1的状态： {'append_list': [], 'high_score': 0}
进入node2的状态： {
  'covered': 'node1 result',
  'append_list': ['node1 result'],
  'high_score': 5
}
最终：{
  'covered': 'node2 result',
  'append_list': ['node1 result', 'node2 result'],
  'high_score': 5
}
```

三个通道的最终值：

- `covered`：node1 入口没有这一键——无 reducer 的通道在首次写入前不存在；node2 入口已是 `"node1 result"`，最终被 `"node2 result"` 覆盖
- `append_list`：入口是 `[]`，两次写入被拼接成两元素列表
- `high_score`：入口是 `0`，然后 `max(0, 5) = 5`，再 `max(5, 3) = 5`，较小的 3 不会留下

带 reducer 的通道会用值类型的零值作为合并起点：`list()` → `[]`，`int()` → `0`。因此 `high_score` 在任何节点写入之前已经是 `0`，无法区分「尚未计分」与「分数为零」。无 reducer 的 `covered` 没有这种零值，缺席就是缺席。

`invoke({})` 可以执行，是因为三个键都是 `NotRequired`。若把某键改成必填，输入里必须带上该键。

> **说明：** 节点返回值里只出现要更新的键。未返回的键保持原样，不会被删掉。若必须绕过 reducer、把整条通道直接换成新值，可用 `Overwrite` 包一层（见官方文档）；本篇示例都不需要。

## 内置 Reducer：add_messages

消息列表若用 `operator.add`，只能拼接，不能按 `id` 更新已有条目，也不能接受 `{"role", "content"}` 这种简写。LangGraph 提供 `add_messages`：把更新合并进当前消息列表。

行为：

1. 新消息的 `id` 在现有列表中不存在 → 追加到末尾
2. `id` 已存在 → 用新对象替换该位置的旧对象，列表长度不变
3. 传入 `RemoveMessage(id=...)` → 按 `id` 删除（本篇不演示）

`id` 在构造时若传入整数，对象上会规范成字符串。下面分三次合并，只看 `content` 与 `id`；`additional_kwargs` / `response_metadata` / `tool_calls` 等空字段用省略号代替：

```python
from langchain.messages import AIMessage, HumanMessage, SystemMessage
from langgraph.graph.message import add_messages

messages = [
  SystemMessage("系统消息", id=1),
  HumanMessage("用户消息1", id=2),
]

messages = add_messages(messages, [
  AIMessage("AI回复1", id=3),
  HumanMessage("用户消息2", id=4),
])
```

```text
[
  SystemMessage(content='系统消息', id='1', ...),
  HumanMessage(content='用户消息1', id='2', ...),
  AIMessage(content='AI回复1', id='3', ...),
  HumanMessage(content='用户消息2', id='4', ...)
]
```

再追加一条新 `id`：

```python
messages = add_messages(messages, AIMessage("AI回复2", id=5))
```

```text
[
  SystemMessage(content='系统消息', id='1', ...),
  HumanMessage(content='用户消息1', id='2', ...),
  AIMessage(content='AI回复1', id='3', ...),
  HumanMessage(content='用户消息2', id='4', ...),
  AIMessage(content='AI回复2', id='5', ...)
]
```

用已存在的 `id=3` 再写一次：

```python
messages = add_messages(messages, AIMessage("AI回复1-改", id=3))
```

```text
[
  SystemMessage(content='系统消息', id='1', ...),
  HumanMessage(content='用户消息1', id='2', ...),
  AIMessage(content='AI回复1-改', id='3', ...),
  HumanMessage(content='用户消息2', id='4', ...),
  AIMessage(content='AI回复2', id='5', ...)
]
```

按 `id` 合并之后：

- 前两次都是新 `id`，列表从 2 条到 4 条再到 5 条，顺序与传入顺序一致
- 第三次 `id='3'` 已在列表中：长度仍是 5，没有变成 6
- 被替换的是原位置上的那一条（仍是第三条），`content` 从 `'AI回复1'` 变成 `'AI回复1-改'`，不是追加到末尾

这与 Agent底层逻辑第07章「已入列的历史不可改写」并不冲突：业务上仍应避免改已经定稿的轮次。按 `id` 替换是给图状态用的合并语义，典型场景是流式先写入不完整的 `AIMessage`，生成结束后用完整对象换掉同一 `id` 的占位。

节点里不要自己 `state["messages"] + [response]`。返回 `{"messages": [response]}`，交给 `add_messages` 合并。

from langgraph.graph import END, START, StateGraph
from langgraph_project.nodes.call_model import call_model
from langgraph_project.states.core_agent_state import CoreAgentState

def build_graph():
  """生成核心 Agent 图（未编译）"""
  workflow = StateGraph(CoreAgentState)
  workflow.add_node("call_model", call_model)
  workflow.add_edge(START, "call_model")
  workflow.add_edge("call_model", END)

  return workflow

`langgraph_project/states/core_agent_state.py`：`messages` 必填且标注 `add_messages`；模型配置与模板名选填，使用默认覆盖，节点内原样读出。

```python
from typing import Annotated, NotRequired, Required, TypedDict

from langchain_core.messages import BaseMessage
from langgraph.graph.message import add_messages
from langgraph_project.states.model_config import ModelConfig

class CoreAgentState(TypedDict):
  """核心 Agent 图状态"""

  # 消息列表，使用 add_messages reducer 自动累积
  messages: Required[Annotated[list[BaseMessage], add_messages]]
  # 模型配置，invoke 时传入，节点内透传给 create_model
  model_config: NotRequired[ModelConfig]
  # 系统提示词模板名称，选填，默认 system
  system_prompt_template: NotRequired[str]
```

`langgraph_project/states/model_config.py`：将第02章、第03章的模型参数封装为可写入状态的对象。`to_kwargs()` 展开后交给 `create_model`。

```python
from dataclasses import dataclass, field
from typing import Any

from langgraph_project.core.config import anthropic_settings
from langgraph_project.core.create_model import Provider

@dataclass
class ModelConfig:
  """模型配置，最终透传给 create_model"""

  model_name: str = anthropic_settings.default_model
  provider: Provider = "anthropic"
  kwargs: dict[str, Any] = field(default_factory=dict)

  def to_kwargs(self) -> dict[str, Any]:
    return {
      "model_name": self.model_name,
      "provider": self.provider,
      **self.kwargs,
    }
```

`langgraph_project/nodes/call_model.py`：从状态取出**对话消息**（不含系统提示词），按模板渲染 `SystemMessage`，再 `ainvoke([system_message, *messages])`。返回值只有 `{"messages": [response]}`——系统提示词不写回状态，本轮 `AIMessage` 交给 `add_messages` 追加。

系统提示词仍对应 Agent底层逻辑第06章：模板文件静态，运行时只注入环境快照。不把 `SystemMessage` 写入 `messages` 通道，避免历史中出现多份 system，也便于每次用同一份模板渲染（与第07章「system 放最前且尽量固定」一致：内容固定，只是组装发生在节点内部）。

```python
import os
import subprocess
from typing import Any

from langchain_core.messages import SystemMessage
from langgraph_project.core.create_model import create_model
from langgraph_project.states.core_agent_state import CoreAgentState
from langgraph_project.states.model_config import ModelConfig
from langgraph_project.templates import prompt_from_filename

def _is_git(cwd: str) -> bool:
  result = subprocess.run(
    ["git", "-C", cwd, "rev-parse", "--is-inside-work-tree"],
    capture_output=True,
    text=True,
  )

  return result.returncode == 0

def _environment_info() -> dict[str, Any]:
  cwd = os.getcwd()

  return {
    "cwd": cwd,
    "os": os.name,
    "is_git": _is_git(cwd),
  }

# 系统提示词名称 -> 需要注入的信息（模块导入时求值一次）
_SYSTEM_PROMPT_TEMPLATES: dict[str, dict[str, Any]] = {"system": _environment_info()}

def _build_system_message(template_name: str) -> SystemMessage:
  data = _SYSTEM_PROMPT_TEMPLATES[template_name]

  return SystemMessage(
    content=prompt_from_filename(template_name, data),
  )

async def call_model(state: CoreAgentState) -> dict:
  """调用模型节点"""
  messages = state["messages"]  # 取出 messages，不包含系统提示词
  model_config = state.get("model_config", ModelConfig())
  template_name = state.get("system_prompt_template", "system")
  system_message = _build_system_message(template_name)
  model = create_model(**model_config.to_kwargs())
  response = await model.ainvoke([system_message, *messages])

  return {"messages": [response]}
```

> **说明：** `_environment_info()` 在模块导入时求值，进程内工作目录一般不变。若要在每次节点执行时采集，把调用移进 `_build_system_message`。

`langgraph_project/templates/__init__.py`：按文件名读 `.mst` 再渲染。必须显式 `encoding="utf-8"`。

```python
from pathlib import Path
from typing import Any

from langchain_core.utils.mustache import render

def prompt(template: str, data: dict[str, Any]):
  return render(template, data)

def prompt_from_filename(filename: str, data: dict[str, Any]):
  template_path = Path(__file__).parent / f"{filename}.mst"
  template = template_path.read_text(encoding="utf-8")

  return prompt(template, data)
```

> **说明：** `Path.read_text()` 不传 `encoding` 时，使用 locale 默认编码。Windows 中文系统常见为 GBK（`cp936`），而 `system.mst` 是 UTF-8。用 GBK 去读 UTF-8 会触发 `UnicodeDecodeError`，或得到乱码。macOS / Linux 上 locale 多为 UTF-8，同一行代码往往不会暴露这个问题。第03章的 `prompt_from_filename` 已经写了 `encoding="utf-8"`，此处同一原因。
