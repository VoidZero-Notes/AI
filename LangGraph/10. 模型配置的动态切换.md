第02章用 `init_chat_model` 在创建时固定 `model`、密钥与厂商；第03章把这次创建封装成 `create_model(..., **kwargs)`；第04章再把参数写入图状态的 `model_config`，节点每次从状态读出后重建模型。本篇改走 LangChain 的运行时配置：创建时只声明允许覆盖的字段，调用时经 `RunnableConfig.configurable` 注入。图、节点、`bind_tools` 返回的对象都是嵌套的 `Runnable`，同一份配置沿 `ContextVar` 向下传播，因此不必再把模型参数写进图状态。

第07章已经使用同一条通道：`config.configurable.thread_id` 指定检查点线程。本篇只是在同一个 `configurable` 字典里增加模型字段。Agent底层逻辑第06章、第07章的 `Model` 在构造时固定参数，没有「同一实例按调用覆盖」这一层；对应关系停在第02章的 Chat Model 封装。

| 概念                  | 作用                                                                                         |
| --------------------- | -------------------------------------------------------------------------------------------- |
| `configurable_fields` | 创建模型时声明允许运行时覆盖的字段名                                                         |
| `RunnableConfig`      | 任何 `Runnable` 的 `invoke` / `ainvoke` 都可接收的配置对象                                   |
| `configurable`        | `RunnableConfig` 中的字典；本篇放模型参数，第07章放 `thread_id`                              |
| `ContextVar`          | 框架把当前 `config` 写入上下文变量，嵌套 `Runnable` 不必层层手传                             |
| `ConfigPrinter`       | 回调：在 `on_chat_model_start` 打印本次实际生效的调用参数                                    |

## 两步机制

`model = init_chat_model(配置)` 仍是第02章的工厂。动态切换拆成两步：

1. 创建时声明可覆盖的字段名（`configurable_fields`）
2. 运行时经 `config.configurable` 注入新值

`ainvoke(..., config=...)` 时，框架把这份 `RunnableConfig` 写入 `ContextVar`。外层 `Runnable`（编译后的图）套内层 `Runnable`（节点里的模型、`bind_tools` 返回的新对象），配置沿嵌套向下，任意一层都可消费，无需改节点函数签名，也无需再走状态通道。

```text
ContextVar ← config
Runnable          # 编译后的图
  Runnable        # 节点 / 条件边
    Runnable      # bind_tools 得到的新模型
      Runnable    # init_chat_model 返回的 Chat Model
```

任何 `Runnable` 都可以接收一份 `RunnableConfig`；内部再按已声明的字段消费。未列入 `configurable_fields` 的键即使写进 `configurable` 也不会生效。

## 创建时声明字段

```python
import asyncio
from langgraph_project.core.config import anthropic_settings
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage
from langchain_core.callbacks import BaseCallbackHandler

# 创建模型时，指定哪些字段可以在运行时重新配置
model = init_chat_model(
  model_provider="anthropic",
  model=anthropic_settings.default_model,
  configurable_fields=[
    "model",
    "temperature",
    "top_p",
    "thinking"
  ]
)

class ConfigPrinter(BaseCallbackHandler):
  def on_chat_model_start(self, serialized, messages, **kwargs):
    params = kwargs["invocation_params"]
    print("本次调用使用的模型配置：")
    print(f"  Model:       {params.get('model')}")
    print(f"  Temperature: {params.get('temperature')}")
    print(f"  Top P:       {params.get('top_p')}")
    print(f"  Thinking:    {params.get('thinking')}")
    print(f"  Top K:       {params.get('top_k')}")

asyncio.run(model.ainvoke(
  input=[HumanMessage("你好")],
  config={
    "callbacks": [ConfigPrinter()]
  }
))
```

```text
本次调用使用的模型配置：
  Model:       qwen3.7-plus
  Temperature: None
  Top P:       None
  Thinking:    None
  Top K:       None
```

未传 `configurable` 时，`model` 使用创建时的默认值（本例为 `qwen3.7-plus`），其余字段为 `None`。`top_k` 未列入 `configurable_fields`，后面注入也不会出现在实际调用里。

## 运行时注入

同一实例再次 `ainvoke`，把要覆盖的值放进 `config.configurable`：

```python
asyncio.run(model.ainvoke(
  [HumanMessage("你好")],
  config={
    "configurable": {
      "model": "qwen3.7-max",
      "temperature": 0.5,
      "top_p": 0.9,
      "thinking": {"type": "disabled"},
      "top_k": 50,
    },
    "callbacks": [ConfigPrinter()],
  }
))
```

```text
本次调用使用的模型配置：
  Model:       qwen3.7-max
  Temperature: 0.5
  Top P:       0.9
  Thinking:    {'type': 'disabled'}
  Top K:       None
```

`model` / `temperature` / `top_p` / `thinking` 已声明，因此覆盖成功。`top_k: 50` 写了但未声明，打印仍是 `None`。

## 工程：create_model

第03章最后一次给出完整 `create_model`：签名接收 `model_name` / `provider` / `**kwargs`，原样交给 `init_chat_model`。第04章、第08章的节点都是 `create_model(**model_config.to_kwargs())`，每次调用按状态重建。

本篇去掉调用时参数，改为在工厂内部写死默认值，并声明可覆盖字段。

`src/langgraph_project/core/create_model.py`：

```python
from typing import Literal, Union
from .config import anthropic_settings
from langchain.chat_models import init_chat_model

Provider = Union[Literal["anthropic"], Literal["openai_reasoning"]]

def create_model():
  model_name = anthropic_settings.default_model
  provider: Provider = "anthropic"

  return init_chat_model(
    model=model_name,
    model_provider=provider,
    thinking={"type": "disabled"},
    configurable_fields=["model", "temperature", "top_p", "thinking"],
  )
```

相对第03章：

| 第03章                                    | 本篇                                                         | 原因                                               |
| ----------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------- |
| 签名含 `model_name` / `provider` / `**kwargs` | 无参                                                         | 覆盖改走 `configurable`，不再靠调用方传参          |
| 无默认 `thinking`                         | `thinking={"type": "disabled"}`                              | 默认关闭思维链；需要时由运行时覆盖                 |
| 无 `configurable_fields`                  | 声明 `model` / `temperature` / `top_p` / `thinking`          | 只有列入的字段能在 `ainvoke` 时被替换              |

字段名是 `init_chat_model` 的参数名（`model`），不是第03章签名里的 `model_name`。

## 工程：从状态中移除 model_config

第04章最后一次给出完整 `CoreAgentState`，当时把 `ModelConfig` 放进图状态，供节点透传给 `create_model`。第08章的 `call_model` 仍按该字段读取。

本篇删除 `model_config`：模型参数不再是图状态的一部分。第07章的检查点会持久化状态；把温度、模型名写进状态，会与对话历史绑在同一份快照上，换一次调用参数还得改状态。改走 `RunnableConfig` 后，参数只作用于当次 `ainvoke`，不进入 `messages`，也不被检查点当作业务状态保存。

第04章的 `model_config.py`（`ModelConfig` + `to_kwargs`）在这条路径上不再被引用。

`src/langgraph_project/states/core_agent_state.py`：

```python
from typing import Annotated, NotRequired, Required, TypedDict
from langchain_core.messages import BaseMessage
from langgraph.graph.message import add_messages

class CoreAgentState(TypedDict):
  """核心 Agent 图状态"""

  # 消息列表，使用 add_messages reducer 自动累积
  messages: Required[Annotated[list[BaseMessage], add_messages]]
  # 系统提示词模板名称，选填，默认 system
  system_prompt_template: NotRequired[str]
```

相对第04章：去掉 `model_config: NotRequired[ModelConfig]` 及其 import。`messages` 与 `system_prompt_template` 不变。

第08章的 `call_model` 仍写着 `state.get("model_config", ModelConfig())` 与 `create_model(**model_config.to_kwargs())`。工厂改为无参之后，节点改为直接 `create_model()`，不再读状态里的模型配置。`ainvoke` 不必再手传 `config`：外层图已经把 `RunnableConfig` 写入 `ContextVar`，嵌套的模型会自行消费。取消息、拼系统提示词、`bind_tools`、返回 `{"messages": [response]}` 与第08章相同。

```python
model = create_model()
model_with_tools = model.bind_tools(tools)
response = await model_with_tools.ainvoke([system_message, *messages])
```

## 从图上注入

编译后的图本身是 `Runnable`（第01章、第02章）。`graph.ainvoke(..., config=...)` 与直接调模型相同：`configurable` 进入 `ContextVar`，传到 `call_model` 内部的 Chat Model。与第07章的 `thread_id` 可以写在同一份 `configurable` 里。

`main.py`：

```python
import asyncio
from langgraph_project.graphs.core_agent_graph import build_graph
from langchain_core.callbacks import BaseCallbackHandler
from langchain_core.messages import HumanMessage

class ConfigPrinter(BaseCallbackHandler):
  def on_chat_model_start(self, serialized, messages, **kwargs):
    params = kwargs["invocation_params"]
    print("本次调用使用的模型配置：")
    print(f"  Model:       {params.get('model')}")
    print(f"  Temperature: {params.get('temperature')}")
    print(f"  Top P:       {params.get('top_p')}")
    print(f"  Thinking:    {params.get('thinking')}")
    print(f"  Top K:       {params.get('top_k')}")

graph = build_graph().compile()

asyncio.run(graph.ainvoke(
  input={
    "messages": [HumanMessage("你好")]
  },
  config={
    "configurable": {
      "model": "qwen3.7-max",
      "temperature": 0.5,
      "top_p": 0.9,
      "thinking": {"type": "disabled"},
      "top_k": 50,
    },
    "callbacks": [ConfigPrinter()],
  }
))
```

```text
本次调用使用的模型配置：
  Model:       qwen3.7-max
  Temperature: 0.5
  Top P:       0.9
  Thinking:    {'type': 'disabled'}
  Top K:       None
```

`callbacks` 与 `configurable` 同属 `RunnableConfig`，不是图状态。`ConfigPrinter` 挂在回调上，才能在模型真正发起请求时读到覆盖后的 `invocation_params`。`top_k` 同样未声明，结果仍为 `None`。
