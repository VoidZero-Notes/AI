第05章把已编译的图部署为 Agent Server：一张图对应一个默认 Assistant，`langgraph.json` 里的图 ID 即默认 `assistant_id`。同一张图可以再创建多份 Assistant：名称、描述、`config`、`context`、`metadata` 不同，拓扑不变。本篇用 `langgraph-sdk` 调用 Agent Server 的 Assistants 接口，完成创建、查询、更新、版本回滚、搜索与删除。调用前须已按第05章启动本地服务（`make studio` / `langgraph dev`，默认 `http://localhost:2024`）。

Agent底层逻辑第11章的 Agent 对外是一次 `invoke(q)`；这里同一张已编译的图注册为服务入口，Assistant 是该图的一份具名、可版本化的配置。发起一次执行仍是 Run（第05章），跨轮状态仍在 Thread 上（第07章）；本篇不发起运行，只管理 Assistant 本身。

文档：[Assistants](https://docs.langchain.com/langsmith/assistants) · [Manage assistants](https://docs.langchain.com/langsmith/configuration-cloud) · [AssistantsClient](https://reference.langchain.com/python/langgraph-sdk/_async/assistants/AssistantsClient) · 本地 OpenAPI：`http://localhost:2024/docs#tag/assistants`

| 概念           | 作用                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| Graph ID       | `langgraph.json` 里 `graphs` 的键。未另行创建时，该 ID 即默认 Assistant              |
| Assistant      | 图的一份版本化配置：`name` / `description` / `config` / `context` / `metadata`       |
| `assistant_id` | 创建后返回的 UUID。发起 Run 时可传图 ID（默认 Assistant），也可传该 UUID（指定配置） |
| `version`      | `create` 为 1；每次 `update` 生成新版本并设为最新；`set_latest` 用于回滚             |
| `config`       | 传给图运行时的 `RunnableConfig`，如 `recursion_limit`（第06章超步上限）              |
| `context`      | 静态上下文，注入 `Runtime`，供节点读取（第09章用 `{"model": "fake"}` 选择模拟模型）  |
| `metadata`     | 仅供搜索过滤，不参与图执行                                                           |

发起 Run 时两种标识不可互换：图 ID（如 `"agent"`）使用默认 Assistant；UUID 使用该份具体配置。本篇创建的 Assistant 得到的是 UUID，不是图 ID。

## 创建客户端

连接本地 Agent Server（默认端口 2024），得到 `client.assistants` 子客户端：

```python
from langgraph_sdk import get_client

client = get_client(url="http://localhost:2024")
client
```

`get_client` 返回异步客户端，后续调用均须 `await`。同步客户端用 `get_sync_client`，接口同名、去掉 `await`。

## 创建 Assistant

> POST /assistants

`graph_id` 必须与 `langgraph.json` 的键一致。创建后生成初始版本（`version=1`），返回体里的 `assistant_id` 是 UUID，供后续接口使用。不传 `assistant_id` 时由服务端生成；传入则可指定 ID。`if_exists` 默认为 `"raise"`（ID 冲突则报错），设为 `"do_nothing"` 则返回已有记录。

启动服务后，图 ID `"agent"` 上已有一份系统创建的默认 Assistant。下面再创建一份自定义配置，不会覆盖默认那份。

```python
# 为 agent 图创建 Assistant
# - context：静态上下文，注入图的 Runtime
# - metadata：附加元数据，供后续搜索过滤
# - name / description：仅作展示，不参与图执行
assistant = await client.assistants.create(
  graph_id="agent",
  name="假模型",
  description="最多允许运行 10 个超步",
  context={"model": "fake"},
  config={
    "recursion_limit": 10
  }
)
assistant
```

保存 `assistant_id`：

```python
assistant_id = assistant["assistant_id"]
assistant_id
```

## 获取 Assistant

> GET /assistants/{assistant_id}

按 ID 读取当前最新版本的详细信息。默认 Assistant 可直接 `get("agent")`。

```python
assistant = await client.assistants.get(assistant_id)
assistant
```

## 更新 Assistant

> PATCH /assistants/{assistant_id}

更新名称、描述、`config`、`context` 等。每次更新生成一个新版本，并自动设为最新；此后用该 `assistant_id` 发起的 Run 均使用新版本。`metadata` 会与已有键值合并；`config` 与 `context` **不合并**：服务端按本次请求体生成新版本，未写入的字段不会从上一版本带过来。要保留的字段必须再次传入。

```python
assistant_v2 = await client.assistants.update(
  assistant_id,
  description="最多允许 20 个超步",
  context={"model": "fake"},
  config={
    "recursion_limit": 20
  }
)
assistant_v2
```

> **说明：** 若 `update` 只改 `recursion_limit` 而不带 `context`，新版本会丢失 `{"model": "fake"}`。无法单独删除某一个历史版本；要跳过某版本，用下一节的 `set_latest` 把另一版本设为最新。

## 获取 Assistant 版本列表

> POST /assistants/{assistant_id}/versions

列出该 Assistant 的全部历史版本：

```python
versions = await client.assistants.get_versions(assistant_id)
versions
```

## 设置最新版本

> POST /assistants/{assistant_id}/latest

将某个历史版本设为最新，用于回滚。回滚后，用该 `assistant_id` 发起的 Run 均使用指定版本的配置。

```python
# 回滚到版本 1
assistant = await client.assistants.set_latest(assistant_id, version=1)
print(f"当前最新版本: {assistant['version']}, 名称: {assistant['name']}")
```

## 搜索 Assistant

> POST /assistants/search

按名称、`graph_id`、`metadata` 过滤，支持分页与排序。不传过滤条件时列出全部 Assistant。`name` 为不区分大小写的子串匹配；`metadata` 对每一对键值做精确匹配。

```python
result = await client.assistants.search(
  graph_id="agent",
  limit=10,
)
result
```

使用 `select` 可指定返回字段：

```python
result = await client.assistants.search(
  limit=2,
  offset=0,
  sort_by="created_at",
  sort_order="desc",
  select=["assistant_id", "name", "created_at"]
)
result
```

## 统计 Assistant 数量

> POST /assistants/count

过滤条件与 `search` 相同，只返回数量：

```python
count = await client.assistants.count()
print(f"数量: {count}")
```

```python
count = await client.assistants.count(graph_id="agent")
print(f"agent 图上的 Assistant 数量: {count}")
```

## 获取 Assistant 图结构

> GET /assistants/{assistant_id}/graph

读取该 Assistant 对应图的节点与边。`xray=True` 时一并展开子图；传入整数则限制展开深度。

```python
graph = await client.assistants.get_graph(assistant_id)
print("节点：", [n for n in graph["nodes"]])
print("边：", [e for e in graph["edges"]])
```

## 获取子图

> GET /assistants/{assistant_id}/subgraphs
>
> GET /assistants/{assistant_id}/subgraphs/{namespace}

图内嵌套了子图时，用该接口读取子图的 JSON Schema。`namespace` 指定某一命名空间；`recurse=True` 递归展开。无子图时返回空对象。SDK 的 `get_subgraphs` 同时覆盖上述两条路径。

```python
subgraphs = await client.assistants.get_subgraphs(assistant_id)
subgraphs
```

`namespace` 须与图中实际子图命名空间一致；无子图时可省略下面这段。

```python
nested = await client.assistants.get_subgraphs(
  assistant_id,
  namespace="child",
  recurse=True,
)
nested
```

## 获取 Assistant Schema

> GET /assistants/{assistant_id}/schemas

获取图输入、输出、状态、配置和上下文的 JSON Schema：

```python
schema = await client.assistants.get_schemas(assistant_id)
schema
```

## 删除 Assistant

> DELETE /assistants/{assistant_id}

删除 Assistant 时，其所有版本一并删除，无法只删某一个版本。删除后再次 `get` 会抛出 `NotFoundError`。`delete_threads=True` 时，还会删除 `metadata.assistant_id` 匹配该 Assistant 的全部 Thread 及其 Run、检查点。不要删除默认 Assistant（图 ID `"agent"`），否则按图 ID 发起的 Run 会找不到入口。

```python
from langgraph_sdk.errors import NotFoundError

await client.assistants.delete(assistant_id)

try:
  await client.assistants.get(assistant_id)
except NotFoundError as e:
  print("已删除：", e)
```
