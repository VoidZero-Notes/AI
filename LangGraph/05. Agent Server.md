第01章把图编译成可在本进程 `invoke` 的 `Runnable`。调用方仍须自写 HTTP、自行保存状态：进程退出后，图状态与对话历史一并消失。Agent Server 把已编译的图封装为 HTTP 服务：对外提供 runs / threads / assistants 等接口，对内注入 checkpointer 与 store，使图状态可跨请求持久化。本篇只覆盖本地开发服务器 `langgraph dev`，不涉及生产部署。

本篇对应 Agent底层逻辑第11章的 Agent：那里对外是一次 `invoke(q)`；这里把同一张已编译的图注册为服务入口，由客户端按图 ID 发起运行。持久化对应 Agent底层逻辑第07章的 Session：那边把消息写成 JSON、按 id 读回；这里用 Thread 标识一条会话，Checkpointer 在每一步写入状态快照。Agent底层逻辑第17章的 Graph Engineering 讨论多个 loop 如何连接；LangGraph 把图落地，Agent Server 再把这张图部署为可调用的服务。

文档：[Agent Server](https://docs.langchain.com/langsmith/agent-server) · [Application structure](https://docs.langchain.com/oss/python/langgraph/application-structure) · [Local development](https://docs.langchain.com/langsmith/local-dev-testing)

| 概念              | 作用                                                                                          |
| ----------------- | --------------------------------------------------------------------------------------------- |
| Agent Server      | 运行已编译图的 HTTP 服务，内置持久化与任务队列                                                |
| Graph             | 部署清单里的蓝图。一张图对应一个默认 Assistant                                                |
| Assistant         | 图的一份配置实例。未另行创建时，`langgraph.json` 里的图 ID 即默认 assistant                   |
| Thread            | 一条可持久化的会话容器，跨多次 run 保留图状态                                                 |
| Run               | 在某个 assistant 上执行一次图；可绑定 thread，也可无 thread 的一次性运行                      |
| Checkpointer      | 每一步写入图状态快照。线程内短时记忆：中断后可从最近检查点恢复                                |
| Store             | 跨 thread 的长时记忆（偏好、事实等）。本篇不展开                                              |
| `langgraph.json`  | 声明依赖、图入口、环境变量的部署清单                                                          |
| `langgraph dev`   | 本地轻量开发服务器：无需 Docker，默认端口 2024，热重载，状态写入内存并 pickle 到本地目录      |

Chat Completions 无状态，Agent底层逻辑第07章用 Session 在调用方维护历史。图在进程内 `invoke` 同样无跨进程记忆。Agent Server 把「谁来存状态」从业务代码里拆出去：服务端按 `thread_id` 读写检查点，调用方不必手写 JSON。使用 Agent Server 时，**不要在图代码里自行配置 checkpointer / store**——服务会在运行时注入，以便统一管理 thread、run 与恢复。进程内在 `compile(checkpointer=...)` 上显式指定存储器的用法见第07章；与 Agent Server 不要混用。

一次请求的路径：客户端指定 assistant（或图 ID）与可选 thread → 服务创建 run → 工作进程加载图并执行 → 每一步写入 checkpoint → 若客户端打开了流式连接，事件经 SSE 推回。同一 thread 上同一时刻最多执行一个 run，避免两路写入互相覆盖。

第01章进程内 `compile` / `invoke` 属于手动模式：编译参数、调用参数、调用后的状态与 HTTP 均由调用方自行处理。Agent Server 注入 checkpointer，并接管调用与调用后的持久化。两种模式对照如下：

1. 建立编译好的图结构
2. 看懂 Agent Server API

## 安装 CLI

LangGraph CLI 根据当前目录的 `langgraph.json` 启动 Agent Server。`langgraph dev` 不依赖 Docker，需要带内存后端的 extra：

```bash
uv add "langgraph-cli[inmem]==0.4.31"
```

CLI 安装在项目的 `.venv` 中，默认不进入系统 PATH。在 PowerShell 中直接执行 `langgraph` 会报命令未找到。用 `uv run` 在项目环境中调用：

```bash
uv run langgraph --version
```

`langgraph up` 会启动接近生产的 Docker 栈（PostgreSQL + Redis，默认端口 8123）。日常开发使用 `dev` 即可。

## 配置文件

一份可被 CLI 加载的应用由三部分组成：已编译的图（或返回图的工厂函数）、`langgraph.json`、以及包依赖清单（本工程是 `pyproject.toml`）。可选 `.env` 提供密钥。CLI 默认读取当前目录的 `langgraph.json`。

官方建议导出**已经 `compile()` 过的图**：服务在启动时加载一次，之后每次 run 复用，没有按请求重新编译的开销。仅在需要按 assistant 配置动态换模型或工具时，才导出工厂函数；工厂会在每次调用时执行，应保持轻量。两种方式下，checkpointer 都由服务注入，图代码只负责拓扑。

### 图入口

`langgraph_project/dev.py`：从工程里取出构建器，编译后赋给模块级变量 `graph`。该对象必须是已编译图（`CompiledStateGraph` / Pregel），或返回图的可调用对象。

```python
from langgraph_project.graphs.core_agent_graph import build_graph

graph = build_graph().compile()
```

`build_graph()` 对应第01章的 `StateGraph` 构建阶段；`.compile()` 把节点与边固定成可运行图。这里不传入 checkpointer：若在 `compile(checkpointer=...)` 里自行挂上，会与服务注入的后端冲突。

### 部署清单

`langgraph.json` 把「哪张图、依赖从何处安装、环境变量从何处读取」写成一份清单。`graphs` 的键是图 ID，客户端与 Studio 用这个 ID 选图；值是「模块路径:对象名」。

```json
{
  "dependencies": ["."],
  "graphs": {
    "agent": "langgraph_project.dev:graph"
  },
  "env": ".env"
}
```

| 字段             | 本工程取值                      | 含义                                                                 |
| ---------------- | ------------------------------- | -------------------------------------------------------------------- |
| `dependencies`   | `["."]`                         | 在当前目录查找 `pyproject.toml` / `requirements.txt`，按其中列表安装 |
| `graphs.agent`   | `langgraph_project.dev:graph`   | 导入 `langgraph_project.dev`，取属性 `graph`。图 ID 为 `agent`       |
| `env`            | `".env"`                        | 启动时加载该文件中的环境变量                                         |

值也可以写成文件路径，例如 `./src/agent.py:graph`。本工程用包导入路径，与 `src` 布局下的包名一致。键名 `agent` 即后文 Studio / Agent Chat 要填写的图 ID。

### Makefile 与编码

`export PYTHONUTF8 := 1` 做两件事：

- `PYTHONUTF8 := 1`：给 Make 变量赋值。Python 看到该环境变量后，把默认文本编码改为 UTF-8（不再使用 Windows 的 GBK）
- `export`：把该变量传给 Makefile 中后续执行的命令（`uv run langgraph dev` 等）

没有它时，`langgraph_api` 用系统默认编码读取 UTF-8 的 `openapi.json`，会在中文 Windows 上触发 `UnicodeDecodeError`。

```makefile
export PYTHONUTF8 := 1

.PHONY: dev studio

dev:
  uv run --env-file .env src/langgraph_project/main.py

studio:
  uv run langgraph dev
```

`dev` 仍是进程内直接运行 `main.py`，与第01章的 `invoke` 相同，不经过 Agent Server。`studio` 才启动本地 Agent Server。

## 启动服务

在工程根目录执行：

```bash
make studio
```

等价于 `uv run langgraph dev`。服务默认监听 `127.0.0.1:2024`，改代码后热重载。启动完成后可访问：

| 地址                                         | 用途                                      |
| -------------------------------------------- | ----------------------------------------- |
| `http://127.0.0.1:2024`                      | Agent Server 根地址                       |
| `http://127.0.0.1:2024/docs`                 | OpenAPI 文档，可直接调用 runs / threads 等 |
| `http://127.0.0.1:2024/ok`                   | 健康检查                                  |

`/docs` 里可以看到 assistants、threads、runs 与 store 的路径。创建 run 时，`assistant_id` 填 `agent`（与 `langgraph.json` 的键一致）；若要跨轮保留状态，先创建 thread，再把 `thread_id` 传给后续 run。

## 使用 Studio

Studio 是托管在 LangSmith 上的可视化客户端，通过 `baseUrl` 指向本机 Agent Server，并不把图上传到云端执行。

浏览器打开：

```text
https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:2024
```

即可在界面中与 Agent 对话、查看图结构与运行轨迹。Studio 按 thread 组织对话，对应上文的 Thread：同一条会话里的多次发送共用一份检查点，因此能看到完整消息历史与节点轨迹。需要 LangSmith 账号；图本身仍在 `127.0.0.1:2024` 上运行。

## 使用 Agent Chat

[Agent Chat](https://agentchat.vercel.app/) 是另一套网页客户端，只要求一个可达的 Agent Server 地址与图 ID，不依赖 Studio 的可视化。

打开该站点，填入：

| 项       | 本工程取值                    |
| -------- | ----------------------------- |
| 服务地址 | `http://127.0.0.1:2024`       |
| 图 ID    | `agent`                       |

即可在网页上与 Agent 对话。图 ID 必须与 `langgraph.json` 的 `graphs` 键一致；填错则服务找不到对应 assistant。
