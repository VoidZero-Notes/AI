`Runtime.context` 是官方推荐的运行时配置通道：创建图时登记 `context_schema`，调用时经 `context` 注入，节点从 `Runtime.context` 读取，解决的是「当次运行的自定义配置，不写进图状态，也不被第07章的检查点当作业务状态保存」这一类问题。第11章走的是另一条通道——把系统提示词、工具清单、模型开关放进 `RunnableConfig.configurable`，由节点显式读取；本篇是同一类问题的第二种解法。

自定义键应只走其中一条。框架预留字段（第07章的 `thread_id`、第06章的 `recursion_limit`、第10章的 `callbacks` / `tags`）仍在 `RunnableConfig` 上，并不被 `context` 取代。Agent底层逻辑第10章的 ReAct 在构造 Session 时允许覆盖 `system_prompt` 与 `tools`；第11章已把同一类覆盖改到当次 `ainvoke`。本篇只换注入通道，不改覆盖语义。

| 概念              | 作用                                                                                          |
| ----------------- | --------------------------------------------------------------------------------------------- |
| `ContextSchema`   | 声明本次运行允许传入的字段；Pydantic / dataclass / TypedDict 均可，字段须有默认值或标为必传     |
| `context`         | `invoke` / `ainvoke` 的参数。按 schema 注入，不进图状态                                       |
| `context_schema`  | 创建 `StateGraph` 时登记上述 schema                                                           |
| `Runtime`         | 节点内读取 `context`（以及 store 等运行时对象）的容器                                         |
| `get_runtime()`   | 节点签名不含 `runtime` 时，从 `ContextVar` 取出当前 `Runtime`                                 |
| `configurable`    | 第11章的自定义键通道。本篇业务键改走 `context`；框架字段与 Chat Model 仍读它                  |

## 两条通道

LangGraph 提供两种注入自定义配置的渠道：

1. 经 `config.configurable` 注入，经 `config.configurable` 读取（第10章、第11章）
2. 经 `context` 注入，经 `runtime.context` 读取（本篇）

官方建议自定义配置走 `context`；`configurable` 留给 `thread_id` 等框架字段。两条通道仍然同时可用。使用第05章的 Agent Server 时，两者不能混用，应使用 `context`。

最佳实践：同一项目只用一条通道，不要并列写入。

- 新项目一律使用 `context`
- 旧项目沿用已有通道，不要在中途混入另一条

二者不是整份 API 的互相替换。`RunnableConfig` 仍负责框架预留字段；`context` 只接管原先写入 `configurable` 的业务键。Chat Model 的 `configurable_fields`（第10章）仍然只读 `config.configurable`，不读 `Runtime.context`，因此模型参数若写在 `ContextSchema` 里，调用模型时必须再转写回 `configurable`。

## 注入与读取

两种读法得到同一份 `context`：

```python
import asyncio
from pydantic import BaseModel, Field
from typing_extensions import TypedDict
from langgraph.runtime import Runtime, get_runtime
from langgraph.graph import END, START, StateGraph

class ContextSchema(BaseModel):
  user_id: str = Field(description="用户id")
  locale: str = Field(description="语言偏好", default="zh-CN")

class State(TypedDict):
  pass

# 依赖注入：第二个参数声明 Runtime，框架按签名传入
def greet_di(state: State, runtime: Runtime[ContextSchema]):
  user_id = runtime.context.user_id
  locale = runtime.context.locale
  return {}

# 签名不含 runtime 时，从 ContextVar 取出
def greet_get(state: State):
  runtime = get_runtime(ContextSchema)
  user_id = runtime.context.user_id
  locale = runtime.context.locale
  return {}

builder = StateGraph(State, context_schema=ContextSchema)
builder.add_node(greet_di)
builder.add_node(greet_get)
builder.add_edge(START, "greet_di")
builder.add_edge("greet_di", "greet_get")
builder.add_edge("greet_get", END)

graph = builder.compile()

asyncio.run(graph.ainvoke(
  input={},
  context=ContextSchema(user_id="张三"),
))
```

依赖注入便于标注类型；`get_runtime()` 用于不能改签名的节点。下面的 `call_model` 走 `get_runtime()`。未传的字段使用 schema 默认值（本例 `locale` 为 `"zh-CN"`）。

## 工程：ContextSchema

第11章的自定义键散落在 `configurable` 字典里，没有类型约束。本篇把同一组字段归纳为 `ContextSchema`，与图状态写在同一文件，但**不是** `CoreAgentState` 的成员：它只给 `StateGraph(..., context_schema=...)` 与 `ainvoke(..., context=...)` 用。

`langgraph_project/states/core_agent_state.py`：

```python
from typing import Annotated, Any, Required, TypedDict
from langchain_core.messages import BaseMessage
from langgraph.graph.message import add_messages
from pydantic import BaseModel, Field

class ContextSchema(BaseModel):
  """上下文 Schema"""

  # 模型可配置字段
  model: str | None = Field(description="模型", default=None)
  temperature: float | None = Field(description="温度", default=None)
  top_p: float | None = Field(description="核采样概率", default=None)
  thinking: dict[str, Any] | None = Field(description="思考配置", default=None)

  # 提示词与工具配置
  system_prompt: str | None = Field(description="系统提示词", default=None)
  tools: list[str] | None = Field(description="工具列表", default=None)

class CoreAgentState(TypedDict):
  """核心 Agent 图状态"""

  # 消息列表，使用 add_messages reducer 自动累积
  messages: Required[Annotated[list[BaseMessage], add_messages]]
```

相对第11章：`CoreAgentState` 仍只有 `messages`。新增的是并列的 `ContextSchema`。`model` / `temperature` / `top_p` / `thinking` 对应第10章交给 Chat Model 的字段；`system_prompt` / `tools` / `model`（作 `"fake"` 开关）对应第11章节点自己读取的键。

## 工程：图登记 context_schema

第08章、第11章都是 `StateGraph(CoreAgentState)`。本篇加上 `context_schema`，否则 `ainvoke` 的 `context` 没有类型可校验，节点里的 `Runtime[ContextSchema]` 也无法对齐。

`langgraph_project/graphs/core_agent_graph.py`：

```python
from langgraph.graph import END, START, StateGraph
from langgraph_project.nodes.call_model import call_model
from langgraph_project.states.core_agent_state import CoreAgentState, ContextSchema
from langgraph.prebuilt import ToolNode
from langgraph_project.tools import tools

def should_continue(state: CoreAgentState) -> str:
  """判断是否需要调用工具：最后一个消息带 tool_calls 则路由到 tools，否则结束"""
  last_message = state["messages"][-1]
  return "tools" if last_message.tool_calls else END  # type: ignore

def build_graph():
  """生成核心 Agent 图（未编译）"""
  workflow = StateGraph(CoreAgentState, context_schema=ContextSchema)
  workflow.add_node("model", call_model)
  workflow.add_node("tools", ToolNode(tools))

  workflow.add_edge(START, "model")
  workflow.add_conditional_edges(
    "model", should_continue, {"tools": "tools", END: END}
  )
  workflow.add_edge("tools", "model")
  return workflow
```

相对第08章：仅多一个 `context_schema=ContextSchema`。节点、边、`ToolNode(tools)` 仍挂全部工具，与第11章相同。

## 工程：call_model

第11章节点签名增加 `config: RunnableConfig`，三个辅助函数从 `configurable` 取键。本篇去掉该参数：自定义键改从 `get_runtime(ContextSchema).context` 读取。第08章的取消息、`bind_tools`、返回 `{"messages": [response]}` 不变。

第10章的 Chat Model 只消费 `config.configurable`，不会读取 `Runtime.context`。模型参数写在 `ContextSchema` 之后，必须在 `ainvoke` 模型时手动转成调用配置，否则第10章声明的 `configurable_fields` 无法接收覆盖值。

`langgraph_project/nodes/call_model.py`：

```python
from langchain_core.messages import SystemMessage
from langchain_core.runnables import RunnableConfig
from langchain_core.tools import BaseTool
from langgraph.runtime import get_runtime
from langgraph_project.core.create_model import create_model
from langgraph_project.core.mock_model import mock_model
from langgraph_project.states.core_agent_state import ContextSchema, CoreAgentState
from langgraph_project.tools import get_tools, tools

# create_model 中声明的可配置模型字段，Context 中的同名字段需要转给模型的调用配置
_MODEL_CONFIG_FIELDS = ("model", "temperature", "top_p", "thinking")

def _get_context() -> ContextSchema:
  return get_runtime(ContextSchema).context

def _get_system_prompts(context: ContextSchema) -> list[SystemMessage]:
  """根据 Context 获取系统提示词"""
  if not context or not context.system_prompt:
    return []
  return [SystemMessage(context.system_prompt)]

def _get_model(context: ContextSchema):
  """根据 Context 获取模型对象"""
  if context and context.model == "fake":
    return mock_model()
  return create_model()

def _get_tools(context: ContextSchema) -> list[BaseTool]:
  """根据 Context 获取工具列表，未配置时返回全部工具"""
  if context and context.tools:
    return get_tools(context.tools)
  return tools

def _get_model_config(context: ContextSchema) -> RunnableConfig:
  """模型 invoke 只读 config.configurable，不读 Context，需手动把模型配置转成调用配置"""
  if not context:
    return {}
  configurable = {
    name: getattr(context, name)
    for name in _MODEL_CONFIG_FIELDS
    if getattr(context, name) is not None
  }
  return {"configurable": configurable}

async def call_model(state: CoreAgentState) -> dict:
  """调用模型节点"""
  context = _get_context()
  messages = state["messages"]

  model = _get_model(context)
  system_prompts = _get_system_prompts(context)
  active_tools = _get_tools(context)
  model_with_tools = model.bind_tools(active_tools)

  response = await model_with_tools.ainvoke(
    [*system_prompts, *messages],
    config=_get_model_config(context),
  )
  return {"messages": [response]}
```

相对第11章：

| 第11章                                              | 本篇                                                         | 原因                                                         |
| --------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 签名 `(state, config: RunnableConfig)`              | 签名只留 `state`，经 `get_runtime` 取 context                | 业务键改走 `Runtime`，不再从 `configurable` 读               |
| `_get_*` 接收 `RunnableConfig`，再 `.get("configurable")` | `_get_*` 直接读 `ContextSchema` 属性                         | schema 有类型与默认值，不必再防御空字典                      |
| 无桥接                                              | 新增 `_get_model_config`，把模型字段写回 `configurable`      | Chat Model 不读 `context`，第10章的覆盖通道未变              |
| `ainvoke([...])` 不传 `config`                      | `ainvoke(..., config=_get_model_config(context))`            | 外层只传了 `context`，嵌套模型看不到 `configurable`，必须手传 |
| `configurable.model == "fake"` 换假模型             | `context.model == "fake"` 换假模型                           | 开关语义不变，只换取值位置                                   |

`_get_model` 仍把 `model == "fake"` 当成开关，与第10章「覆盖 `init_chat_model` 的模型名」不是同一语义。两种用法不要写在同一次调用里互相覆盖。第11章的 `get_tools`、未配置则绑定全部工具，本篇未改。
