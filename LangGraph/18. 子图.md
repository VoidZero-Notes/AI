第01章把节点定义为一步计算，`compile()` 把构建器固化为可运行图。本篇把**已编译的图**再当作另一张图里的一个节点来使用，这张被嵌套的图称为子图。子图自身仍有节点、边与状态通道；对父图而言，它只是拓扑上的一步。

Agent底层逻辑第16章的子代理：由父 Agent 再启动一轮独立 `invoke`，子轮次有自己的会话，父代理只纳入各段最终结果。LangGraph 子图是同一边界在图上的落地：子图内部的中间通道不必暴露给父图；父图只接收约定好的输出。Agent底层逻辑第17章的 Graph Engineering 讨论多个 loop 如何连接；子图是连接方式之一——先编译局部图，再嵌进父图，而不是把全部节点摊在同一张父图上。检查点与线程仍按第07章：父图编译时指定存储器，子图默认继承，不必再指定存储器实现。

文档：[Subgraphs](https://docs.langchain.com/oss/python/langgraph/use-subgraphs)

| 概念 | 作用 |
| --- | --- |
| 子图 | 已编译的图，作为父图中的一个节点运行 |
| 作为节点 | 父子共享状态通道，直接 `add_node(已编译子图)` |
| 节点内调用 | 通道名不同或需要变换时，在节点函数里 `invoke` 子图并做映射 |
| `checkpointer=None` | 默认。每次调用重新开始；单次调用内部仍继承父图存储器，可中断、可持久执行 |
| `checkpointer=True` | 同一线程上跨次调用累积子图状态 |
| `checkpointer=False` | 无检查点。执行方式与普通函数调用相同，不能中断、不能持久执行 |

## 子图的两种通信模式

父图与子图之间如何传递状态，取决于**通道是否共享**。有两种模式：

| 模式 | 适用 | 状态 schema |
| --- | --- | --- |
| 作为节点 | 父子有共享键，子图直接读写这些通道 | 把已编译子图传给 `add_node`，无需包装函数 |
| 节点内调用 | 无共享键，或调用前后需要变换 | 节点函数把父状态映射为子图输入，再把子图输出映射回父状态 |

![image-20260907211040152](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-09-07-131040.png)

共享键上的写入会回到父图；子图可以另有私有键，父图读不到。无共享键时若仍把已编译子图直接交给 `add_node`，框架会报错，必须改用节点内调用。

### 作为节点

父子共用通道 `foo`。子图编译后作为父图节点，读写的就是父图上的同名通道：

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START

class State(TypedDict):
  foo: str

def subgraph_node_1(state: State):
  return {"foo": "hi! " + state["foo"]}

subgraph = (
  StateGraph(State)
  .add_node(subgraph_node_1)
  .add_edge(START, "subgraph_node_1")
  .compile()
)

builder = StateGraph(State)
builder.add_node("node_1", subgraph)
builder.add_edge(START, "node_1")
graph = builder.compile()

print(graph.invoke({"foo": "foo"}))  # {'foo': 'hi! foo'}
```

`add_node("node_1", subgraph)` 传入的是编译结果，不是函数。父图执行到 `node_1` 时，把当前状态交给子图；子图执行完毕后，共享通道上的更新合并回父图。

子图 schema 可以比父图更宽：共享键照常回流，私有键只在子图内部可见。

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START

class SubgraphState(TypedDict):
  foo: str  # 与父图共享
  bar: str  # 仅子图可见

def subgraph_node_1(state: SubgraphState):
  return {"bar": "bar"}

def subgraph_node_2(state: SubgraphState):
  return {"foo": state["foo"] + state["bar"]}

subgraph = (
  StateGraph(SubgraphState)
  .add_node(subgraph_node_1)
  .add_node(subgraph_node_2)
  .add_edge(START, "subgraph_node_1")
  .add_edge("subgraph_node_1", "subgraph_node_2")
  .compile()
)

class ParentState(TypedDict):
  foo: str

def node_1(state: ParentState):
  return {"foo": "hi! " + state["foo"]}

builder = StateGraph(ParentState)
builder.add_node("node_1", node_1)
builder.add_node("node_2", subgraph)
builder.add_edge(START, "node_1")
builder.add_edge("node_1", "node_2")
graph = builder.compile()

print(graph.invoke({"foo": "foo"}))  # {'foo': 'hi! foobar'}
```

`bar` 只在子图两个节点之间传递；父图状态始终只有 `foo`。`node_1` 把 `foo` 写成 `hi! foo`，子图再把私有的 `bar` 拼接到共享键上，父图最终得到 `hi! foobar`。

### 节点内调用

父子没有同名通道时，不能直接 `add_node(subgraph)`。在节点函数里调用 `subgraph.invoke`，自行做两边映射。多 Agent 系统里常用来隔离各自的消息历史：每个子图一份私有 `messages`，父图只接收最终文本。

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START

class SubgraphState(TypedDict):
  bar: str

def subgraph_node_1(state: SubgraphState):
  return {"bar": "hi! " + state["bar"]}

subgraph = (
  StateGraph(SubgraphState)
  .add_node(subgraph_node_1)
  .add_edge(START, "subgraph_node_1")
  .compile()
)

class ParentState(TypedDict):
  foo: str

def call_subgraph(state: ParentState):
  subgraph_output = subgraph.invoke({"bar": state["foo"]})
  return {"foo": subgraph_output["bar"]}

builder = StateGraph(ParentState)
builder.add_node("node_1", call_subgraph)
builder.add_edge(START, "node_1")
graph = builder.compile()

print(graph.invoke({"foo": "foo"}))  # {'foo': 'hi! foo'}
```

`call_subgraph` 把父通道 `foo` 写入子通道 `bar`，再把子图的 `bar` 写回 `foo`。变换规则写在这个函数里，框架不会自动对齐键名。

> **说明：** 映射必须覆盖子图 `invoke` 所需的全部必填键。漏传或键名写错，失败发生在节点函数内部，不会被 `add_node` 在编译期拦住。

## 子图持久化模式

子图默认继承父图的检查点存储器，因此不必再为子图指定存储器实现（不必再传入 `InMemorySaver` 等）。编译时仍可用 `checkpointer` 控制**持久化行为**：状态保留多久、单次调用内部能否中断。父图必须带检查点，子图的 `None` / `True` 才有中断、状态查看与跨次记忆；`False` 则子图完全不走检查点。

```python
# 持久化行为取值: None | True | False
sub_graph.compile(checkpointer=持久化行为取值)
```

| 模式 | `checkpointer=` | 行为 |
| :-- | :-- | :-- |
| [每次调用](https://docs.langchain.com/oss/python/langgraph/use-subgraphs#per-invocation-default) | `None`（默认） | 每次调用重新开始；继承父级检查点器，以支持单次调用中的中断与持久执行 |
| [每线程](https://docs.langchain.com/oss/python/langgraph/use-subgraphs#per-thread) | `True` | 状态在同一线程上的调用之间累积。每次调用从上次停止处继续 |
| [无状态](https://docs.langchain.com/oss/python/langgraph/use-subgraphs#stateless) | `False` | 无检查点机制。执行方式与普通函数调用相同，不能中断、不能持久执行 |

三种取值都不指定子图自己的存储器后端；后端始终来自父图（第07章的 `InMemorySaver` 等）。`None` 与 `True` 的差别是**命名空间里的状态跨几次父图调用保留**：`None` 只覆盖这一次 `invoke`；`True` 按父图的 `thread_id` 跨次累积。

多数多 Agent 场景用默认 `None`：子 Agent 处理彼此独立的一次请求，不必记住上次被叫时的内部消息。需要子图跨多轮记住自己的上下文时再用 `True`（例如持续跟踪已编辑文件的编码助手）。不需要中断、也不需要查看子图快照时用 `False`。

> **说明：** `checkpointer=True` 时，同一子图实例在一次运行里并行调用会争用同一检查点命名空间。需要并行时用默认 `None`；多个不同的每线程子图则应各自处于稳定的节点名下，避免按调用次序分配命名空间导致错位。

## 子Agent模式

把子图作为可调用的专家接入父图，对应 Agent底层逻辑第16章：父代理拆分任务，子代理各自执行完毕，父代理只接收最终答复。落在 LangGraph 里通常是下面四条：

1. 不同的子 Agent 使用**同一张图的不同配置**（同一拓扑，提示词、职责或入参约定不同）
2. 提供调用子 Agent 的**工具**即可
3. 通信模式：节点内调用（工具函数里 `invoke` 子图，只把最终字段返回给父图）
4. 持久化模式：`None`（每次工具调用重新开始，不累积子图内部状态）

同一拓扑编译出两份子图，分别包成工具；父图节点调用工具，只写入最终字符串。子图编译不传 `checkpointer`，即默认 `None`。

```python
from typing import TypedDict
from langchain.tools import tool
from langgraph.graph import StateGraph, START

class ExpertState(TypedDict):
  question: str
  answer: str

def build_expert(label: str):
  def reply(state: ExpertState):
    return {"answer": f"{label}：{state['question']}"}

  return (
    StateGraph(ExpertState)
    .add_node("reply", reply)
    .add_edge(START, "reply")
    .compile()
  )

fruit_expert = build_expert("水果专家")
veggie_expert = build_expert("蔬菜专家")

@tool
def ask_fruit_expert(question: str) -> str:
  """处理水果相关问题。"""
  return fruit_expert.invoke({"question": question})["answer"]

@tool
def ask_veggie_expert(question: str) -> str:
  """处理蔬菜相关问题。"""
  return veggie_expert.invoke({"question": question})["answer"]

class ParentState(TypedDict):
  question: str
  result: str

def call_fruit(state: ParentState):
  return {"result": ask_fruit_expert.invoke({"question": state["question"]})}

parent = (
  StateGraph(ParentState)
  .add_node(call_fruit)
  .add_edge(START, "call_fruit")
  .compile()
)

print(parent.invoke({"question": "苹果"}))
# {'question': '苹果', 'result': '水果专家：苹果'}
```

`build_expert` 是同一张图、不同 `label`；两份编译结果各自作为子 Agent。工具内部 `invoke` 属于节点内调用：父状态只有 `question` / `result`，与子图的 `answer` 并不共享键名。`compile()` 未传 `checkpointer`，每次 `ask_fruit_expert.invoke` 都从空状态开始。接第08章时，把这两个 `@tool` 交给 `ToolNode`，由模型决定调哪一个；通信与持久化仍是这两条。

> **说明：** 子图写在工具函数里时，框架无法在编译期静态发现它。`get_state(..., subgraphs=True)` 看不到这类子图快照；中断仍会传到顶层父图。需要检查点子图状态时，改用「作为节点」或在普通节点函数里直接 `invoke`，不要隔一层工具。
