时间旅行指从某个历史检查点**继续跑**，而不只是读取。支持两种模式——Replay：原样重新执行；Fork：先修改该检查点的状态，再从新检查点继续。第07章的检查点让每个超步都留下一份可读的状态快照，第14章在 Agent Server 上按 `checkpoint_id` 读取过其中某一份；时间旅行是在这份可读性之上，把"读"变成"从那里继续跑"。

第14章把 `update_state`（Fork 用到的接口）留到本篇；Replay 则是给 `runs.wait`（第15章）多传一个 `checkpoint` 参数。本篇按 LangGraph API（进程内）与 Agent Server（SDK）各走一遍，子图的限制放在最后，选修部分再讲一种绕开 Studio 显示问题的写法。

文档：[Use time travel](https://docs.langchain.com/oss/python/langgraph/use-time-travel) · [Checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers) · 本地 OpenAPI：`http://localhost:2024/docs#tag/threads`

| 概念            | 作用                                                                             |
| --------------- | -------------------------------------------------------------------------------- |
| Replay          | 用某个历史检查点的 config 重新执行；检查点之前的节点不重跑，之后的节点（含 LLM 调用）重新执行一遍 |
| Fork            | 在某个历史检查点上先 `update_state` 修改状态，再从新检查点继续执行                |
| `checkpoint_id` | 检查点自身的 id，藏在 `config["configurable"]` 里（第14章「获取指定检查点状态」已用过） |
| `as_node`       | Fork 时声明这次状态更新算作哪个节点产生的，决定后续从哪个节点继续跑               |
| `__copy__`      | [选修] 只复制、不新建父子关系的写法，用于绕开 Studio 的一处显示问题               |

## LangGraph API

### 准备工作

```python
from langgraph_project.graphs.core_agent_graph import build_graph
from langgraph.checkpoint.memory import InMemorySaver
from langchain_core.messages import HumanMessage
from langchain_core.runnables import RunnableConfig
from langgraph_project.states.core_agent_state import ContextSchema
from langgraph.graph import START

context = ContextSchema(
  system_prompt="尽可能简短地回答问题，不要长篇大论",
)
config: RunnableConfig = {
  "configurable": {
    "thread_id": "time_travel"
  }
}

graph = build_graph().compile(checkpointer=InMemorySaver())
```

### 运行一次，产出多个检查点

```python
await graph.ainvoke(
  input={"messages": [HumanMessage("月亮离地球有多远")]},
  config=config,
  context=context,
)
```

### 查看历史记录

`get_state_history`（第07章）按最新在前返回全部检查点。同时打印每个检查点及其父检查点，方便挑选 Replay / Fork 的起点：

```python
history = list(graph.get_state_history(config))
for i, state in enumerate(history):
  cid = state.config["configurable"]["checkpoint_id"]
  parent = (
    state.parent_config["configurable"]["checkpoint_id"]
    if state.parent_config
    else None
  )
  print(f"{i:>2}  checkpoint_id={cid}  parent={parent}")
```

```python
before_start = history[2].config  # START 之前
after_start = history[1].config   # START 之后、模型调用之前
```

### Replay

`input` 必须传 `None`：这次执行不是新一轮对话，是从 `after_start` 这个检查点继续跑，节点会重新调用模型：

```python
await graph.ainvoke(
  input=None,
  config=after_start,
  context=context,
)
```

### Fork

与 Replay 的区别：可以先**修改检查点状态**再运行。`update_state` 在 `before_start` 上生成一枚新检查点，`as_node=START` 声明这次更新算作 START 产生的：

```python
fork_config = graph.update_state(
  config=before_start,
  values={"messages": [HumanMessage("太阳距离地球有多远")]},
  as_node=START,
)

await graph.ainvoke(
  input=None,
  config=fork_config,
  context=context,
)
```

### 最佳实践

- 刷新 AI 输出：找到 AI 结果之前的检查点，直接 Replay
- 修改内容：找到内容产出节点的上一个检查点，`as_node` 指定为该节点，替换内容后从该检查点继续跑

## Agent Server

时间旅行在 Agent Server 上同样基于检查点，通过 SDK 操作。区别只在于：历史、状态与检查点都存在服务端，经 `client.threads` 查询与修改，再经 `client.runs` 从指定检查点恢复运行。

### 准备工作

用默认 Assistant 跑一次触发工具调用的问题（第08章 `ToolNode`），一次运行会产生多个检查点：

```python
from langgraph_sdk import get_client

client = get_client(url="http://localhost:2024")
assistant_id = "agent"

thread = await client.threads.create(metadata={"__name__": "时间旅行"})
thread_id = thread["thread_id"]

await client.runs.wait(
  thread_id=thread_id,
  assistant_id=assistant_id,
  input={"messages": [{"role": "user", "content": "地球为什么是圆的？"}]},
)
```

### 查看历史记录

`get_history`（第14章）按 `metadata.step` 找到 START 前后的检查点：

```python
history = await client.threads.get_history(thread_id, limit=20)
before_start = {}
after_start = {}
for state in history:
  step = state["metadata"].get("step")
  print(f"step={step:>3}  next={state['next']}  checkpoint_id={state['checkpoint']['checkpoint_id']}")
  if step == -1:
    before_start = state["checkpoint"]
  elif step == 0:
    after_start = state["checkpoint"]
```

### Replay

> POST /threads/{thread_id}/runs/wait

`runs.wait` 不传 `input`，改传 `checkpoint`：

```python
result = await client.runs.wait(
  thread_id=thread_id,
  assistant_id=assistant_id,
  input=None,
  checkpoint=after_start,
)
result
```

### Fork

> POST /threads/{thread_id}/state

第14章预留未展开的 `update_state`，就是 Fork 用的这个接口。在 `before_start` 上写入新状态，`as_node=START` 与 LangGraph API 一致；拿到的新检查点再传给 `runs.wait`：

```python
from langgraph.graph import START

updated = await client.threads.update_state(
  thread_id,
  values={"messages": [{"role": "user", "content": "月球到地球距离是多少？"}]},
  checkpoint=before_start,
  as_node=START,
)
updated_checkpoint = updated["checkpoint"]

result = await client.runs.wait(
  thread_id=thread_id,
  assistant_id=assistant_id,
  input=None,
  checkpoint=updated_checkpoint,
)
result
```

演示用完后删除测试线程：

```python
await client.threads.delete(thread_id)
```

## [选修] 魔法版本：绕开 Studio 的显示问题

前面的 Fork 会把新检查点的父节点指向 `before_start`，`LangSmith Studio` 的时间线图上会显示成从旧检查点直接分叉；某些场景下这与实际预期的父子关系对不上（也可能是 `LangGraph` 本身的设计限制）。用固定值 `as_node="__copy__"` 可以先复制出一份不带这层父子关系的检查点，再在其上操作：

### LangGraph API

Replay 前先「复制」一份检查点，`values` 必须传 `None`：

```python
fork_config = graph.update_state(
  after_start,
  values=None,
  as_node="__copy__",
)

await graph.ainvoke(
  input=None,
  config=fork_config,
  context=context,
)
```

Fork 时把新状态与来源节点包成 `[values, as_node]` 传给 `values`，外层 `as_node` 固定写 `"__copy__"`：

```python
fork_config = graph.update_state(
  before_start,
  values=[
    [
      {"messages": [HumanMessage("太阳距离地球有多远？")]},
      START,
    ]
  ],
  as_node="__copy__",
)

await graph.ainvoke(
  input=None,
  config=fork_config,
  context=context,
)
```

### Agent Server

写法与 LangGraph API 对应，`checkpoint` 换成服务端返回的检查点对象：

```python
# Replay：先复制
updated = await client.threads.update_state(
  thread_id=thread_id,
  values=None,
  checkpoint=after_start,
  as_node="__copy__",
)
updated_checkpoint = updated["checkpoint"]

result = await client.runs.wait(
  thread_id=thread_id,
  assistant_id=assistant_id,
  input=None,
  checkpoint=updated_checkpoint,
)
```

```python
# Fork
updated = await client.threads.update_state(
  thread_id,
  values=[
    [
      {"messages": [{"role": "user", "content": "月球到地球距离是多少？"}]},
      START,
    ]
  ],
  checkpoint=before_start,
  as_node="__copy__",
)
updated_checkpoint = updated["checkpoint"]

result = await client.runs.wait(
  thread_id=thread_id,
  assistant_id=assistant_id,
  input=None,
  checkpoint=updated_checkpoint,
)
```
