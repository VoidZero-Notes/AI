人在回路（Human-in-the-Loop，简称 HITL）指图运行到某个点主动暂停，把决策交给用户，等用户答复后再从暂停处继续执行——这正是第22章 中断里 `interrupt()` 的一种典型应用场景：不是"出了异常才暂停"，而是主动设计一个会向用户提问的工具。本篇给出具体落地：`ask_user_question` 工具，把"该不该问用户、问什么、答案怎么传回来"固定成三段契约——工具参数契约、中断契约、回复契约——并给出完整实现代码。

文档：[Human-in-the-loop](https://docs.langchain.com/oss/python/langgraph/interrupts)

| 概念 | 作用 |
| --- | --- |
| 工具参数契约 | 模型调用 `ask_user_question` 时必须传入的参数结构：一个问题 + 2～5 个互斥选项 |
| 中断契约 | 工具函数内部传给 `interrupt()` 的字典结构，前端据此渲染问题与选项 |
| 回复契约 | 用户答复回传给 `interrupt()` 的格式：纯字符串 |
| `args_schema` | 用 Pydantic 模型覆盖 `@tool` 自动推断的入参 schema（第08章 工具节点） |
| `field_validator` | 对选项集合做组合校验：至多一个推荐项、标题不重复 |
| `ToolNode` | 执行工具调用的节点：先用 Pydantic 校验参数，失败则封装为 `ToolMessage` 返回给模型，通过才调用工具函数（第08章 工具节点） |

## 设计 ask_user_question 工具契约

### 工具参数契约

先用 Pydantic 定义参数结构，再据此生成发给模型的 schema：

```python
from pydantic import BaseModel, Field, field_validator

class QuestionOption(BaseModel):
  """用户可选择的单选项。"""

  title: str = Field(description="选项标题，也是用户选择后返回给模型的值")
  description: str = Field(description="选项的简短说明，帮助用户理解选择的影响")
  recommended: bool = Field(
    default=False,
    description="是否为推荐选项；一个问题最多只能有一个推荐选项",
  )

class AskUserQuestionInput(BaseModel):
  """ask_user_question 工具的输入。"""

  question: str = Field(description="需要询问用户的一个明确问题")
  options: list[QuestionOption] = Field(
    min_length=2,
    max_length=5,
    description=(
      "提供给用户的2到5个互斥选项。最多只能有一个推荐选项。"
      "不要添加'其他'选项，界面会自动允许用户输入其他答案"
    ),
  )

  # options 字段校验完成后，再检查选项之间的组合关系
  @field_validator("options")
  @classmethod
  def validate_options(cls, options: list[QuestionOption]) -> list[QuestionOption]:
    # 推荐项总数大于1时校验失败
    if sum([option.recommended for option in options]) > 1:
      # 这里抛出的 ValueError 会被 Pydantic 捕获，统一封装为 ValidationError
      raise ValueError("一个问题最多只能有一个推荐选项")

    # 标题重复时校验失败
    titles = [option.title for option in options]
    if len(titles) != len(set(titles)):
      raise ValueError("选项标题不能重复")

    return options
```

`@field_validator("options")` 声明"该函数校验 `options` 字段"：Pydantic 先完成 `options` 列表里每个 `QuestionOption` 元素各自的字段类型校验，再把整个列表交给这个函数做跨元素的组合校验。`@classmethod` 是 Pydantic v2 对校验函数的固定要求，第一个参数 `cls` 是 `AskUserQuestionInput` 类本身，而非实例（此时实例尚未构造完成）。`sum([option.recommended for option in options])` 利用 Python 里 `True` 等价于 `1`、`False` 等价于 `0` 的特性，统计这一批选项里被标为推荐项的个数，超过 1 个即视为不合法。函数内抛出的 `ValueError`（以及 `AssertionError`）不会直接传给调用方：Pydantic 会捕获它，统一包装成携带字段名与原因的 `ValidationError`，这正是后文 `ToolNode 的参数校验流程` 一节图中"校验失败 → ValidationError"这一步的来源。

对应的参数示例：

```json

  "question": "你希望使用哪种数据库？",
  "options": [
    {
      "title": "PostgreSQL",
      "description": "功能完善，适合生产环境",
      "recommended": true
    },
    {
      "title": "MySQL",

    },

```

### 中断契约

工具函数拿到校验通过的参数后，原样传给 `interrupt()`，只多包一层 `type` 字段供前端识别中断类型：

```json

  "type": "ask_user_question",
```

### 回复契约

用户选择一个已有选项，或者输入自定义答案，最终都以纯字符串形式传回 `interrupt()`：

```text
PostgreSQL
```

### 完整实现

三段契约拼起来，就是 `ask_user_question` 工具的完整实现：

```python
from langchain.tools import tool
from langgraph.types import interrupt

@tool(args_schema=AskUserQuestionInput)
def ask_user_question(question: str, options: list[QuestionOption]) -> str:
  """
  当缺少必要信息、需要向用户提问时，向用户提出一个单选问题并暂停执行。
  用户可以选择一个已有选项，也可以输入自己的答案。
  """
  answer = interrupt(
    {
      "type": "ask_user_question",
      "question": question,
      "options": [option.model_dump() for option in options],
    }
  )
  answer = str(answer)
  if not answer:
    # 这个错误会导致图被终止，无法重试
    raise ValueError(f'对于问题"{question}"请给予你的选择')
  return answer
```

### ToolNode 的参数校验流程

`args_schema=AskUserQuestionInput` 用 Pydantic 模型覆盖 `@tool` 自动推断的入参 schema（第08章 工具节点）。模型每次发出 `ask_user_question` 调用请求后，节点 `ToolNode` 按以下顺序处理：

```
组装参数 → Pydantic 模型（AskUserQuestionInput）
  → Pydantic 验证参数
    → 校验失败：抛出 ValidationError
      → ToolNode 对 ValidationError 做特殊处理：封装为 ToolMessage，加入图状态
    → 校验通过：调用工具函数（ask_user_question 函数体）
```

模型看到的参数说明来自各字段的 `Field(description=...)`，`field_validator` 的组合校验也会一并生效：模型传入的参数不满足约束时，触发的是 Pydantic 的 `ValidationError`，由 `ToolNode` 在工具执行前拦截并封装成 `ToolMessage` 返回给模型，模型可以据此重新构造参数再次调用，图本身不会终止。

工具函数内部再抛出的 `ValueError`（用户答复为空字符串时）性质不同：它发生在 `interrupt()` 恢复之后，不再经过上面这条参数校验流程，会直接导致图运行终止（第20章 容错机制：出错时立即停止图的运行，最新检查点仍是错误发生之前那一枚），不会像参数校验错误那样自动重试。
