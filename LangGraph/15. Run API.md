Run 是对某个 Assistant 执行一次图：客户端指定 Assistant 与可选 Thread，服务创建运行并写入检查点。本篇用 `langgraph-sdk` 调用 Runs 接口，在线程上发起、等待、查询、列出、取消、删除运行，处理同一线程上的并发（多任务策略），以及不绑定线程的一次性运行。第13章、第14章分别只管理 Assistant 与 Thread 本身，都不发起执行；本篇补上真正驱动图运行的这一层。调用前须已按第05章启动本地服务，并按第13章安装 SDK。

Agent底层逻辑第11章的 Agent 对外是一次 `invoke(q)`；第07章同一条 Session 上的多个轮次，对应这里同一 Thread 上的多次 Run。本篇覆盖后台运行、同步等待、无状态运行、批量创建、取消运行与多任务策略。流式接口（`/runs/stream`、`join_stream`）依赖流式处理，本篇不讲。Cron 按时间表创建 Run，见第16章。

文档：[Runs](https://docs.langchain.com/langsmith/runs) · [Background runs](https://docs.langchain.com/langsmith/background-run) · [Stateless runs](https://docs.langchain.com/langsmith/stateless-runs) · [Cancel a run](https://docs.langchain.com/langsmith/cancel-run) · [Double texting](https://docs.langchain.com/langsmith/double-texting) · [RunsClient](https://reference.langchain.com/python/langgraph-sdk/_async/runs/RunsClient) · 本地 OpenAPI：`http://localhost:2024/docs#tag/thread-runs`

| 概念            | 作用                                                                       |
| --------------- | -------------------------------------------------------------------------- |
| Run             | 对某个 Assistant 执行一次图                                                |
| 有状态运行      | 绑定 `thread_id`，更新该线程的状态与检查点                                 |
| 无状态运行      | 不绑定已有线程；服务临时建线程，默认结束后删除                             |
| `run_id`        | 创建后返回的 UUID                                                          |
| `status`        | 如 `pending` / `running` / `success` / `error` / `interrupted` / `timeout` |
| `assistant_id`  | 图 ID（默认 Assistant）或第13章返回的 UUID                                 |

同一 Thread 上同一时刻最多执行一个 Run（第05章），避免两路写入互相覆盖；前一个还没结束又发起新 Run 时如何处理，由 `multitask_strategy` 决定，见下文《多任务策略》。`assistant_id` 传 `"agent"` 使用默认 Assistant；传 UUID 使用那份具体配置。两种标识不可互换。

## 创建客户端

```python
from langgraph_sdk import get_client

client = get_client(url="http://localhost:2024")
client
```

## 准备工作

有状态运行必须先有一条线程。`metadata.__name__` 会被 Studio 读作会话标题：

```python
thread = await client.threads.create(
  metadata={"__name__": "Run API 测试"}
)
thread_id = thread["thread_id"]
assistant_id = "agent"
```

## 创建后台运行

> POST /threads/{thread_id}/runs

创建后**立即返回**，不等待执行完成。适合先创建、稍后取结果：

```python
run = await client.runs.create(
  thread_id=thread_id,
  assistant_id=assistant_id,
  input={"messages": [{"role": "user", "content": "你好"}]},
  metadata={"lesson": "run-api"},
)
run_id = run["run_id"]
run
```

刚返回时 `status` 多为 `pending`（排队）或 `running`。

### 等待已创建的运行完成

> GET /threads/{thread_id}/runs/{run_id}/join

阻塞直到该后台运行结束，返回图的最新状态：

```python
final_state = await client.runs.join(thread_id, run_id)
final_state
```

### 创建并等待

> POST /threads/{thread_id}/runs/wait

一步完成「创建 + 等待」，直接返回最终状态。适合需要同步拿到结果的场景：

```python
result = await client.runs.wait(
  thread_id=thread_id,
  assistant_id=assistant_id,
  input={"messages": [{"role": "user", "content": "地球为什么是圆的？"}]},
)
result
```

`wait` 与 `create` + `join` 效果等价，只是封装成一个接口。

### 创建时的常用字段

| 字段            | 含义                                                                 |
| --------------- | -------------------------------------------------------------------- |
| `thread_id`     | 绑定的线程。无状态运行传 `None`                                      |
| `assistant_id`  | 使用的 Assistant                                                     |
| `input`         | 注入的图状态                                                         |
| `metadata`      | 本次运行的元数据，供过滤                                             |
| `config` / `context` | 覆盖该 Assistant 的对应配置（第13章）；只作用于这一次 Run      |
| `after_seconds` | 延迟多少秒再开始，用于一次性定时                                     |
| `if_not_exists` | 线程不存在时：`reject`（默认，报错）/ `create`（自动创建线程）       |
| `durability`    | 检查点写入频率                                                       |
| `multitask_strategy` | 同线程上前一个 Run 还没结束时如何处理新 Run，见下文《多任务策略》 |

`durability` 三档：

| 模式            | 行为                                                     | 代价                                                 |
| --------------- | -------------------------------------------------------- | ---------------------------------------------------- |
| `exit`          | 只在图退出时（成功 / 出错 / 中断）持久化一次             | 性能最好；中途崩溃则中间状态全丢                     |
| `async`（默认） | 下一步执行的同时异步写入检查点                           | 兼顾性能与可靠；崩溃时最后一个检查点可能没写入       |
| `sync`          | 下一步开始前同步写入检查点                               | 每步都落盘，最可靠，开销最大                         |

### run 对象常用字段

| 字段           | 含义                                       |
| -------------- | ------------------------------------------ |
| `run_id`       | 运行 ID                                    |
| `thread_id`    | 所属线程                                   |
| `assistant_id` | 本次使用的助手                             |
| `status`       | 运行状态                                   |
| `metadata`     | 创建时传入的元数据                         |
| `kwargs`       | 创建时的参数（`input`、`config`、`context`） |

## 多任务策略

多任务策略（multitask strategy，官方也称 double texting）是 Agent Server 独有的功能：同一线程内前一个 Run 还在执行，又发起新 Run 时，用它决定这两次 Run 如何相处。比如 `Run A` 正在运行，此时发起 `Run B`，四种策略处理方式不同：

| 策略               | Run A（旧）  | Run B（新）          | Run A 已产生的状态 |
| ------------------ | ------------ | --------------------- | ------------------- |
| `enqueue`（默认）  | 继续完成     | 排队等待               | 保留                 |
| `reject`           | 继续完成     | 拒绝创建，报错         | 保留                 |
| `interrupt`        | 被中断       | 立即接替执行           | 保留已提交部分       |
| `rollback`         | 被中断并删除 | 从 A 之前的状态执行    | 回滚并删除           |

创建第二次运行时通过 `multitask_strategy` 指定：

```python
import asyncio

run_a = await client.runs.create(
  thread_id=thread_id,
  assistant_id=assistant_id,
  input={"messages": [{"role": "user", "content": "你好！"}]},
)

# 等 Run A 运行一秒，模拟两次请求的时间差
await asyncio.sleep(1)

run_b = await client.runs.create(
  thread_id=thread_id,
  assistant_id=assistant_id,
  input={"messages": [{"role": "user", "content": "hello！"}]},
  multitask_strategy="rollback",
)
```

```python
run_a = await client.runs.get(thread_id, run_a["run_id"])
run_b = await client.runs.get(thread_id, run_b["run_id"])
run_a["status"], run_b["status"]
```

`interrupt` 与 `rollback` 的效果分别对应下一节「取消运行」里 `action="interrupt"` / `action="rollback"`：区别是这里由 Run B 的到来自动触发，取消一节是主动调用 `cancel`。`enqueue`、`reject` 不涉及取消，只是让 B 排队或直接拒绝创建。

## 取消运行

> POST /threads/{thread_id}/runs/{run_id}/cancel

取消运行是 Agent Server 独有的功能：图本身没有「取消」的概念。适用场景是用户已不需要结果，或运行时间过长需要提前终止。取消接口需要同时提供 `thread_id` 和 `run_id`：

```python
cancel_run = await client.runs.create(
  thread_id=thread_id,
  assistant_id=assistant_id,
  input={"messages": [{"role": "user", "content": "你好！"}]},
)
cancel_run_id = cancel_run["run_id"]
```

```python
await client.runs.cancel(
  thread_id=thread_id,
  run_id=cancel_run_id,
  action="interrupt",  # 默认值，另一个是 rollback
  wait=True,
)
```

| 参数     | 含义                                                                     |
| -------- | ------------------------------------------------------------------------ |
| `action` | `interrupt`（默认）：停止运行，保留已产生的检查点；`rollback`：停止并连同检查点一起删除 |
| `wait`   | `True` 阻塞到取消真正完成才返回；默认 `False`，请求发出即返回，取消异步执行 |

只能取消 `pending` 或 `running` 状态的运行；对已结束的运行调用会报错。批量取消用 `client.runs.cancel_many`，按 `thread_id` + `run_ids` 或按 `status`（`pending` / `running` / `all`）过滤，同样支持 `action`：

```python
await client.runs.cancel_many(status="pending")
```

## 获取运行

> GET /threads/{thread_id}/runs/{run_id}

按 ID 读取最新信息，最常用的是看 `status`：

```python
run = await client.runs.get(thread_id, run_id)
print(f"运行状态: {run['status']}")
run
```

## 列出运行

> GET /threads/{thread_id}/runs

列出该线程上的运行记录，支持分页、按状态过滤、指定返回字段：

```python
import json

runs = await client.runs.list(thread_id, limit=10)
print(json.dumps(runs, indent=2, ensure_ascii=False))
```

```python
runs = await client.runs.list(
  thread_id,
  limit=10,
  status="success",
  select=["run_id", "status", "created_at"],
)
runs
```

## 删除运行

> DELETE /threads/{thread_id}/runs/{run_id}

删除运行记录后再次 `get` 会抛出 `NotFoundError`。删除运行时，**该次运行写入的检查点也会一并删除**：

```python
from langgraph_sdk.errors import NotFoundError

await client.runs.delete(thread_id, run_id)

try:
  await client.runs.get(thread_id, run_id)
except NotFoundError as e:
  print("已删除：", e)
```

```python
await client.threads.get_state(thread_id=thread_id)
```

线程本身还在；`get_state` 看到的是剩下的检查点（例如后面那次 `wait` 留下的），不是被删的那一次。

> **说明：** 取消仍在执行的运行用 `client.runs.cancel`，与删除已结束记录不是一回事，见前面《取消运行》一节。

## 无状态运行

无状态运行不绑定已有线程。服务为每次运行临时创建线程，结束后默认删除（`on_completion="delete"`）。各次运行互不共享状态，适合一次性调用，不必先 `threads.create`。

### 创建无状态后台运行

> POST /runs

与有状态后台运行的区别：不传 `thread_id`（SDK 里传 `None`）：

```python
run = await client.runs.create(
  thread_id=None,
  assistant_id=assistant_id,
  input={"messages": [{"role": "user", "content": "无状态运行：一次性问答"}]},
)
print(f"状态: {run['status']}")
run
```

### 无状态等待输出

> POST /runs/wait

创建无状态运行并直接等待输出：

```python
result = await client.runs.wait(
  thread_id=None,
  assistant_id=assistant_id,
  input={"messages": [{"role": "user", "content": "无状态等待输出"}]},
)
result
```

### 批量创建

> POST /runs/batch

一次创建多个无状态后台运行，立即返回运行列表：

```python
runs = await client.runs.create_batch([
  {"assistant_id": assistant_id, "input": {"messages": [{"role": "user", "content": "批次 1"}]}},
  {"assistant_id": assistant_id, "input": {"messages": [{"role": "user", "content": "批次 2"}]}},
  {"assistant_id": assistant_id, "input": {"messages": [{"role": "user", "content": "批次 3"}]}},
])
print(f"创建数量: {len(runs)}")
print([(r["run_id"], r["status"]) for r in runs])
```

批量接口只接受无状态运行。要在同一线程上连续提问，用前面的有状态 `create` / `wait`。

演示用完后删除测试线程：

```python
await client.threads.delete(thread_id)
```
