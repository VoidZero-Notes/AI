A2A（Agent-to-Agent Protocol）规定异构 Agent 之间如何发现能力、交换任务：对方只要实现同一套发现文档与 JSON-RPC 入口，不必共用同一运行时或同一套 SDK。传输为 HTTP(S)，报文为 JSON-RPC 2.0。第05章的 Agent Server 启动后即为每个 Assistant 暴露 A2A 入口，不必自行实现协议栈。本篇覆盖三件事：创建一份专供外部 Agent 调用的 Assistant、读取 Agent Card、以及经 JSON-RPC 向该入口发送消息。

第17章只覆盖 System 运维接口与 MCP 入口，路径表里的 `POST /a2a/{assistant_id}` 留到本篇。第13章管理 Assistant 本身；本篇把那份 Assistant 当作 A2A 服务身份。A2A 的 `contextId` 映射第07章的 `thread_id`：同一上下文上的多轮消息落在同一条 Thread。图状态须含 `messages` 字段，才能接收 A2A 的文本部件（第03章）。

Agent底层逻辑第14章的 MCP 规定 Agent 如何与异构 tool 通信：schema 在 Server，Client 用同一套发现 / 调用。A2A 规定 Agent 如何与异构 Agent 通信。Agent底层逻辑第11章的 Agent 对外是一次 `invoke(q)`；这里把已部署的 Assistant 暴露为其他 Agent 可发现、可调用的端点。Agent底层逻辑第16章的子代理仍在同一进程内再启动一轮 `invoke`；A2A 是跨进程、跨实现的协作，对方可以是另一套框架写出的 Agent。

文档：[A2A endpoint](https://docs.langchain.com/langsmith/server-a2a) · [A2A JSON-RPC](https://docs.langchain.com/langsmith/agent-server-api/a2a/a2a-json-rpc) · 协议官网：[a2a-protocol.org](https://a2a-protocol.org/) · 本地 OpenAPI：`http://localhost:2024/docs#tag/A2A`

| 概念                     | 作用                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| A2A                      | 异构 Agent 互发现、互调用的开放协议                                  |
| MCP                      | Agent 与异构 tool 的协议（Agent底层逻辑第14章；第17章的 `/mcp/`）    |
| Agent Card               | 发现文档：名称、技能、输入输出模式、通信 URL                         |
| Agent Server             | 为每个 Assistant 自动暴露 Card 与 JSON-RPC 入口（第05章）            |
| `assistant_id`           | 第13章创建 Assistant 后返回的 UUID；Card 与 `/a2a/{id}` 都按它寻址   |
| `contextId`              | 会话上下文，映射 `thread_id`（第07章）                               |
| `taskId`                 | 同一上下文内的一次任务                                               |
| `POST /a2a/{assistant_id}` | JSON-RPC 通信入口                                                  |

旅游规划是典型协作场景：行程、机票、酒店可以由彼此独立的 Agent 实现，经 A2A 发现对方并交换任务，而不必嵌入同一张 LangGraph 图。

## 协议要点

- 通信协议：HTTP(S)
- 消息格式：JSON-RPC 2.0
- 协议官网：https://a2a-protocol.org/
- Agent Server 启动后即为每个 Assistant 暴露 A2A 入口，无需另行搭建协议服务器

调用前须已按第05章启动本地服务（`make studio` / `langgraph dev`，默认 `http://localhost:2024`），并按第13章安装 `langgraph-sdk`。SDK **没有** A2A 子客户端，发现与通信均走 `client.http`，与第17章的 System / MCP 相同。

要关闭该入口，在 `langgraph.json` 里设置：

```json
{
  "http": {
    "disable_a2a": true
  }
}
```

## 创建 A2A 服务器

Agent Server 已在运行，A2A 路径已经存在。本步不是再写一台 HTTP 服务器，而是按第13章创建一份具名 Assistant，作为外部 Agent 要发现、要调用的服务身份。`name` 与 `description` 会进入 Agent Card；`context` 注入 Runtime（第12章）；`metadata` 仅供搜索，不参与图执行（第13章）。

```python
from langgraph_sdk import get_client

client = get_client(url="http://localhost:2024")
```

```python
# 创建一份专供 A2A 调用的 Assistant
assistant = await client.assistants.create(
  graph_id="agent",
  name="poet-agent",
  description="专业诗人，可以编写古代、现代等不同风格的诗文",
  context={
    "system_prompt": (
      "1. 你必须使用子代理来完成诗文生成。"
      "2. 在生成诗文的过程中你必须至少调用一次 ask_user_question 来确认需求"
    )
  },
  metadata={
    "user_id": "a2a"  # 检索用标签，模拟用户 id
  }
)
assistant_id = assistant["assistant_id"]
assistant_id
```

`graph_id` 必须与 `langgraph.json` 的键一致。返回的 `assistant_id` 是 UUID，后续 Card 与 JSON-RPC 都用它，不能用图 ID `"agent"` 代替。

> **说明：** Assistant 的 `metadata` 不注入图运行。第25章长期记忆读取的是 Thread `metadata` 里的 `user_id`；A2A 把 `contextId` 映射为 `thread_id`，不会把 Assistant 上的 `user_id` 自动写入 Thread。

## 访问 A2A 服务器

### Agent Card

A2A 服务器会暴露一个发现地址，规范路径通常为 `/.well-known/agent-card.json`。请求该地址得到一份 Agent Card，描述如何与该 Agent 交流。

Agent Server 按 Assistant 区分，路径为：

```text
GET /.well-known/agent-card.json?assistant_id={assistant_id}
```

```python
card = await client.http.get(
  "/.well-known/agent-card.json",
  params={"assistant_id": assistant_id},
)
card
```

Card 中通常包含名称、描述、技能、默认输入输出模式，以及 JSON-RPC 入口 URL。该 URL 对应：

```text
POST /a2a/{assistant_id}
```

部分部署也提供按 Assistant 嵌套的路径：`GET /a2a/{assistant_id}/.well-known/agent-card.json`。本地开发以带查询参数的规范路径为准。

### JSON-RPC 通信

向上述 URL 发送 JSON-RPC 2.0 请求。Agent Server 按 `method` 分发：

| 方法             | 含义                         |
| ---------------- | ---------------------------- |
| `message/send`   | 发送消息并等待最终 Task      |
| `message/stream` | 发送消息，以 SSE 返回        |
| `tasks/get`      | 按 ID 读取 Task              |
| `tasks/cancel`   | 请求取消该 Task              |

只实现 JSON-RPC 绑定；gRPC 与 HTTP+JSON 不可用。文本部件要求图状态含 `messages` 字段。

```python
import uuid

payload = {
  "jsonrpc": "2.0",
  "id": str(uuid.uuid4()),
  "method": "message/send",
  "params": {
    "message": {
      "role": "user",
      "parts": [{"kind": "text", "text": "写一首关于秋天的五言绝句"}],
      "messageId": str(uuid.uuid4()),
    }
  },
}

result = await client.http.post(f"/a2a/{assistant_id}", json=payload)
result
```

首轮不要带 `contextId` / `taskId`，服务端会生成并在结果里返回。后续轮次只带回 `contextId`，即可落在同一条 Thread；已结束的 Task 不要再复用其 `taskId`。需要向仍在进行的任务追加输入（例如中断等待答复）时，才带上该 `taskId`。

> **说明：** 本例系统提示词要求调用 `ask_user_question`，图会走到第22章的中断，Task 停留在等待输入。此时应读取返回的 `taskId`，在后续 `message/send` 中带上，而不是新开一个 Task。
