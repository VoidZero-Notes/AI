Thread 是 Agent Server 上可持久化的会话容器，同一线程上的多次 Run 共享检查点。本篇用 `langgraph-sdk` 调用 Threads 接口：创建、查询、更新、搜索、复制、读取状态与历史、清理与删除。第07章在进程内用 `thread_id` + Checkpointer 保存图状态，是同一机制在服务端的落地；第13章的 SDK 管理的是 Assistant（图的一份配置），不发起运行、也不读写线程，与本篇的对象不同。调用前须已按第05章启动本地服务，并按第13章安装 SDK。

Agent底层逻辑第07章的 Session：那边按 id 读写消息列表。第07章把同一件事做成进程内检查点；这里 Thread 是服务端的会话容器，检查点由 Agent Server 注入的存储器写入。一次执行仍是 Run（第15章）。本篇前半只管理线程记录；读状态与历史前会先发起一次 Run，仅用于写入检查点，接口细节见第15章。

文档：[Threads](https://docs.langchain.com/langsmith/use-threads) · [ThreadsClient](https://reference.langchain.com/python/langgraph-sdk/_async/threads/ThreadsClient) · 本地 OpenAPI：`http://localhost:2024/docs#tag/threads`

| 概念        | 作用                                                             |
| ----------- | ---------------------------------------------------------------- |
| Thread      | 一条可持久化的会话容器。同一线程上的多次 Run 共享检查点          |
| `thread_id` | 创建后返回的 UUID，后续接口都用它标识这一条会话                  |
| `status`    | `idle`（空闲）/ `busy`（执行中）/ `interrupted`（中断）/ `error` |
| `metadata`  | 仅供搜索过滤。更新时与已有键值合并                               |
| `values`    | 线程当前的图状态。未运行过时为 `None`                            |
| 检查点      | 一次超步结束时的状态快照（第06章、第07章）。历史里每一项对应一个 |

创建线程时**不会**绑定图。`metadata` 里的 `graph_id` 只供搜索；真正关联 Assistant / 图发生在该线程上发起 Run 时（第15章）。加入线程流、协议 v2 命令、`update_state`（时间旅行）本篇不展开；进程内改状态见第07章。

## 创建客户端

第13章已安装 `langgraph-sdk==0.4.2`。连接本地 Agent Server，得到 `client.threads`：

```python
from langgraph_sdk import get_client

client = get_client(url="http://localhost:2024")
client
```

`get_client` 返回异步客户端，后续调用均须 `await`。同步客户端用 `get_sync_client`，接口同名、去掉 `await`。

## 创建线程

> POST /threads

创建时可附带 `metadata`，供后续搜索过滤：

```python
thread = await client.threads.create(
  metadata={
    "title": "新会话",
    "user_id": "007",
    "graph_id": "agent",
  },
)
thread
```

保存 `thread_id`：

```python
thread_id = thread["thread_id"]
thread_id
```

极少用的字段：`ttl` 控制线程存活周期（到期自动清理）；`supersteps` 可在创建时直接写入若干检查点状态。需要时再查 OpenAPI。

## 获取线程

> GET /threads/{thread_id}

按 ID 读取线程记录（不是图状态；状态用后面的 `get_state`）：

```python
thread = await client.threads.get(thread_id)
thread
```

返回字段里常用的是：

| 字段               | 含义                                               |
| ------------------ | -------------------------------------------------- |
| `state_updated_at` | 状态最近更新时间。每次运行产生新检查点时变化       |
| `status`           | 见上表                                             |
| `config`           | 最新一次运行使用的配置，来自 Assistant 的 `config` |
| `values`           | 当前图状态。未运行过为 `None`                      |
| `metadata`         | 创建 / 更新时写入的键值                            |

## 更新线程

> PATCH /threads/{thread_id}

更新 `metadata`。新键值与已有键**合并**，未出现的旧键保留：

```python
thread_v2 = await client.threads.update(
  thread_id,
  metadata={"title": "langgraph_sdk 的使用方法"},
)
thread_v2
```

`user_id`、`graph_id` 仍在；只有 `title` 被覆盖。这与第13章 Assistant 的 `config` / `context` **不合并**不同。

## 搜索线程

> POST /threads/search

按 `metadata`、`values`、`status` 过滤，支持分页与排序。不传过滤条件时列出全部线程：

```python
result = await client.threads.search(
  metadata={"user_id": "007"},
  limit=10,
)
result
```

使用 `select` 可指定返回字段：

```python
result = await client.threads.search(
  limit=5,
  offset=0,
  sort_by="created_at",
  sort_order="desc",
  select=["thread_id", "status", "created_at"],
)
result
```

每个元素的字段与「获取线程」一致；指定了 `select` 则只返回选中字段。

## 统计线程数量

> POST /threads/count

过滤条件与 `search` 相同，只返回数量：

```python
count = await client.threads.count()
print(f"线程数量: {count}")
```

## 写入一次状态（供后续接口使用）

未运行过的线程没有检查点，`get_history` 为空。文档语义下 `get_state` 的 `values` 为 `None`；本地 inmem 上对空线程（尤其是 `copy` 出来的）`get_state` 可能直接 500，见下一节。下面用第15章的 `runs.wait` 往这条线程写入一次运行，仅为本篇后面的状态 / 历史 / 复制提供数据：

```python
await client.runs.wait(
  thread_id=thread_id,
  assistant_id="agent",
  input={"messages": [{"role": "user", "content": "你好"}]},
)
```

`assistant_id="agent"` 使用默认 Assistant（第13章：图 ID 与 UUID 不可互换）。

## 获取线程状态

> GET /threads/{thread_id}/state

读取最新检查点的状态：

```python
import json

state = await client.threads.get_state(thread_id)
print(json.dumps(state, indent=2, ensure_ascii=False))
```

未运行过的线程没有检查点。文档语义是 `values` 为 `None`；本地 `langgraph dev`（in-memory checkpointer）上，对**从未 Run 过的线程** `copy` 后再 `get_state`，会 500：`KeyError: ''`（查询根命名空间 `checkpoint_ns=""` 时，空存储被拷成普通 `dict`，访问失败）。源线程若仍是 `defaultdict`，`get_state` 可能返回空状态而不崩。

因此：先完成上一节的 `runs.wait`，再读状态。若读的是复制线程，必须在源线程已有检查点之后再 `copy`，并对**新的** `copy_thread_id` 调用。Run 之前拷出的旧 id 不会因为后来源线程跑过而补上检查点，需要重新 `copy`。

| 字段                   | 含义                                                        |
| ---------------------- | ----------------------------------------------------------- |
| `values`               | 图的最新状态（如 `messages`）                               |
| `next`                 | 下一步要执行的节点；空列表表示已执行完毕                    |
| `tasks`                | 正在排队 / 执行中的任务                                     |
| `metadata`             | 本次运行的元数据（`graph_id`、`assistant_id` 等）           |
| `checkpoint`           | 最新检查点（`checkpoint_id`、`thread_id`、`checkpoint_ns`） |
| `checkpoint_id`        | 每个超步产生一个                                            |
| `parent_checkpoint_id` | 上一个检查点                                                |
| `interrupts`           | 人机环中断时才会有内容                                      |
| `created_at`           | 检查点创建时间                                              |

这是服务端版的第07章 `get_state`：进程内读的是本进程 Checkpointer；这里读的是 Agent Server 为该 `thread_id` 保存的快照。

## 获取线程历史

> GET /threads/{thread_id}/history

列出该线程上的全部历史状态。每个超步产生一个检查点，对应列表中的一项：

```python
history = await client.threads.get_history(thread_id, limit=10)
print(json.dumps(history, indent=2, ensure_ascii=False))
```

每项字段与「获取线程状态」一致。`metadata.step` 为超步序号。等价于第07章的 `get_state_history`。

## 获取指定检查点状态

> GET /threads/{thread_id}/state/{checkpoint_id}

按 `checkpoint_id` 读取某一历史时刻的状态，用于回溯。`checkpoint_id` 从上一节的历史里取：

```python
checkpoint_id = history[0]["checkpoint"]["checkpoint_id"]
state = await client.threads.get_state(thread_id, checkpoint_id=checkpoint_id)
state
```

返回结构与「获取线程状态」相同，只是对应指定检查点那一刻。

## 复制线程

> POST /threads/{thread_id}/copy

连同状态和检查点一起复制，得到一条新线程；旧线程不受影响：

```python
copy_thread = await client.threads.copy(thread_id)
copy_thread_id = copy_thread["thread_id"]
copy_thread_id
```

返回字段与「获取线程」一致，`thread_id` 为新生成。复制出的线程自带当时已有的检查点，适合拿去试验清理 / 删除而不动原会话。源线程从未 Run 过则没有检查点可拷；本地 inmem 下对这种空拷贝调用 `get_state` 会 500，见「获取线程状态」。须先 `runs.wait` 再 `copy`。

## 清理线程

> POST /threads/prune

按 ID 批量清理。`strategy="delete"` 删除整个线程；`strategy="keep_latest"` 只丢掉旧检查点，保留线程及最新状态：

```python
result = await client.threads.prune(
  thread_ids=[copy_thread_id],
  strategy="keep_latest",
)
result
```

返回 `pruned_count`：实际清理的线程数量。

## 删除线程

> DELETE /threads/{thread_id}

删除线程时，其所有检查点一并删除。删除后再次 `get` 会抛出 `NotFoundError`：

```python
from langgraph_sdk.errors import NotFoundError

await client.threads.delete(copy_thread_id)

try:
  await client.threads.get(copy_thread_id)
except NotFoundError as e:
  print("已删除：", e)
```

演示用完后把原线程也删掉，避免本地服务里堆积测试会话：

```python
await client.threads.delete(thread_id)
```
