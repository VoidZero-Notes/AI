Store 是跨线程、跨会话的长期键值存储：数据不依附某一次图执行，可在新对话中读取用户信息，也可在多条线程或多个 Agent 之间共享。本篇覆盖进程内 `InMemoryStore` 的增删改查，以及 Agent Server 上经 SDK 调用的同一套 Store 接口。

第07章的 Checkpointer 保存某一 `thread` 的图状态，线程之间彼此隔离。需要跨线程长期保留的用户偏好、资料、从对话中提取的稳定事实，应写入 Store，而不是写进检查点。

Agent底层逻辑第07章把「外部记忆」与 Session 并列：用户偏好、长期事实写入数据库或向量库，需要时检索再注入当前 `messages`。LangGraph 的 Store 就是这件事的落地：第07章的 Thread / Checkpointer 对应那边的 Session（会话内短时状态），Store 对应外部长期记忆。第05章的 Agent Server 在服务端注入 Store；第12章的 `Runtime` 是节点读取这份 Store 的容器。本篇只讲 Store 本身的读写 API，不把 Store 接到图节点上。

文档：[Stores](https://docs.langchain.com/oss/python/langgraph/stores) · [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) · [InMemoryStore](https://reference.langchain.com/python/langgraph.store/memory/InMemoryStore) · 本地 OpenAPI：`http://localhost:2024/docs#tag/store`

| 概念            | 作用                                                                              |
| --------------- | --------------------------------------------------------------------------------- |
| Store           | 跨线程长期键值存储。不进图状态，不随某条 thread 的检查点走                        |
| Checkpointer    | 某一 thread 的图状态快照（第07章）                                                |
| `namespace`     | 命名空间，用元组表示，相当于数据所在的目录                                        |
| `key`           | 当前命名空间内的唯一标识                                                          |
| `value`         | 真正保存的数据，必须是字典                                                        |
| `Item`          | 进程内查询返回的对象：`namespace` / `key` / `value` / `created_at` / `updated_at` |
| `InMemoryStore` | 内存后端。进程退出后数据消失                                                      |

通常用于实现长期记忆：

- **用户偏好**：用户曾经说过「回答时请使用中文」。即使下次开启新对话，Agent 仍可从 Store 读取该偏好。
- **用户资料**：记住用户的姓名、职业、所在城市等稳定信息，在之后的不同会话中提供个性化服务。
- **状态跟踪**：把「用户正在学习 LangGraph」这类值得长期保留的信息从对话状态中提取出来，写入 Store。

## LangGraph API

### 创建 Memory Store

一条数据由三部分组成：`namespace`、`key`、`value`。层级如下：

```text
Store
└── namespace（命名空间）
    ├── key → value
    ├── key → value
    └── key → value
```

```python
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()
namespace = ("users", "user_001", "memory")
```

`InMemoryStore` 仅存在于当前进程。需要写入磁盘或跨进程时，换 PostgreSQL 等后端，接口相同。

本篇示例一律用异步接口。同步方法签名与返回值相同，去掉 `a` 前缀、不必 `await`：

| 异步                 | 同步                |
| -------------------- | ------------------- |
| `aput`               | `put`               |
| `aget`               | `get`               |
| `asearch`            | `search`            |
| `alist_namespaces`   | `list_namespaces`   |
| `adelete`            | `delete`            |

### 增加数据

使用异步方法 `aput` 写入。同一个命名空间中，`key` 唯一标识一条数据：

```python
await store.aput(
  namespace,
  key="profile",
  value={"name": "张三", "city": "上海", "job": "Python 工程师"},
)

await store.aput(
  namespace,
  key="preferences",
  value={"language": "中文", "response_style": "简洁"},
)
```

### 查询单条数据

使用异步方法 `aget`，按 `namespace + key` 精确查询一条数据：

```python
profile = await store.aget(namespace, key="profile")
profile
```

返回如下：

```text
Item(
  namespace=['users', 'user_001', 'memory'],
  key='profile',
  value={'name': '张三', 'city': '上海', 'job': 'Python 工程师'},
  created_at='2026-08-18T02:02:10.402312+00:00',
  updated_at='2026-08-18T02:02:10.402314+00:00'
)
```

键不存在时返回 `None`。

### 查询多条数据

使用异步方法 `asearch` 查询某个命名空间下的多条数据：

```python
items = await store.asearch(namespace)
[(item.key, item.value) for item in items]
```

返回如下：

```text
[
  ('profile', {'name': '张三', 'city': '上海', 'job': 'Python 工程师'}),
  ('preferences', {'language': '中文', 'response_style': '简洁'})
]
```

### 查询子命名空间

使用异步方法 `alist_namespaces` 查询父命名空间下的子命名空间。`prefix` 指定父命名空间，`max_depth` 限制返回的命名空间深度：

```python
namespaces = await store.alist_namespaces(
  prefix=("users",),
  max_depth=4,
)
namespaces
```

返回如下：

```text
[('users', 'user_001', 'memory')]
```

### 修改数据

Store 没有单独的 `update` 方法。使用相同的 `namespace + key` 再次调用 `aput`，就会覆盖原数据：

```python
await store.aput(
  namespace,
  key="profile",
  value={"name": "张三", "city": "杭州", "job": "AI 工程师"},
)

updated_profile = await store.aget(namespace, key="profile")
updated_profile
```

返回如下：

```text
Item(
  namespace=['users', 'user_001', 'memory'],
  key='profile',
  value={'name': '张三', 'city': '杭州', 'job': 'AI 工程师'},
  created_at='2026-08-18T02:05:09.322899+00:00',
  updated_at='2026-08-18T02:05:09.322901+00:00'
)
```

`aput` 会整体替换原来的 `value`，不会自动合并新旧字典。上例若只想改 `city`，仍须把 `name`、`job` 一并传入，否则这两项会丢失。

### 删除数据

使用异步方法 `adelete` 删除指定数据。删除不存在的键不会报错：

```python
await store.adelete(namespace, key="profile")
await store.aget(namespace, key="profile")
```

返回如下：

```text
None
```

再清理示例中剩余的数据：

```python
await store.adelete(namespace, key="preferences")
await store.asearch(namespace)
```

返回如下：

```text
[]
```

## Agent Server API

Agent Server 通过 Store API 对外提供长期存储。这些数据不依赖图、Assistant 或 Thread，经 `client.store` 访问。调用前须已按第05章启动本地服务，并按第13章安装 SDK。使用 Agent Server 时不要在图代码里自行配置 store——服务会注入（第05章）。

本地 OpenAPI：`http://localhost:2024/docs#tag/store`

| 接口                     | 含义           |
| ------------------------ | -------------- |
| PUT /store/items         | 存储或更新条目 |
| DELETE /store/items      | 删除条目       |
| GET /store/items         | 获取条目       |
| POST /store/items/search | 搜索或列出条目 |
| POST /store/namespaces   | 列出命名空间   |

### 创建客户端

连接本地 Agent Server（默认端口 2024）：

```python
from langgraph_sdk import get_client

client = get_client(url="http://localhost:2024")
server_namespace = ("users", "user_002", "memory")
```

`get_client` 返回异步客户端，后续调用均须 `await`。同步客户端用 `get_sync_client`，接口同名、去掉 `await`。

### 增加数据

> PUT /store/items

使用 `put_item` 写入数据：

```python
await client.store.put_item(
  server_namespace,
  key="profile",
  value={"name": "李四", "city": "北京", "job": "Python 工程师"},
)

await client.store.put_item(
  server_namespace,
  key="preferences",
  value={"language": "中文", "response_style": "简洁"},
)
```

### 查询单条数据

> GET /store/items

使用 `get_item` 按 `namespace + key` 精确查询一条数据：

```python
profile = await client.store.get_item(
  server_namespace,
  key="profile",
)
profile
```

返回如下：

```text
{
  'namespace': ['users', 'user_002', 'memory'],
  'key': 'profile',
  'value': {'name': '李四', 'city': '北京', 'job': 'Python 工程师'},
  'created_at': '2026-08-18T02:05:56.665619+00:00',
  'updated_at': '2026-08-18T02:05:56.665624+00:00'
}
```

> **说明：** 进程内 `aget` 返回 `Item` 对象；SDK `get_item` 返回字段相同的字典。

### 查询多条数据

> POST /store/items/search

使用 `search_items` 查询某个命名空间下的多条数据：

```python
result = await client.store.search_items(server_namespace)
[(item["key"], item["value"]) for item in result["items"]]
```

返回如下：

```text
[
  ('profile', {'name': '李四', 'city': '北京', 'job': 'Python 工程师'}),
  ('preferences', {'language': '中文', 'response_style': '简洁'})
]
```

### 查询子命名空间

> POST /store/namespaces

使用 `list_namespaces` 查询父命名空间下的子命名空间：

```python
result = await client.store.list_namespaces(
  prefix=["users"],
  max_depth=4,
)
result["namespaces"]
```

返回如下：

```text
[['users', 'user_002', 'memory']]
```

> **说明：** 进程内 `alist_namespaces` 的 `prefix` 用元组，返回元组列表；SDK 的 `list_namespaces` 的 `prefix` 用列表，返回 `{"namespaces": [...]}`，内部也是列表。

### 修改数据

> PUT /store/items

Store API 同样没有单独的更新接口。使用相同的 `namespace + key` 再次调用 `put_item`，就会覆盖原数据：

```python
await client.store.put_item(
  server_namespace,
  key="profile",
  value={"name": "李四", "city": "深圳", "job": "AI 工程师"},
)

updated_profile = await client.store.get_item(
  server_namespace,
  key="profile",
)
updated_profile
```

返回如下：

```text
{
  'namespace': ['users', 'user_002', 'memory'],
  'key': 'profile',
  'value': {'name': '李四', 'city': '深圳', 'job': 'AI 工程师'},
  'created_at': '2026-08-18T02:06:25.081953+00:00',
  'updated_at': '2026-08-18T02:06:25.081958+00:00'
}
```

`put_item` 会整体替换原来的 `value`，不会自动合并新旧字典。

### 删除数据

> DELETE /store/items

使用 `delete_item` 删除指定数据：

```python
await client.store.delete_item(server_namespace, key="profile")

result = await client.store.search_items(server_namespace)
[(item["key"], item["value"]) for item in result["items"]]
```

返回如下：

```text
[('preferences', {'language': '中文', 'response_style': '简洁'})]
```

再清理示例中剩余的数据：

```python
await client.store.delete_item(server_namespace, key="preferences")
await client.store.search_items(server_namespace)
```

返回如下：

```text
{'items': []}
```
