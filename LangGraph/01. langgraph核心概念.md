LangGraph 是 LangChain 团队出的工作流编排库：把多步骤任务收成一张**可执行的图**。节点做事，边决定下一步走哪，图状态在节点之间共享。

Agent底层逻辑第10章的 ReAct 是一条 `while True`：同一目标反复做，直到停。真实任务很少是一条直道——常见形状是分支、汇合、回退、人审门闸。这些如果塞进循环和提示词，控制流看不见，也难回放。LangGraph 把控制流抬成一等公民：先把拓扑画清楚，再编译运行。Agent底层逻辑第17章说的 Graph Engineering 是「多个 loop 怎么接线」；LangGraph 是把这件事落地的库之一。

它出现的目的：让有状态、可循环、带分支的 LLM 应用能被显式接线，而不是把流程藏在 `if-else` 和提示词里。

这篇先跑通最小例子，再收节点、边、图状态，以及定义 → 编译 → 运行三个阶段。

## 第一个程序

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# 图状态
class MyState(TypedDict, total=False):
  node1: str  # node1 channel
  node2: str  # node2 channel

# 创建图
workflow = StateGraph(MyState)

def node1(state: MyState):
  return {"node1": "node1 result"}

def node2(state: MyState):
  return {"node2": "node2 result"}

(
  workflow.add_node(node1)
  .add_node(node2)
  .add_edge(START, "node1")
  .add_edge("node1", "node2")
  .add_edge("node2", END)
)

graph = workflow.compile()

print(graph.invoke({}))  # {'node1': 'node1 result', 'node2': 'node2 result'}
```

外层括号没有 API 含义。`add_node` / `add_edge` 返回 `workflow` 自身，所以能链式调用；括号只是让 Python 把这几行当成**一个表达式**（隐式续行），等价于写成一行。

`START` 和 `END` 不是你写的节点函数，而是图的虚拟起点、终点：边从 `START` 出发，接到 `END` 这条路径就结束。源码里它们就是字符串常量（`sys.intern` 过，方便身份比较）：

```python
print(START)  # __start__
print(END)    # __end__
print(START == "__start__")  # True
print(END == "__end__")      # True
```

自己的节点名不要用 `"__start__"` / `"__end__"`，这两个是保留标识。

`workflow.compile()` 把构建器上的节点和边**固定**成一张可运行的图。编译结果（这里的 `graph`）不能再 `add_node` / `add_edge`，运行时也不能动态增删节点或边。要改结构，只能改 `workflow` 再 `compile()` 出一张新图；已经编译好的那张不会跟着变。

```python
from langchain_core.runnables import Runnable

print(isinstance(graph, Runnable))  # True
```

编译结果是 `Runnable`，所以能用 `invoke` / `ainvoke` / `stream` 等接口去跑。

## 核心概念

![image-20260830232538756](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-08-30-152539.png)

图上就三样东西：

| 元素 | 功能 |
| --- | --- |
| **节点** | 一步计算。读当前图状态，做事（调模型、跑函数、调工具），返回要写入状态的字段 |
| **边** | 节点之间的连线。规定执行顺序：这一步完了走哪一步；`START` / `END` 标虚拟起止 |
| **图状态** | 整张图共享的一份数据。节点靠它传东西；图跑完，得到的结果就是最新状态 |

构建和运行还要两样：

| 概念 | 作用 |
| --- | --- |
| `StateGraph` | 图的构建器，只描述节点、边、状态结构，本身不可运行 |
| `compile()` | 校验并固化拓扑，得到可运行的图 |

### 三个阶段

定义 → 编译 → 运行

1. **定义**
   - 节点
   - 边
   - 图状态结构

2. **编译**

   定义好的图是不可运行的，它只是一个描述。

   若要运行图，需要进行编译。

   编译好的图，节点和边会固定下来，不能动态变化。

3. **运行**

   编译结果可以运行。

   > langgraph 底层使用 Pregel 系统运行图。
   >
   > Pregel 来自 2010 年的谷歌论文，论文中详细阐述了图的执行。
   >
   > https://dl.acm.org/doi/10.1145/1807167.1807184

### 节点

节点是图上的一步：接收当前图状态，做完自己的事，返回一份更新（不是整份状态）。谁先跑、谁后跑，不由节点自己决定，由边决定。

节点可以接收以下类型：

- 可调用对象：实现了 `__call__` 的对象
- Runnable 对象：`Runnable` 是 `langchain_core` 中定义的类型

```python
from langchain_core.runnables import Runnable

print(hasattr(Runnable, "invoke"))      # 执行
print(hasattr(Runnable, "ainvoke"))     # 异步执行
print(hasattr(Runnable, "stream"))      # 流式执行
print(hasattr(Runnable, "astream"))     # 异步流式执行
print(hasattr(Runnable, "batch"))       # 批量执行
print(hasattr(Runnable, "abatch"))      # 异步批量执行
```

### 边

边是节点之间的连线，只负责**走向**，不做事。无条件边永远从 A 走到 B；后面还会碰到按状态选择下一跳的条件边。

`START` → 第一个节点：图从哪开始。最后一个节点 → `END`：这条路径到此结束。至少要有边接到 `END`，否则图不知道何时停。

### 图状态

图状态是整张图的共享数据空间，图在执行期间，每个节点都可以获取到完整的图状态，也可以更新图状态。

图执行完后，得到的结果就是最新的图状态。

<img src="https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-08-30-151737.png" alt="image-20260830231737297" style="zoom:33%;" />

图状态本质上是一个字典，字典的每一个字段称之为 channel（通道）。

### 通道

通道是图状态里的一个**具名字段**：上面例子里的 `node1`、`node2` 各是一条通道。节点读的是整份状态，写的时候只声明「更新哪几条通道」；运行时按通道把更新合进状态，而不是让节点直接改整个字典。

默认行为是后写覆盖。多条更新打到同一通道时，由这条通道自己的合并规则决定怎么合（例如覆盖、拼接）。通道把「状态里有哪些槽、每个槽怎么更新」从节点逻辑里拆出来。
