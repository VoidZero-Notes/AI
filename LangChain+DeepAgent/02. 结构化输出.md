## 含义

让某个`Agent`始终遵循某种`JSON`输出格式，比如：

```json
{
  "name": "张三",
  "phone": "13300001111",
  "address": "四川省成都市xxxx"
}
```

## 场景

**信息抽取**

```json
{
  "name": "张三",
  "phone": "13300001111",
  "address": "四川省成都市xxxx"
}
```

**分类或打标签**

```json
{
  "category": "退款",
  "urgency": "高"
}
```

**情感分析**

```json
{
  "sentiment": "负面",
  "score": 0.92,
  "reason": "用户对等待时间不满"
}
```

**生成数据库记录**

```json
{
  "customer_name": "李明",
  "phone": "138...",
  "appointment_time": "2026-08-21 14:00"
}
```

...

## 实现

`create_agent` 的 `response_format` 决定结构化结果怎么产出。三种写法：

- 直接传 schema（如 `AddressInfo`）：把 schema 交给框架，由它按模型能力自动选策略
- `ProviderStrategy`：强制走厂商原生结构化输出
- `ToolStrategy`：强制挂一个「提交结构化结果」的假工具

`AddressInfo` 只规定最终 `structured_response` 的形状（`name` / `phone` / `address` 必填），本身不决定调用方式。

langchain_project\agents\address_parser.py

```python
from langchain_project.core.config import openai_settings, anthropic_settings
from langchain.agents import create_agent
from langchain.agents.structured_output import ProviderStrategy, ToolStrategy
from pydantic import BaseModel, Field
from langchain_project.tools import tools, ask_user_question
from langchain.chat_models import init_chat_model

class AddressInfo(BaseModel):
  """用户收货地址信息"""

  name: str = Field(description="姓名")
  phone: str = Field(description="电话")
  address: str = Field(description="地址")


model = init_chat_model(
  model=anthropic_settings.default_model,
  model_provider="anthropic",
  thinking={"type": "disabled"},
)

agent = create_agent(
  model=model,
  system_prompt="请根据提供的信息提取出收货地址的结构化信息，如果提供的信息不全，必须使用 ask_user_question 工具让用户补充信息",
  tools=[ask_user_question],
  response_format=AddressInfo,
)
```

上面 `response_format=AddressInfo` 是自动选策略。Anthropic Claude 支持原生结构化输出，实际会走 `ProviderStrategy`；模型不支持时退回 `ToolStrategy`。

|                        | `AddressInfo`                        | `ProviderStrategy(AddressInfo)`                                                    | `ToolStrategy(AddressInfo)`                                          |
| ---------------------- | ------------------------------------ | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 角色                   | schema，自动选策略                   | 强制原生结构化输出                                                                 | 强制用假工具提交结果                                                 |
| 机制                   | 模型支持原生 → Provider；否则 → Tool | 厂商接口按 schema 约束生成（OpenAI `json_schema`、Anthropic structured output 等） | 模型结束时调用「提交结果」工具，框架校验后写入 `structured_response` |
| 可靠性                 | 看模型                               | 通常最高；部分厂商可设 `strict=True`                                               | 依赖 tool calling                                                    |
| 校验失败重试           | 否                                   | 否                                                                                 | 有（`handle_errors`：错误塞回对话再试）                              |
| Union 多 schema        | 否                                   | 否                                                                                 | 支持                                                                 |
| 与 `ask_user_question` | Claude 上可并存                      | 可并存                                                                             | 并存，但和业务工具抢同一 tool-calling 通道；结束靠再调一次提交工具   |

读结果一律用 `result["structured_response"]`，不要看最后一条 AI 文本。

## 最佳实现

Agent 不带业务工具时，用 `ProviderStrategy`，并选支持 `json_schema` / 原生结构化输出的厂商。

Agent 需要业务工具（如 `ask_user_question`）且模型不支持「工具 + 原生结构化输出」并存时，用 `ToolStrategy`。Claude 上两者可并存，直接传 `AddressInfo` 即可。
