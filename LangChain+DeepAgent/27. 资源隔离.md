同一服务上的多个用户各自只能访问自己的资源。线程等资源在创建时写入隔离键，此处为当前用户标识；之后的读取与搜索按该键筛选。存储（Store）以命名空间第一段作为隔离条件，该段必须等于当前用户标识。本篇在授权处理函数中实现这两类隔离，并用两名用户的线程搜索与存储读写对照结果。

## 普通资源隔离

需要按所有者隔离的资源，创建时在元数据中写入隔离键，键名为 `owner`，值为当前用户标识。后续搜索与读取只返回该键与当前用户一致的记录。

`langchain_project/core/auth.py` 在认证之后注册授权处理函数。`MOCK_USER` 将令牌映射为用户：`identity` 为用户标识，`permissions` 为允许的 `{资源}:{动作}`。`authenticate` 校验请求头 `Authorization: Bearer <token>`。值为空、无法分离出令牌，或令牌不在 `MOCK_USER` 中时，抛出状态码 401、详情为 `invalid token` 的 `HTTPException`。`authorization.partition(" ")` 取出第三段作为令牌。

`@auth.on` 是默认处理函数，未单独注册的资源（如线程）走这里。函数先核对 `{资源}:{动作}` 是否在 `ctx.permissions` 中，不在则返回 `False`，请求被拒绝。通过后把 `owner` 写入请求元数据，并返回 `{"owner": 当前用户标识}`。创建时该字段随资源保存；搜索与读取时，该返回值作为筛选条件，只保留所有者为当前用户的记录。

已为某一资源单独注册处理函数时，该资源由专用函数处理。`@auth.on.assistants` 只做权限核对。`@auth.on.store` 在权限核对之外，还要求命名空间非空，且第一段等于 `ctx.user.identity`，否则返回 `False`。存储的约定见下文。

```python
from typing import Never

from langgraph_sdk import Auth
from .mock_user import MOCK_USER

auth = Auth()

def _raise_invalid_token() -> Never:
  raise Auth.exceptions.HTTPException(status_code=401, detail="invalid token")

@auth.authenticate
async def authenticate(
  authorization: str | None,
) -> Auth.types.MinimalUserDict:
  """验证 Authorization: Bearer <token> 并返回当前用户。"""
  if not authorization:
    _raise_invalid_token()
  schema, sep, token = authorization.partition(" ")
  if not token:
    _raise_invalid_token()
  # 解析token，通常要访问后端web服务（用户中心）
  if token not in MOCK_USER:
    _raise_invalid_token()

  return MOCK_USER[token]

@auth.on.store
async def on_store(ctx: Auth.types.AuthContext, value: dict):
  permission = f"{ctx.resource}:{ctx.action}"
  if permission not in ctx.permissions:
    return False
  namespace = tuple(value["namespace"]) if value["namespace"] else ()
  if not namespace or namespace[0] != ctx.user.identity:
    return False
  return True

@auth.on.assistants
async def on_assistants(ctx: Auth.types.AuthContext, value: dict):
  permission = f"{ctx.resource}:{ctx.action}"
  if permission not in ctx.permissions:
    return False
  return True

@auth.on
async def authorization(ctx: Auth.types.AuthContext, value: dict):
  permission = f"{ctx.resource}:{ctx.action}"
  if permission not in ctx.permissions:
    return False
  metadata = value.setdefault("metadata", {})
  metadata["owner"] = ctx.user.identity

  return {"owner": ctx.user.identity}
```

> **说明：** 处理函数返回 `False` 时，调用方得到 `PermissionDeniedError`，详情为 `Forbidden`。返回筛选字典时请求继续，结果中只含匹配记录；没有匹配记录时得到空列表。

### 创建线程

下列片段按 `main.py` 中的交互单元格书写，在支持顶层 `await` 的环境里顺序执行。两个客户端都指向本机 Agent Server `http://127.0.0.1:2024`：`user1` 使用 `Bearer user_1`，`user2` 使用 `Bearer user_2`。`threads.create` 经过默认授权处理函数，新建线程的 `metadata.owner` 为调用方的用户标识。后文搜索结果表明，`user_1` 对应的标识为 `user_id_001`。

```python
from langgraph_sdk import get_client

user1 = get_client(
  url="http://127.0.0.1:2024",

user2 = get_client(

  headers={"Authorization": "Bearer user_2"}
)

assistant_id = 'c3cdd36b-80ed-5994-823a-a26808ae54cd'

# %%
thread = await user1.threads.create( # type: ignore
  metadata={"__name__": "用户1的线程2"}
)
thread_id = thread["thread_id"]
```

## 存储隔离

存储项的隔离由命名空间完成。`on_store` 要求命名空间的第一段等于当前用户标识。

- 用户自行写入的项，必须以该用户的标识作为命名空间前缀。
- 图或后端代码写入的项，由写入方自行加上命名空间前缀。

`user1` 向命名空间 `["user_id_001", "store-demo"]` 写入键 `preference`。第一段与当前用户标识一致，写入通过。

```python
await user1.store.put_item( # type: ignore
  ["user_id_001", "store-demo"],
  key="preference",
  value={
    "theme": "dark",
    "lang": "zh-cn",
  }
)
```

在同一命名空间中搜索，返回刚写入的项。

```python
await user1.store.search_items( # type: ignore
  ["user_id_001", "store-demo"]
)
```

```python

```

仍以 `user1` 搜索命名空间 `["user_id_002", "store-demo"]`。第一段为 `user_id_002`，与 `user1` 的标识 `user_id_001` 不一致，`on_store` 返回 `False`，请求被拒绝。
