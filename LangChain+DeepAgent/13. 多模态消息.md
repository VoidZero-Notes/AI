多模态消息是把图像、PDF 等非文本载荷放进 LangChain 标准内容块，随 `HumanMessage` 或 `ToolMessage` 进入 Agent 循环。本篇说明两处处理：工具节点读取文件后如何构造多模态 `ToolMessage`；模型节点在请求前如何按模型 `profile` 重排消息，使不支持该模态的模型不会因非法载荷报错。这两步由 Deep Agents 默认中间件 `FilesystemMiddleware` 完成。

文件系统工具 `read_file` 读取图像、PDF 等文件后，会以多模态内容块（而非纯文本）返回。本篇落到两个包裹钩子上：`wrap_tool_call`（在工具节点内包住每次工具调用）产出该多模态形状，`wrap_model_call`（包住每次模型调用）按模型 `profile` 决定是否把这些块交给模型。

文档：[Multimodal](https://docs.langchain.com/oss/python/deepagents/multimodal) · [Model profiles](https://docs.langchain.com/oss/python/langchain/models#model-profiles) · [`FilesystemMiddleware`](https://reference.langchain.com/python/deepagents/middleware/filesystem/FilesystemMiddleware)

## 多模态消息位置

多模态载荷会出现在下列消息类型中：

- `ToolMessage`：`read_file` 等工具读取图片、PDF 后，结果写在这里
- `HumanMessage`：用户直接上传或粘贴多模态内容
- `AIMessage`：无额外处理，本篇不展开
- `SystemMessage`：几乎不会承载多模态载荷

## 核心问题

**消息格式。** 发生在工具节点：读取一张图片、一份 PDF 等文件后，应构造多模态消息，而不是纯文本。

**模型能力。** 并非所有模型都支持多模态。遇到不支持的模型，应重排消息，避免请求报错。

这两步由 `FilesystemMiddleware` 处理。

## 工具节点产出

`FilesystemMiddleware` 通过 `wrap_tool_call` 注入文件系统工具。读取图片、PDF 等文件后，针对该类型构造多模态 `ToolMessage`。`read_file` 读取图像、PDF 等文件时，返回的 `ToolMessage` 内容不是纯字符串，而是内容块列表：图像以图像块（含 base64 数据）承载，文本仍以文本块承载，模型据此看到图像本身。下图是这一步的形状。

![image-20260920211423033](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-09-20-131423.png)

`langchain_project/agents/demo/multimodal_demo.py`：`FilesystemBackend` 指向本机 `backup/files`。系统提示词约定：用户给出路径则调用 `read_file`；用户直接给出多模态消息则读取消息内容。`profile` 中 `image_inputs` 与 `image_tool_message` 均为 True。Studio 中发送 `test.jpg`，模型调用 `read_file: /test.jpg`，随后根据工具结果中的图像描述画面。

```python
from deepagents import create_deep_agent
from langchain.chat_models import init_chat_model
from langchain_project.core.config import anthropic_settings
from deepagents.backends import FilesystemBackend

model = init_chat_model(
  model="qwen3.7-flash",
  model_provider="anthropic",
  thinking={"type": "disabled"},
  profile={
    # 是否支持对应输入类型
    "image_inputs": True,
    "pdf_inputs": True,
    "audio_inputs": False,
    "video_inputs": False,
    # 是否允许媒体出现在工具结果 ToolMessage 中
    "image_tool_message": True,
    "pdf_tool_message": True,
  },
)

system_prompt = (
  "这是一个测试多模态的Demo。"
  "如果用户给予的是一个路径，"
  "比如，用户输入：test.jpg，你就调用工具 read_file: /test.jpg 文件即可。"
  "如果用户直接给予一个多模态消息，你就读取消息内容即可。"
)

agent = create_deep_agent(
  model=model,
  system_prompt=system_prompt,
  backend=FilesystemBackend(
    root_dir="F:/python/langChain-project/backup/files"
  ),
)
```

## 模型节点上下文重排

`FilesystemMiddleware` 通过 `wrap_model_call` 拦截消息中的文件相关内容块，按模型 `profile` 决定是否把这些块交给模型。判断依据是模型对象的 `profile` 属性。未声明的能力视为支持。

```python
profile = {
  # 是否支持对应输入类型
  "image_inputs": True,
  "pdf_inputs": True,
  "audio_inputs": False,
  "video_inputs": False,
  # 是否允许媒体出现在工具结果 ToolMessage 中
  "image_tool_message": False,
  "pdf_tool_message": True,
}
# 没有声明则表示支持
```

将同一入口的 `image_tool_message` 改为 False 后，图状态里的 `ToolMessage` 仍带图像块（Trace 中可见 base64），但发给模型的请求已去掉该媒体。模型回复无法查看图像。

换用声明为不支持多模态的模型（本例 `qwen3.7-max`），不传 `profile` 覆盖。`wrap_model_call` 按该模型的能力重排消息，请求不会因非法媒体报错；模型读到的是去掉图像后的上下文，回复无法直接处理图像。

```python
from deepagents import create_deep_agent
from langchain.chat_models import init_chat_model
from langchain_project.core.config import anthropic_settings
from deepagents.backends import FilesystemBackend

model = init_chat_model(
  model="qwen3.7-max",  # 这个模型不支持多模态
  model_provider="anthropic",
  thinking={"type": "disabled"},
)

system_prompt = (
  "这是一个测试多模态的Demo。"
  "如果用户给予的是一个路径，"
  "比如，用户输入：test.jpg，你就调用工具 read_file: /test.jpg 文件即可。"
  "如果用户直接给予一个多模态消息，你就读取消息内容即可。"
)

agent = create_deep_agent(
  model=model,
  system_prompt=system_prompt,
  backend=FilesystemBackend(
    root_dir="F:/python/langChain-project/backup/files"
  ),
)
```
