文件系统工具是 Deep Agents 默认 harness 注入的一组文件操作：`ls`、`read_file`、`write_file`、`edit_file`、`delete`、`glob`、`grep`。工具本身不决定文件落在何处；实际读写由 `backend` 完成。`backend` 实现 `BackendProtocol`，默认是 `StateBackend`：内容写入当前线程的图状态，不落本地磁盘。本篇说明这组工具与后端的关系，以及如何改用 `FilesystemBackend` 把文件写到指定目录。

Agent底层逻辑第08章的 Tool Calling、第09章的工具注册与执行，把 `read_file` / `write_file` 做成可调用工具并在循环中执行；本篇同一类动作由第05章清单中的 `FilesystemMiddleware` 注入，存储实现可替换。Agent底层逻辑第17章的 Harness Engineering 把文件系统列为模型外面的环境；Deep Agents 用 `backend` 落地这件事。文件随线程保存，对应 LangGraph第07章的线程和检查点。第06章 `create_deep_agent` 的 `backend` 参数把该后端传给文件系统中间件。

文档：[Backends](https://docs.langchain.com/oss/python/deepagents/backends) · [`FilesystemMiddleware`](https://reference.langchain.com/python/deepagents/middleware/filesystem/FilesystemMiddleware) · [`StateBackend`](https://reference.langchain.com/python/deepagents/backends/state/) · [`FilesystemBackend`](https://reference.langchain.com/python/deepagents/backends/filesystem/FilesystemBackend)

| 概念 | 作用 |
| --- | --- |
| `FilesystemMiddleware` | 默认 harness 中间件。向 Agent 注入文件系统工具，并把调用转给 `backend` |
| 文件系统工具 | `ls`、`read_file`、`write_file`、`edit_file`、`delete`、`glob`、`grep` |
| `backend` | 虚拟文件系统的存储实现。第06章已列为 `create_deep_agent` 选填参数 |
| `BackendProtocol` | 后端必须实现的协议。工具只依赖协议，不依赖具体存储 |
| `StateBackend` | 默认后端。文件写入当前线程图状态的 `files` 通道 |
| `FilesystemBackend` | 本地磁盘后端。在指定 `root_dir` 下读写真实文件 |
| `files` | `DeepAgentState` 中的通道。Studio Input 的 Files 字段对应它 |

## 工具与后端

模型看到的是工具；工具调用 `backend`；`backend` 实现 `BackendProtocol`。更换后端不更换工具名，只更换读写落点。

![image-20260916234213219](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-09-16-154213.png)

`create_deep_agent` 未传 `backend` 时，内部仍构造 `StateBackend()`，经 `FilesystemMiddleware` 挂到默认栈上。

| 工具 | 作用 |
| --- | --- |
| `ls` | 列出目录中的文件 |
| `read_file` | 读取文件。文本可按行分页；图像等以多模态块返回 |
| `write_file` | 创建文件；若已存在则整文件覆盖，不是追加 |
| `edit_file` | 在已有文件中做精确字符串替换，写入前须先 `read_file` |
| `delete` | 删除文件或目录 |
| `glob` | 按 glob 模式匹配路径 |
| `grep` | 按字面文本搜索内容，不是正则 |

> **说明：** `write_file` / `edit_file` / `delete` 的 schema 要求绝对路径。模型因此会自行给出以 `/` 开头的路径，例如 `/home/user/自由之诗.txt`。该路径是否对应本机磁盘，取决于当前 `backend`，而不是路径字符串本身。

## 默认 StateBackend

未传 `backend` 时即为 `StateBackend`。文件只存在于当前这条 Thread 的 graph state，经检查点在同一线程的后续轮次可读；不写入本地磁盘，更换 `thread_id` 后不可见。

在 Studio 中请求模型写诗并保存到本地。模型调用 `write_file`，自行选择虚拟路径 `/home/user/自由之诗.txt`，并回复称已保存。本机磁盘上没有该文件。

![image-20260916234232306](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-09-16-154232.png)

这不是工具执行失败。`write_file` 已写入当前线程状态的 `files` 通道；Studio 左侧 Input 的 Files 是下一次调用的入参，默认空对象 `{}`，不能用来判断本轮是否已写入状态。同一线程继续对话时，模型仍可用 `read_file` 读到这首诗；新开一条 Thread 则该通道为空。

`StateBackend` 适合中间草稿、大工具结果卸载：内容随当前线程保存，线程结束或更换后即不可见。需要本机可见、跨线程保留的产物时，应更换后端。

## 改用 FilesystemBackend

`FilesystemBackend` 在指定 `root_dir` 下读写真实文件。`root_dir` 须为绝对路径。工具集合不变，`write_file` 的落点改为该目录。

### Agent 入口

`langchain_project/agents/coding_agent.py`：在第06章的 Deep Agent 入口上增加 `backend`。模型与工具装配不变。

```python
from deepagents import create_deep_agent
from langchain.chat_models import init_chat_model
from langchain_project.core.config import anthropic_settings
from langchain_project.tools import tools
from deepagents.backends import FilesystemBackend

model = init_chat_model(
  model=anthropic_settings.default_model,
  model_provider="anthropic",
  thinking={"type": "disabled"},
)

agent = create_deep_agent(
  model=model,
  tools=tools,
  backend=FilesystemBackend(root_dir="F:/python/langChain-project/temp"),
)
```

传入后再请求模型把检索结果落盘。回复中的路径仍是虚拟绝对路径（下例为 `/mercedes_f1_driver_points.md`）；实际文件出现在 `root_dir` 目录中。

![image-20260916234253592](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-09-16-154253.png)

> **说明：** `FilesystemBackend` 授予 Agent 对该目录的真实读写，修改不可撤销。仅适合本地开发或受控环境。Web 服务、多租户接口应继续使用 `StateBackend`，或改用文档中的沙箱后端，并配合第05章的 `HumanInTheLoopMiddleware` 审批写操作。
