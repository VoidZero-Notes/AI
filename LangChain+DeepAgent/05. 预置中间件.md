预置中间件是 LangChain 为常见 Agent 工程需求提供的现成 `AgentMiddleware`：不改写 `model ⇄ tools` 主循环，只把重试、限流、摘要、人工审批、PII 检测、子 Agent 等能力以配置形式注入 `create_agent` 的 `middleware`。本篇给出完整清单，并以 `PIIMiddleware` 为实例，说明如何用确定性规则检测消息中的个人身份信息，再按 `redact` / `mask` / `hash` / `block` 处理输入、模型输出与工具结果。

03 说明自定义中间件的形态与两类钩子。本篇使用框架已实现的中间件，不改写钩子。`PIIMiddleware` 使用 03 的节点钩子 `before_model` / `after_model`，返回字典按 LangGraph第04章的 Reducer 写入 `messages`。

清单中 `HumanInTheLoopMiddleware` 对应 LangGraph第23章的人在回路（基于第22章的中断）；`SubAgentMiddleware` 对应 Agent底层逻辑第16章的子代理。本篇展开的是 `PIIMiddleware`。检测对象是 LangGraph第03章的 `HumanMessage` / `AIMessage` / `ToolMessage`。各示例使用 LangGraph第09章的 Mock Model（`parrot` 回显、固定文本、按规则发出工具调用）。经 Agent Server 登记图入口的方式与第01章相同（LangGraph第05章）；测试调用对应 LangGraph第15章的 `runs.wait`，线程对应第14章。

文档：[Built-in middleware](https://docs.langchain.com/oss/python/langchain/middleware/built-in) · [PIIMiddleware](https://reference.langchain.com/python/langchain/agents/middleware/PIIMiddleware)

| 概念 | 作用 |
| --- | --- |
| 预置中间件 | 框架提供的 `AgentMiddleware` 实现，配置后列入 `middleware` |
| PII | Personally Identifiable Information，能直接或间接识别个人的信息 |
| `PIIMiddleware` | 用确定性规则检测 PII，再按策略处理 |
| `redact` / `mask` / `hash` / `block` | 四种处理策略 |
| `apply_to_input` / `apply_to_output` / `apply_to_tool_results` | 拦截用户输入、模型输出、工具结果 |
| `detector` | 自定义正则或检测函数；缺省时使用内置类型 |

## 清单

| 类 | 作用 |
| --- | --- |
| `ToolErrorMiddleware` | 捕获工具执行异常，转换为模型可理解的错误消息。适合希望 Agent 自行修正参数或从工具错误中恢复的场景 |
| `ToolRetryMiddleware` | 工具调用失败时自动重试，支持指数退避。适合网络请求、外部 API 等可能暂时失败的工具 |

| `SummarizationMiddleware` | 上下文接近限制时，将较早的对话压缩为摘要。适合长对话或历史消息较多的 Agent |
| `HumanInTheLoopMiddleware` | 工具执行前暂停 Agent，等待人工批准、修改或拒绝。适合发送邮件、修改数据、资金交易等高风险操作 |
| `ModelCallLimitMiddleware` | 限制单次运行或整个线程中的模型调用次数。适合防止 Agent 无限循环或调用成本失控 |

| `PIIMiddleware` | 检测并按规则拦截、隐去、哈希或遮罩个人敏感信息。适合处理邮箱、信用卡号等隐私数据 |
| `TodoListMiddleware` | 为 Agent 提供任务拆分、计划和进度跟踪。适合需要协调多个步骤或工具的复杂任务 |
| `LLMToolSelectorMiddleware` | 先用一个模型筛选与当前任务相关的工具，再调用主模型。适合工具数量较多、需减少上下文消耗并提高选择准确性的 Agent |
| `ProviderToolSearchMiddleware` | 将部分工具延迟加载，由模型厂商的服务端搜索按需返回。适合支持工具搜索的模型与大规模工具集 |
| `ShellToolMiddleware` | 为 Agent 提供持久的 Shell 会话以执行系统命令。适合开发、部署、测试和脚本自动化；使用时需配置合适的隔离策略 |
| `FilesystemMiddleware` | 为 Agent 提供列出、读取、写入和编辑文件的能力，也可配置持久存储。适合用文件保存上下文、产物或长期记忆 |
| `SubAgentMiddleware` | 允许主 Agent 将任务交给子 Agent，并隔离各自的上下文。适合需要分工、专业化处理或避免主上下文膨胀的复杂任务 |
| `RubricMiddleware`（Beta） | 让 Agent 按预设标准自我评估并反复改进，直到达标或达到最大迭代次数。适合具有明确质量标准的内容生成、代码生成 |
| `FilesystemFileSearchMiddleware` | 为 Agent 提供 Glob 文件匹配和 Grep 内容搜索。适合在大型代码库或文件集中定位文件与内容 |
| `ContextEditingMiddleware` | 上下文过长时，清理较早的工具调用结果并保留最近结果。适合工具调用频繁的长时间对话，可减少 token 消耗 |
| `LLMToolEmulator` | 使用模型生成模拟的工具返回结果，代替真实工具执行。适合外部工具尚未实现、不可用或调用成本较高时的测试与原型验证 |

## PII

PII 是 **Personally Identifiable Information** 的缩写，即个人身份信息：能够直接或间接识别某个人的信息。常见类别包括：

- 姓名、身份证号、学号
- 手机号、邮箱、家庭住址
- 银行卡号、信用卡号
- IP 地址、设备地址

`PIIMiddleware` 使用确定性检测规则找到消息中的 PII，再按照指定策略处理。它不是包裹钩子（`wrap_model_call` / `wrap_tool_call`），而是节点钩子。

### 内置检查类型

| 类型 | 检测内容 |
| --- | --- |
| `email` | 邮箱地址 |
| `credit_card` | 通过 Luhn 校验的信用卡号 |
| `ip` | IPv4 地址 |
| `mac_address` | MAC 地址 |
| `url` | URL |

### 处理策略

| 策略 | 作用 | 示例 |
| --- | --- | --- |
| `redact` | 使用占位符替换 | `[REDACTED_EMAIL]` |
| `mask` | 隐藏一部分，只保留末尾字符 | `**** **** **** 1111` |
| `hash` | 替换为稳定的哈希值 | `<ip_hash:805ebf20>` |
| `block` | 抛出异常并终止 Run | `PIIDetectionError` |

`hash` 对匹配文本做 SHA-256，取十六进制前 8 位，格式为 `<{类型}_hash:{摘要}>`。上表中的 `805ebf20` 即 `192.168.1.10` 的摘要。同一输入每次得到同一哈希，可用于在隐去原文的前提下做关联分析。

`mask` 按类型有固定格式：信用卡保留末 4 位数字并沿用原文分隔符；自定义类型保留末 4 个字符，其余以 `****` 替换。

### 拦截位置

```text
  ...
   ↓
before_model  ← 检查点
   ↓
model
   ↓
after_model   ← 检查点
   ↓
  ...
```

`before_model` 和 `after_model` 都可能在一次 Run 中执行多次，因此模型输出检查针对的是**每次模型调用产生的 `AIMessage`**，而不只是 Run 的最终输出。

| 参数 | 默认值 | 检查对象 | 执行位置 |
| --- | --- | --- | --- |
| `apply_to_input` | `True` | 最近一条 `HumanMessage` | `before_model` |
| `apply_to_output` | `False` | 最近一条 `AIMessage` | `after_model` |
| `apply_to_tool_results` | `False` | 工具产生的 `ToolMessage` | 下一次调用模型前的 `before_model` |

检测到 PII 后，中间件会创建处理后的新消息，并返回 `{'messages': new_messages}` 更新图状态。因此它修改的不只是临时模型请求，最终图状态中的对应消息也会改变。

> **说明：** `block` 是例外：它会抛出 `PIIDetectionError` 并终止 Run，不会把脱敏消息写入状态。`apply_to_output=True` 时，在 `langchain>=1.3.2` 还会通过流转换器处理流式文本增量、工具参数与状态快照；图状态仍由 `after_model` / `before_model` 写入。

### PII 示例

`langchain_project/agents/pii_agent.py`：按拦截位置与策略拆成多个 Agent。`parrot` 回显最后一条输入，便于核对输入侧处理后的文本；固定文本与工具调用规则用于输出侧、工具结果侧。

```python
import re

from langchain.agents import create_agent
from langchain.agents.middleware import PIIMiddleware
from langchain.tools import tool

from langchain_project.core.mock_model import mock_model

def _fixed_response_model(text: str):
  """创建只返回固定文本的模拟模型。"""
  return mock_model(
    {
      "rules": [],
      "responses": [{"text": text}],
    }
  )

def _parrot_model():
  """创建回显最后一条输入消息的模拟模型。"""
  return mock_model({"mode": "parrot"})

# 演示内置 PII 类型以及 redact、mask、hash 三种处理策略。
pii_input_agent = create_agent(
  model=_parrot_model(),
  middleware=[
    PIIMiddleware("email", strategy="redact"),
    PIIMiddleware("credit_card", strategy="mask"),
    PIIMiddleware("ip", strategy="hash"),
    PIIMiddleware("mac_address", strategy="redact"),
    PIIMiddleware("url", strategy="redact"),
  ],
)

# 演示 block：检测到邮箱后直接终止 Run。
pii_block_agent = create_agent(
  model=_fixed_response_model("这条消息不会在拦截成功时返回"),
  middleware=[
    PIIMiddleware("email", strategy="block"),
  ],
)

# 演示使用正则表达式定义项目自己的 PII 类型。
pii_custom_agent = create_agent(
  model=_parrot_model(),
  middleware=[
    PIIMiddleware(
      "student_id",
      detector=r"STU-\d{6}",
      strategy="redact",
    ),
  ],
)

def detect_phone_number(content: str):
  """检测中国手机号。"""
  matches = []
  for match in re.finditer(r"(?<!\d)1[3-9]\d{9}(?!\d)", content):
    matches.append(
      {
        "value": match.group(),
        "start": match.start(),
        "end": match.end(),
      }
    )
  return matches

# 演示使用检测函数定义项目自己的 PII 类型。
pii_custom_detector_agent = create_agent(
  model=_parrot_model(),
  middleware=[
    PIIMiddleware(
      "phone_number",
      detector=detect_phone_number,
      strategy="mask",
    ),
  ],
)

# 演示模型输出脱敏：模拟模型会固定返回一个邮箱。
pii_output_agent = create_agent(
  model=_fixed_response_model("请联系 support@example.com"),
  middleware=[
    PIIMiddleware(
      "email",
      strategy="redact",
      apply_to_input=False,
      apply_to_output=True,
    ),
  ],
)

@tool
def get_customer_profile() -> str:
  """查询测试客户资料。"""
  return "客户邮箱是 tool@example.com"

# 第一次模型调用生成工具调用，收到工具结果后结束。
_tool_result_model = mock_model(
  {
    "rules": [
      {
        "when": {"last_message": "human"},
        "respond": {
          "tool_calls": [
            {
              "name": "get_customer_profile",
              "args": {},
            }
          ]
        },
      },
      {
        "when": {"last_message": "tool_result"},
        "respond": {"text": "客户资料查询完成"},
      },
    ],
    "responses": [{"text": "客户资料查询完成"}],
  }
)

# 演示工具结果脱敏：在工具结果再次送入模型之前处理。
pii_tool_result_agent = create_agent(
  model=_tool_result_model,
  tools=[get_customer_profile],
  middleware=[
    PIIMiddleware(
      "email",
      strategy="redact",
      apply_to_input=False,
      apply_to_output=False,
      apply_to_tool_results=True,
    ),
  ],
)
```

> **说明：** 检测函数须返回匹配列表，每项含 `value` / `start` / `end`。官方 `PIIMatch` 还可含 `type`；省略时由中间件填为当前 `pii_type`。`pii_output_agent` 关闭 `apply_to_input`，避免把输入侧检查与输出侧检查混在一次演示里。
