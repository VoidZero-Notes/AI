待办清单中间件（`TodoListMiddleware`）让 Agent 在动手之前先把多步骤任务写成结构化列表，再按项执行并回写进度。没有这份列表时，模型只能靠当前上下文里的对话记忆「下一步该做什么」；步骤一多，就容易漏项、重复，或把尚未开始的工作直接标成完成。中间件提供三条互相配合的机制：注入系统提示词、暴露 `write_todos` 工具、把清单写入图状态。本篇给出启用方式，并在 Studio 中用「7 天 LangGraph 入门训练营」观察清单如何随执行推进。

自 `deepagents` v0.7 起，任务规划不再默认开启。需要 `write_todos` 时，将 `TodoListMiddleware` 传入 `create_deep_agent` 的 `middleware`。

文档：[Deep Agents overview](https://docs.langchain.com/oss/python/deepagents/overview) · [`TodoListMiddleware`](https://reference.langchain.com/python/langchain/agents/middleware/TodoListMiddleware)

## 启用待办清单

`langchain_project/agents/demo/todo_demo.py`：将该图登记为 `todo_demo`，供 Studio 加载。

```python
from deepagents import create_deep_agent
from langchain_project.core.config import anthropic_settings
from langchain.chat_models import init_chat_model
from langchain.agents.middleware import TodoListMiddleware

model = init_chat_model(
  model=anthropic_settings.default_model,
  model_provider="anthropic",
  thinking={"type": "disabled"},
)

agent = create_deep_agent(model=model, middleware=[TodoListMiddleware()])
```

## 三项机制

挂上中间件之后，运行时按下面这条链路工作：

```text
注入系统提示词
  → 模型调用 write_todos
    → 更新图状态 todos
      → status: pending | in_progress | completed
```

### 注入系统提示词

每次调用工作模型之前，`wrap_model_call` 把待办相关指令追加到系统消息末尾。这份指令不是用户写的 `system_prompt`，而是中间件自带的规划说明，核心约定包括：

- 任务包含多个相互依赖的步骤时，先调用 `write_todos` 列出完整清单，再开始执行
- 同一时刻只把当前正在做的那一项标为 `in_progress`
- 每完成一步立刻把该项改为 `completed`，并视需要把下一项改为 `in_progress`
- 禁止等到全部做完再一次性把所有项标成 `completed`
- 发现计划有误时，再次调用 `write_todos` 用新列表整体替换旧列表

模型因此知道「何时建清单、何时改状态」，而不是把 `write_todos` 当成可选用可不用的普通工具。本篇 Studio 提示词里「开始任务前创建待办事项，每完成一步立即更新状态」与这份注入指令是同一套约束，用户侧再强调一次，避免模型直接开写文件、跳过规划。

### write_todos

中间件向 Agent 注册工具 `write_todos`。参数是完整的待办数组，每一项包含：

- `content`：这一步要做什么
- `status`：`pending`、`in_progress` 或 `completed`

该工具的语义是**整表替换**，不是「追加一条」或「只改第 N 项」。模型每次调用都必须提交当前完整清单：已完成的项继续带上并标 `completed`，正在做的标 `in_progress`，尚未开始的标 `pending`。同一模型回合内最多调用一次；并行两次 `write_todos` 时无法判定哪一份列表生效，中间件会拒绝这种写法。

工具执行本身几乎不做业务计算，返回值只确认列表已更新。真正留下的是下一节的图状态。

### 更新图状态

`write_todos` 的结果写入图状态的 `todos` 通道（`PlanningState`），而不是只出现在某条 `ToolMessage` 的文本里。因此：

- 后续回合的模型调用可以在状态里读到当前清单，不依赖模型把整份计划背在对话正文中
- Studio 的 Trace 可以直接展开 `todos`，逐项查看 `content` 与 `status`
- 图上会出现 `TodoListMiddleware.after_model`：模型发出 `write_todos` 之后，由该钩子把新列表合并进状态，再进入 `tools` 节点执行其它工具

三项 `status` 的含义固定：

| `status` | 含义 |
| --- | --- |
| `pending` | 尚未开始 |
| `in_progress` | 当前正在执行；同一时刻通常只有一项 |
| `completed` | 已经完成 |

「先计划再行动」指的就是这条闭环：先 `write_todos` 把计划落到 `todos`，再按 `in_progress` 那一项去调文件工具或其它工具，做完立刻把状态写回。计划在图状态里，执行在工具循环里，二者分开。

## Studio 验证

发送：

```text
请设计一个“7 天 LangGraph 入门训练营”，并完成以下任务：
明确目标学员、前置知识和学习目标
设计 7 天课程大纲
为每天设计一个练习和验收标准
将需求、课程大纲、验收清单分别写入三个文件
重新读取三个文件，检查内容是否一致
如果发现遗漏或冲突，修改对应文件
最后汇总交付结果
这是一个多步骤任务。请使用待办清单管理整个执行过程：开始任务前创建待办事项，每完成一步立即更新状态，不要等到最后一次性全部标记完成。
```

图中可见 `TodoListMiddleware.after_model`。模型先调用 `write_todos`，把「明确学员与目标 / 设计大纲 / 设计练习与验收 / 写入三个文件 / 回读检查 / 修正冲突 / 汇总」拆成多项。展开 `todos`：第 0 项 `明确目标学员、前置知识和学习目标` 为 `in_progress`，其余为 `pending`。此时文件尚未写入，清单已经在状态里，后续回合会按项推进并把已完成项改为 `completed`。
