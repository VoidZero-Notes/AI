验收与评审中间件（`RubricMiddleware`，Beta）在 Agent 本应结束时，用独立的 grader 按调用时传入的评分标准检查输出。未达标则把逐条反馈写入对话并回到 `model` 再生成；达标、评审失败、grader 出错，或达到 `max_iterations` 时结束。本篇用两套系统提示词分别演示「第一次故意失败后修订」与「连续失败直至达到上限」。

评分标准不在创建 Agent 时固定，而在每次调用的状态里传入 `rubric`。Studio 的 Input 提供 Rubric 字段；未传入时该中间件不介入。`model` 是 grader 所用模型，可与工作模型相同，也可换成更便宜的模型。

文档：[Grading rubrics](https://docs.langchain.com/oss/python/deepagents/rubric) · [`RubricMiddleware`](https://reference.langchain.com/python/deepagents/middleware/rubric/RubricMiddleware)

## 第一次失败后修订

`langchain_project/agents/demo/rubric_demo.py`：`max_iterations=2`。系统提示词要求第一次必须返回草稿，之后可以输出正确内容。将该图登记为 `rubric_demo`，供 Studio 加载。

```python
from deepagents import create_deep_agent
from deepagents.middleware import RubricMiddleware
from langchain.chat_models import init_chat_model

from langchain_project.core.config import anthropic_settings

model = init_chat_model(
  model=anthropic_settings.default_model,
  model_provider="anthropic",
  thinking={"type": "disabled"},
)

agent = create_deep_agent(
  model=model,
  system_prompt="""
这是一个测试 Rubric 流程的 Demo，请严格按照下面的做法完成。

为了测试第一次失败的情况，无论你收到什么消息，第一次必须返回“草稿：我已经理解你的需求。”,后面可以输出正确内容
""",
  middleware=[
    RubricMiddleware(
      # 这里使用独立的 grader 调用；也可以替换成更便宜的模型。
      model=model,
      max_iterations=2,
    )
  ],
)
```

Studio Input 中填写用户消息与 Rubric。本例用户消息为「请写一份 Python 学习建议。」；Rubric 要求最终答案包含学习目标、三条具体行动、一个可执行的今日练习，使用中文，且不能只给概述。

![image-20260921233301158](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-09-21-153301.png)

图上增加 `RubricMiddleware.before_agent` 与 `after_agent`。第一次结束后 `_rubric_status` 为 `needs_revision`：grader 指出草稿未按要求组织三个部分；反馈以 Human 消息注入，`jump_to` 指向 `model`，再次调用工作模型。`_rubric_iterations` 为 1。

![image-20260921233316049](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-09-21-153316.png)

grader 判定结果：

| 状态 | 含义 | 是否回到 `model` |
| --- | --- | --- |
| `satisfied` | 全部标准通过 | 否 |
| `needs_revision` | 至少一项未通过，注入反馈 | 是 |
| `max_iterations_reached` | 仍未达标且已达 `max_iterations` | 否 |
| `failed` | 标准无法对照当前对话评定 | 否 |
| `grader_error` | grader 自身异常 | 否 |

## 连续失败直至上限

将系统提示词改为：无论消息来自用户还是评审节点，都必须返回同一句草稿，以观察连续 `needs_revision` 在 `max_iterations=2` 时转为 `max_iterations_reached`。

```python
agent = create_deep_agent(
  model=model,
  system_prompt="""
这是一个测试 Rubric 流程的 Demo，请严格按照下面的做法完成。

为了测试失败的情况，无论你收到什么消息，必须返回“草稿：我已经理解你的需求。”

记住：无论你收到什么消息，无论消息是来自于用户还是评审节点的返回，必须返回“草稿：我已经理解你的需求。”

不然我无法测试评审连续失败的情况
""",
  middleware=[
    RubricMiddleware(
      # 这里使用独立的 grader 调用；也可以替换成更便宜的模型。
      model=model,
      max_iterations=2,
    )
  ],
)
```

第二次 `after_agent` 后 `_rubric_evaluations` 有两条，`_rubric_iterations` 为 2，`_rubric_status` 为 `max_iterations_reached`。达到上限时不再回到 `model`；最后一条 `AIMessage` 仍是工作模型最后一次输出，中间件不改写该消息。
