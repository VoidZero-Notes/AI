身份认证通过之后，授权决定当前用户能否对某一资源执行本次动作。处理函数把资源与动作拼成权限字符串 `{资源}:{动作}`，再与该用户的权限列表比对；未列入则拒绝请求。本篇给出三名模拟用户的权限、认证与全局授权处理函数，并用创建助手的调用对比缺少 `assistants:create` 的用户与持有该权限的管理员。下图中，请求先经过身份认证，再经过授权，最后到达接口：第一位调用方两层都通过，第二位通过认证但在授权层被拒绝，第三位未通过认证，不会进入授权。

## 认证与授权

`langchain_project/core/auth.py` 创建 `Auth` 实例。`@auth.authenticate` 校验请求头 `Authorization: Bearer <token>`：值为空、无法分离出令牌，或令牌不在 `MOCK_USER` 中时，抛出状态码 401、详情为 `invalid token` 的 `HTTPException`。令牌命中时返回对应用户。注释中的用户中心，是生产环境按令牌换取身份的位置；示例用本地字典代替。

`@auth.on` 注册全局授权处理函数，对各类资源与动作生效。函数用 `ctx.resource` 与 `ctx.action` 拼出权限字符串，创建助手即为 `assistants:create`。该字符串在 `ctx.permissions` 中则返回 `True`，请求继续；否则返回 `False`，请求被拒绝。参数 `value` 为本次请求体，此函数未使用。

```python
from typing import Never

from langgraph_sdk import Auth
from .mock_user import MOCK_USER

auth = Auth()

def _raise_invalid_token() -> Never:
  raise Auth.exceptions.HTTPException(status_code=401, detail="invalid token")

@auth.authenticate
async def authenticate(
  authorization: str | None,
) -> Auth.types.MinimalUserDict:
  """验证 Authorization: Bearer <token> 并返回当前用户。"""
  if not authorization:
    _raise_invalid_token()
  schema, sep, token = authorization.partition(" ")
  if not token:
    _raise_invalid_token()
  # 解析token，通常要访问后端web服务（用户中心）
  if token not in MOCK_USER:
    _raise_invalid_token()

  return MOCK_USER[token]

@auth.on
async def authorization(ctx: Auth.types.AuthContext, value: dict):
  permission = f"{ctx.resource}:{ctx.action}"
  if permission not in ctx.permissions:
    return False
  return True
```

> **说明：** `authorization.partition(" ")` 将 `Bearer <token>` 分为模式、分隔符与令牌，函数只使用第三段。`ctx.permissions` 来自认证阶段返回的用户字典。返回 `False` 时，调用方得到 `PermissionDeniedError`，详情为 `Forbidden`。
