HITL 中间件（`HumanInTheLoopMiddleware`）在模型发出工具调用之后、真正执行之前暂停运行，把批准、修改参数、拒绝或代答交给人。适用于发送邮件、删除文件、资金操作等高风险工具。本篇说明 `interrupt_on` 如何按工具配置中断时机，中断载荷与恢复载荷的格式，以及用 `create_deep_agent` 的 `interrupt_on` 在 Studio 中完成一次审批演示。

LangGraph第22章的中断提供暂停与恢复；第23章的人在回路是在工具函数内部调用 `interrupt()` 向用户提问。本篇把同一机制做成第05章清单中的预置中间件：不改工具函数，只在执行前审批。第06章的 `interrupt_on` 传入后，`create_deep_agent` 会将该中间件加入默认栈。暂停状态靠检查点保存；恢复时用 LangGraph第21章的 `Command(resume=...)` 传回决定。该中间件实现第03章的节点钩子 `after_model`。

文档：[Human-in-the-loop](https://docs.langchain.com/oss/python/langchain/human-in-the-loop) · [Deep Agents HITL](https://docs.langchain.com/oss/python/deepagents/human-in-the-loop) · [`HumanInTheLoopMiddleware`](https://reference.langchain.com/python/langchain/agents/middleware/human_in_the_loop/HumanInTheLoopMiddleware)

| 概念 | 作用 |
| --- | --- |
| `HumanInTheLoopMiddleware` | 预置中间件。在 `after_model` 中检查 `tool_calls`，按 `interrupt_on` 调用 `interrupt()` |
| `interrupt_on` | 工具名到中断策略的映射。`True` / `False` / `InterruptOnConfig`；未列入的工具直接执行 |
| `allowed_decisions` | 审批时可提交的决定类型 |
| `description` / `when` | 审批说明（字符串或回调）；按本次参数决定是否中断 |
| `action_requests` / `review_configs` | 中断载荷：待审调用，以及各调用允许的决定 |
| `decisions` | 恢复载荷，须与 `action_requests` 顺序一一对应 |
| `approve` / `edit` / `reject` / `respond` | 四种决定：原样执行、改参后执行、跳过并返回失败、跳过并返回成功 |

使用 `create_agent` 时，将中间件实例列入 `middleware`。使用 `create_deep_agent` 时，把同一映射传给 `interrupt_on`，由框架注入该中间件。人在回路依赖检查点：经 Agent Server / Studio 调用时由服务注入；本地直接 `invoke` 须自行传入 `checkpointer`，并固定 `thread_id`。

## 配置中断时机

`interrupt_on` 按工具名配置策略：

| 取值 | 行为 |
| --- | --- |
| `True` | 中断，允许 `approve`、`edit`、`reject`、`respond` |
| `False` | 不中断，直接执行 |
| `InterruptOnConfig` | 自定义 `allowed_decisions`、`description`、`when` |
| 未列入 | 默认直接执行 |

`when` 接收本次工具调用请求，返回 `True` 则中断，返回 `False` 则该次调用不进入审批批次。省略 `when` 时，凡列入且不为 `False` 的调用都会中断。`description` 未单独配置时，使用 `description_prefix` 生成审批说明。

```python
from langchain.agents.middleware import HumanInTheLoopMiddleware

def format_description(tool_call, state, runtime):
  """根据本次工具调用动态生成审批说明。"""
  return f"即将写入文件：{tool_call['args']['file_path']}"

def should_interrupt(request):
  """只有写入 /home/user 目录时才中断。"""
  return request.tool_call["args"]["file_path"].startswith("/home/user/")

HumanInTheLoopMiddleware(
  interrupt_on={
    # 调用时始终中断，允许 approve、edit、reject、respond
    "write_file": True,
    # 调用时不中断，直接执行
    "read_file": False,
    # 调用时始终中断，但只允许批准或拒绝
    "delete_file": {
      "allowed_decisions": ["approve", "reject"],
      "description": "删除文件前需要人工确认。",
    },
    # 根据本次工具调用的参数，动态决定是否中断
    "edit_file": {
      "allowed_decisions": ["approve", "edit", "reject"],
      "description": format_description,
      "when": should_interrupt,
    },
  },
  # 没有单独配置 description 时，使用这个前缀生成审批说明
  description_prefix="工具执行前需要人工审批",
)
```

执行顺序：模型返回带 `tool_calls` 的消息后，`after_model` 按上表筛选；需要审批则调用 `interrupt()`，图停在 `HumanInTheLoopMiddleware.after_model`。恢复后，中间件按 `decisions` 处理：`approve` / `edit` 进入 `tools` 节点执行；`reject` / `respond` 合成 `ToolMessage` 交回模型，不执行该工具。

## 中断消息格式

中断载荷包含两组列表：`action_requests` 是待审的工具调用，`review_configs` 给出每个调用允许的决定。Studio 会在该节点展示同一结构，并等待恢复值。

```json
{
  "action_requests": [
    {
      "name": "write_file",
      "args": {
        "file_path": "/home/user/notes.md",
        "content": "文件内容"
      },
      "description": "工具执行前需要人工审批……"
    }
  ],
  "review_configs": [
    {
      "action_name": "write_file",
      "allowed_decisions": ["approve", "edit", "reject", "respond"]
    }
  ]
}
```

同一模型回合若有多个待审批调用，会合并为一次中断。恢复时 `decisions` 必须与 `action_requests` 顺序一一对应，缺项或错位都会导致恢复失败。

## 恢复中断的消息格式

恢复载荷是 `{"decisions": [...]}`。Studio 在中断节点的 Resume 输入框填入该 JSON；代码侧使用同一对象：

```python
from langgraph.types import Command

agent.invoke(
  Command(resume={"decisions": [{"type": "approve"}]}),
  config={"configurable": {"thread_id": "同一个线程"}},
)
```

`config` 必须与触发中断时使用同一 `thread_id`，检查点才能对上。

### 批准

使用原工具名和原参数继续执行工具。

```json
{
  "decisions": [
    {
      "type": "approve"
    }
  ]
}
```

### 修改后批准

改写工具名或参数后再执行。`edited_action` 必须同时给出 `name` 与 `args`。

```json
{
  "decisions": [
    {
      "type": "edit",
      "edited_action": {
        "name": "write_file",
        "args": {
          "file_path": "/home/user/notes.md",
          "content": "修改后的文件内容"
        }
      }
    }
  ]
}
```

### 拒绝

跳过本次工具执行。`message` 是可选的拒绝原因，中间件会将它作为失败的 `ToolMessage` 返回给模型。省略 `message` 时，框架使用默认拒绝说明，并提示模型不要在用户未要求时重试同一调用。

```json
{
  "decisions": [
    {
      "type": "reject",
      "message": "不允许覆盖该文件，请改用新文件名。"
    }
  ]
}
```

### 代替工具回答

跳过本次工具执行，将 `message` 作为工具的成功返回值交给模型。这种决定适合由人直接回答的工具。

```json
{
  "decisions": [
    {
      "type": "respond",
      "message": "请将文件保存到 /home/user/drafts/notes.md。"
    }
  ]
}
```

> **说明：** `reject` 生成失败的 `ToolMessage`；`respond` 生成成功的 `ToolMessage`。拒绝有副作用的工具应使用 `reject`，不要用 `respond`，否则模型会把该调用当作已经成功。

## 工程文件

### Agent 入口

`langchain_project/agents/demo/hitl_agent_demo.py`：用 `create_deep_agent` 组装演示 Agent。系统提示词要求模型同时调用 `send_mail` 与 `call`，用于对比「未配置中断」与「只审批邮件」两种拓扑。

未配置 `interrupt_on` 时，两个工具都会直接执行。拓扑上只有第06章默认挂上的 `PatchToolCallsMiddleware.before_agent`，没有 HITL 节点。

```python
from deepagents import create_deep_agent
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langchain_project.core.config import anthropic_settings

model = init_chat_model(
  model=anthropic_settings.default_model,
  model_provider="anthropic",
  thinking={"type": "disabled"},
)

@tool
def send_mail(mail: str, title: str, content: str):
  "发送邮件"
  return "邮件已发送"

@tool
def call(tel: str):
  "拨打电话"
  return "电话已拨打"

agent = create_deep_agent(
  model=model,
  system_prompt="这是一个测试的Demo，无论用户发什么样的消息，你要做的事情是同时调用两个工具: send_mail、call，任意填写参数即可。",
  tools=[send_mail, call],
)
```

![image-20260920001031992](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-09-19-161032.png)

传入 `interrupt_on` 后，框架把 `HumanInTheLoopMiddleware` 加入默认栈，拓扑上出现 `HumanInTheLoopMiddleware.after_model`，位于 `model` 与 `tools` 之间。`send_mail` 为 `True`，每次调用都中断；`call` 为 `False`，不进入审批批次。

```python
agent = create_deep_agent(
  model=model,
  system_prompt="这是一个测试的Demo，无论用户发什么样的消息，你要做的事情是同时调用两个工具: send_mail、call，任意填写参数即可。",
  tools=[send_mail, call],
  interrupt_on={
    "send_mail": True,
    "call": False,
  },
)
```

![image-20260920001044970](https://ipic-typora.oss-cn-shenzhen.aliyuncs.com/jishu-img/2026-09-19-161045.png)

Studio 中断面板中的 `action_requests` / `review_configs` 与上一节格式相同。`send_mail` 为 `True`，故 `allowed_decisions` 为四种决定。在 Resume 输入框填入拒绝决定：

```json
{
  "decisions": [
    {
      "type": "reject",
      "message": "没事别发邮箱。"
    }
  ]
}
```

恢复后：`send_mail` 未执行，失败的 `ToolMessage` 把拒绝原因交给模型；`call` 仍执行并返回「电话已拨打」。模型据此汇总：邮件被拒绝，电话已拨打。
