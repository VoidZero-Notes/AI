请求进入 Agent Server 后，先做身份认证，通过后才进入业务接口。调用方在 `Authorization` 头中提交 `Bearer` 令牌；认证处理函数核对该令牌并返回当前用户，服务端把该用户写入本次运行的配置。令牌缺失或无法识别时，请求以 HTTP 401 结束。下图中，前两位调用方通过认证并进入接口，第三位停在认证层。

![image-20260928152024697](F:\个人\AI\LangChain+DeepAgent\assets\image-20260928152024697.png)

处理函数用 `@auth.authenticate` 注册，并通过 `langgraph.json` 的 `auth.path` 接入服务。下文用 SDK 演示未带令牌与携带 `Bearer user_1` 的调用结果，并说明 LangSmith Studio 默认写入 `kind` 为 `StudioUser` 的用户，以及 `disable_studio_auth` 如何使 Studio 改为走同一套认证。

## 认证处理函数

`langchain_project/core/auth.py` 创建 `Auth` 实例，并用 `@auth.authenticate` 注册异步处理函数。参数 `authorization` 是请求头 `Authorization` 的原文。值为空、无法分离出令牌，或令牌不在 `MOCK_USER` 中时，抛出状态码 401、详情为 `invalid token` 的 `HTTPException`。令牌命中时返回 `MinimalUserDict`：`identity` 必填，`display_name` 与 `permissions` 可选。示例用本地字典代替用户中心；注释里的用户中心，是生产环境按令牌换取身份的位置。

```python
from typing import Never

from langgraph_sdk import Auth

auth = Auth()

def _raise_invalid_token() -> Never:
  raise Auth.exceptions.HTTPException(status_code=401, detail="invalid token")

MOCK_USER: dict[str, Auth.types.MinimalUserDict] = {
  "user_1": {
    "identity": "user_id_001",  # 必填
    "display_name": "铁锤",  # 可选
    "permissions": ["thread:create", "assistant:create"],  # 可选
  },
  "user_2": {
    "identity": "user_id_002",  # 必填
    "display_name": "丧彪",  # 可选
    "permissions": ["thread:create", "assistant:create"],  # 可选
  },
}

@auth.authenticate
async def authenticate(
  authorization: str | None,
) -> Auth.types.MinimalUserDict:
  """验证 Authorization: Bearer <token> 并返回当前用户。"""
  if not authorization:
    _raise_invalid_token()
  schema, sep, token = authorization.partition(" ")
  if not token:
    _raise_invalid_token()
  # 解析token，通常要访问后端web服务（用户中心）
  if token not in MOCK_USER:
    _raise_invalid_token()

  return MOCK_USER[token]
```

> **说明：** `authorization.partition(" ")` 将 `Bearer <token>` 分为模式、分隔符与令牌，函数只使用第三段。`user_1` 对应身份 `user_id_001`（显示名「铁锤」），`user_2` 对应 `user_id_002`（显示名「丧彪」），权限均为 `thread:create` 与 `assistant:create`。

## 注册认证

`langgraph.json` 的 `auth.path` 指向上述 `auth` 对象。服务启动后，线程、助手与运行等接口先执行 `authenticate`。

```json
{
  "python_version": "3.13",
  "source": {
    "kind": "uv",
    "root": "."
  },
  "graphs": {
    "main_agent": "langchain_project.agents.main_agent:agent"
  },
  "env": ".env",
  "auth": {
    "path": "langchain_project.core.auth:auth"
  }
}
```

### 未携带令牌

创建线程时未传 `headers`。请求未附带 `Authorization`，`authenticate` 抛出 401。SDK 将该失败表现为 `AuthenticationError`，详情为 `invalid token`。

```python
thread = await client.threads.create( # type: ignore
  metadata={"__name__": "身份认证测试"}
)
thread_id = thread["thread_id"]
thread_id
```

```text
AuthenticationError: invalid token
```

### 携带令牌

同一创建请求加上 `authorization: Bearer user_1`。令牌命中 `MOCK_USER["user_1"]` 后，线程创建成功。单元格输出的 `thread_id` 与后文运行记录中的线程一致。

```python
thread = await client.threads.create( # type: ignore
  metadata={"__name__": "身份认证测试"},
  headers={
    "authorization": "Bearer user_1"
  }
)
thread_id = thread["thread_id"]
thread_id
```

```text
'01a0e6e1-7733-7532-92f9-b7c9258ed35a'
```

## Studio 注入的用户

在 LangSmith Studio 中新建线程并发送消息时，该次运行的用户由服务端直接写入，`kind` 为 `StudioUser`。这条创建请求不进入自定义 `authenticate`，记录中的身份是 `langgraph-studio-user`。

该用户的字段为：

- `kind`：`StudioUser`
- `is_authenticated`：`False`
- `identity` 与 `display_name`：`langgraph-studio-user`
- `permissions`：空列表

运行元数据中 `from_studio` 为 `True`。下面的 `runs.list` 仍携带 `Bearer user_1`，只用于通过读取接口自身的认证。返回记录里的 `langgraph_auth_user` 保持运行创建时写入的 `StudioUser`。

await client.runs.list( # type: ignore

  headers={
    "authorization": "Bearer user_1"

## 关闭 Studio 旁路

`auth.disable_studio_auth` 设为 `true` 后，Studio 与 SDK 一样必须提交能通过 `authenticate` 的令牌，服务端不再为 Studio 写入 `StudioUser`。省略号表示其余字段与上文 `langgraph.json` 相同。

```json
{
  ...
  "auth": {
    "path": "langchain_project.core.auth:auth",
    "disable_studio_auth": true
  }
}
```

缺少该令牌时，Studio 初始化失败，页面提示 `Unauthorized. Invalid token`。

![image-20260928153401685](F:\个人\AI\LangChain+DeepAgent\assets\image-20260928153401685.png)

在 Server connection settings 中，Base URL 填 `http://127.0.0.1:2024`。Custom Headers 增加 `Authorization`，值为 `Bearer user_1`。浏览器把该头带到发往此服务的请求上，请求随后进入 `authenticate`。
