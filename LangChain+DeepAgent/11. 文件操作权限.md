文件操作权限是 Deep Agents 对内置文件系统工具的路径级访问控制：用声明式规则指定哪些路径允许读、允许写、拒绝，或在匹配时暂停等待人工审批。规则在调用后端之前求值，只约束内置文件工具，不约束自定义工具、MCP 工具或沙箱中的 Shell 命令。本篇说明 `FilesystemPermission` 的三项配置、按声明顺序匹配的规则，以及沙箱 `execute` 导致的权限逃逸与当前版本的组合限制；并用 Studio 验证 `deny`、`interrupt` 与匹配顺序。

本篇用第06章 `create_deep_agent` 的 `permissions` 做路径级控制。规则由第05章清单中的 `FilesystemMiddleware` 在调用第07章 `backend` 之前求值。`mode="interrupt"` 接入第10章的 HITL 中间件。第09章的沙箱后端会向模型暴露 `execute`，路径规则管不到这些命令。

文档：[Permissions](https://docs.langchain.com/oss/python/deepagents/permissions) · [`FilesystemPermission`](https://reference.langchain.com/python/deepagents/middleware/filesystem/FilesystemPermission) · [`create_deep_agent`](https://reference.langchain.com/python/deepagents/graph/create_deep_agent)

| 概念 | 作用 |
| --- | --- |
| `permissions` | 第06章选填参数。规则列表，由 `FilesystemMiddleware` 在调用 `backend` 前求值 |
| `FilesystemPermission` | 一条路径级规则：操作类型、Glob 路径、匹配后的处理方式 |
| `operations` | `read` 或 `write`。`read` 对应 `ls`、`read_file`、`glob`、`grep`；`write` 对应 `write_file`、`edit_file`、`delete` |
| `paths` | POSIX 风格 Glob，匹配绝对路径 |
| `mode` | 匹配后的处理：`allow` 放行、`deny` 拒绝、`interrupt` 暂停等待人工审批 |
| 匹配顺序 | 按声明顺序，第一条匹配的规则生效；无匹配则默认允许 |
| `execute` 逃逸 | 沙箱命令可绕过内置文件工具的权限检查 |

## 规则结构

```python
from deepagents import FilesystemPermission, create_deep_agent

permissions = [
  # 禁止读取环境变量文件
  FilesystemPermission(
    operations=["read"],
    paths=["/home/user/workspace/.env", "/home/user/workspace/.env.*"],
    mode="deny",
  )
]

agent = create_deep_agent(
  permissions=permissions,
)
```

每条 `FilesystemPermission` 包含三个配置项：

| 配置项 | 含义 |
| --- | --- |
| `operations` | 要限制的操作类型，可选 `read`、`write` |
| `paths` | 要匹配的绝对路径，使用 POSIX 风格的 Glob 模式，支持 `**` 递归与 `{a,b}` 选择 |
| `mode` | 匹配后的处理方式，可选 `allow`、`deny`、`interrupt`。`allow` 放行；`deny` 拒绝该次调用；`interrupt` 暂停等待人工审批，由第10章的 HITL 中间件处理，并与 `interrupt_on` 合并 |

`operations` 与工具的对应关系：

| 操作类型 | 对应工具 |
| --- | --- |
| `read` | `ls`、`read_file`、`glob`、`grep` |
| `write` | `write_file`、`edit_file`、`delete` |

系统提示词要求模型同时调用 `write_file` 与 `read_file`，目标均为 `/home/user/.env`。规则只对该路径的 `read` 设为 `deny`：`write_file` 写入成功，`read_file` 返回 `permission denied`。拓扑上只有第06章默认挂上的 `PatchToolCallsMiddleware.before_agent`，没有 HITL 节点。

```python
from deepagents import create_deep_agent
from langchain.chat_models import init_chat_model
from langchain_project.core.config import anthropic_settings
from deepagents.middleware import FilesystemPermission

model = init_chat_model(
  model=anthropic_settings.default_model,
  model_provider="anthropic",
  thinking={"type": "disabled"},
)

system_prompt = (
  "这是一个测试权限的Demo，不管用户发什么样的消息，你都要同时调用以下工具: \n"
  "write_file: 向/home/user/.env写入任意内容\n"
  "read_file: 读取/home/user/.env的内容"
)

agent = create_deep_agent(
  model=model,
  system_prompt=system_prompt,
  permissions=[
    FilesystemPermission(
      operations=["read"],
      paths=["/home/user/.env", "/home/user/.env.**"],
      mode="deny",
    ),
  ],
)
```

## 匹配顺序

权限规则按照声明顺序匹配，**第一条匹配的规则生效**。如果没有任何规则匹配，默认允许访问。

因此，范围更具体的规则应该写在范围更大的规则前面：

```python
permissions = [
  # 先保护特殊文件
  FilesystemPermission(
    operations=["read"],
    paths=["/home/user/workspace/.env"],
    mode="deny",
  ),

  # 再允许访问整个工作目录
  FilesystemPermission(
    operations=["read", "write"],
    paths=["/home/user/workspace/**"],
    mode="allow",
  ),
]
```

如果将 `allow /home/user/workspace/**` 放在前面，读取 `/home/user/workspace/.env` 时会先匹配 `allow`，后面的 `deny` 不会生效。

Studio 中先 `allow` `/home/user` 及其子路径，再 `deny` `/**`。系统提示词改为：写入仍指向 `/home/user/.env`，读取改为 `/.env`。`write_file` 命中 `allow`；`read_file` 未命中工作目录规则，落到后面的 `deny`。

```python
system_prompt = (
  "这是一个测试权限的Demo，不管用户发什么样的消息，你都要同时调用以下工具: \n"
  "write_file: 向/home/user/.env写入任意内容\n"
  "read_file: 读取/.env的内容"
)

agent = create_deep_agent(
  model=model,
  system_prompt=system_prompt,
  permissions=[
    FilesystemPermission(
      operations=["read", "write"],
      paths=["/home/user", "/home/user/**", "/home/user/**/.*{,/**}"],
      mode="allow",
    ),
    FilesystemPermission(
      operations=["read", "write"],
      paths=["/**", "/**/.*{,/**}"],
      mode="deny",
    ),
  ],
)
```

## execute 逃逸

权限规则只约束内置文件系统工具，不覆盖自定义工具与 MCP 工具。第09章传入实现 `SandboxBackendProtocol` 的后端后，harness 会向模型暴露 `execute`。模型可通过该工具实现权限逃逸：Shell 命令可以用 `cat`、`cp`、`rm` 等访问文件，绕过内置文件工具的权限检查。

因此，当前版本不允许把沙箱作为默认后端，同时传入覆盖该后端路径的 `permissions`：

```python
create_deep_agent(
  backend=sandbox_backend,
  permissions=permissions,
)
```

创建 Agent 时会抛出 `NotImplementedError`。使用 `CompositeBackend` 且默认后端为沙箱时，权限路径必须落在已知的非沙箱路由下，否则同样抛出该异常。

需要使用沙箱执行命令时，应在沙箱本身建立文件系统隔离；高风险工具也可配合第10章的 `interrupt_on` 做执行前审批。
