代码解释器中间件（`CodeInterpreterMiddleware`）给 Agent 一个隔离的 QuickJS REPL。模型把编排逻辑写成 JavaScript，经 `eval` 在解释器里执行；循环、分支、筛选都在代码中完成，只有最后一条表达式的返回值回到模型。本篇先说明普通工具循环无法「根据上一次结果再遍历、再调用下一个工具」的原因，再给出无解释器的分页审计对照，然后启用 Programmatic Tool Calling（PTC）用一次 `eval` 拉完全部分页，最后列出配置项。解释器为 Beta，需要 `langchain-quickjs`。

文档：[Interpreters](https://docs.langchain.com/oss/python/deepagents/interpreters)

## 安装

```bash
uv add langchain-quickjs
```

## 普通工具循环的限制

Agent 默认是「模型推理 → 发出工具调用 → 观察结果 → 再推理」。模型在**同一回合**里可以并行发出若干次调用，但那一批调用在发出的瞬间就固定了：不能先看到工具 D 的返回，再根据每条结果决定要不要调工具 E。要把 D 的输出送进下一次调用，必须再开一个模型回合。典型依赖链如下：

```text
判断上一工具的结果
  - 调工具 D
    - 将 D 的结果遍历
      - 判断……
  - 调工具 E
```

落到本篇的退款审计：D 是 `get_refund_events_page`（一页最多 5 条，共 50 条），遍历的是每一页的 `events`，判断条件是「金额 > 8000 且带 `duplicate_charge`」，E 在更一般的场景里可以是「对命中订单再查详情 / 再发通知」；本例的 E 退化成在内存里筛选、排序。没有解释器时，模型必须：

1. 调 D，拿到一页（含很长的 `customer_chat_log`）
2. 整页进入上下文，由模型判断这 5 条里有没有命中
3. 根据 `next_cursor` 再调 D，再把下一页全部读进上下文
4. 重复直到 `next_cursor` 为 `null`
5. 最后在对话历史里做汇总

每一页的中间结果都要回模型；模型既要记住已经看过哪些 `cursor`，又要在越来越长的上下文里做过滤。一次模型回合不能写 `while`，也不能保证 10 页全部走到——它倾向于抽样，而不是穷尽。解释器要解决的就是这件事：把「遍历 D 的结果 → 判断 → 再行动」从模型回合里挪到代码里。

## 无解释器时的分页审计

`langchain_project/agents/demo/interpreter_demo.py`：自定义工具 `get_refund_events_page` 每次最多返回 5 条退款事件，并附带较长的 `customer_chat_log`。本段不挂 `CodeInterpreterMiddleware`。将该图登记为 `interpreter_demo`，供 Studio 加载。

```python
from deepagents import create_deep_agent
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langchain_quickjs import CodeInterpreterMiddleware

from langchain_project.core.config import anthropic_settings

TOTAL_EVENTS = 50
PAGE_SIZE = 5

@tool
def get_refund_events_page(cursor: int = 0) -> dict:
  """读取一页退款事件。

  参数：
  - cursor：本页第一条事件的下标。首次调用传 0；后续调用必须原样传入
    上一页返回的 next_cursor。

  返回一个字典，字段含义如下：
  - events：本页退款事件列表，固定最多 5 条。
  - events[].order_id：订单唯一编号。
  - events[].refund_amount：退款金额，单位为元。
  - events[].risk_tags：该订单的风险标签列表，例如 duplicate_charge 表示重复扣款。
  - events[].customer_chat_log：完整客服沟通记录，内容较长；仅在需要分析聊天内容时使用。
  - next_cursor：下一页的 cursor。为整数时说明还有下一页；为 null 时说明已读取全部事件，
    不应再调用此工具。
  """
  if cursor < 0 or cursor > TOTAL_EVENTS:
    raise ValueError("cursor 不合法")

  events = [_build_refund_event(index) for index in range(cursor, cursor + PAGE_SIZE)]
  next_cursor = cursor + PAGE_SIZE
  return {
    "events": events,
    "next_cursor": next_cursor if next_cursor < TOTAL_EVENTS else None,
  }

def _build_refund_event(index: int) -> dict:
  duplicate_charge_indexes = {7, 19, 31, 43}
  is_duplicate_charge = index in duplicate_charge_indexes
  refund_amount = (
    9_000 + index * 10 if is_duplicate_charge else 500 + (index * 1_379) % 7_000
  )
  risk_tags = ["refund", "manual_review"]
  if is_duplicate_charge:
    risk_tags.append("duplicate_charge")

  return {
    "order_id": f"ORD-2026-{index + 1:04d}",
    "refund_amount": refund_amount,
    "risk_tags": risk_tags,
    "customer_chat_log": (
      f"订单 {index + 1} 的客服沟通记录：客户描述付款、退款和物流情况。"
      "客服已核对支付流水并记录处理过程。" * 25
    ),
  }

model = init_chat_model(
  model=anthropic_settings.default_model,
  model_provider="anthropic",
  thinking={"type": "disabled"},
)

system_prompt = """你是一个退款事件审计助手。

你可以使用 get_refund_events_page 分页读取退款事件，并根据用户的条件完成审计。
"""

agent = create_deep_agent(
  model=model,
  tools=[get_refund_events_page],
  system_prompt=system_prompt,
)
```

发送：

```text
请帮我审计全部退款事件：找出退款金额超过 8000 元，且 risk_tags 包含 duplicate_charge 的订单。

请按退款金额从高到低列出订单号和退款金额；不要展示其他订单，也不要展示 customer_chat_log。
```

图上是上一节那条依赖链被拆成多次 `model ⇄ tools`：每次只调一页 `get_refund_events_page`，整页（含 `customer_chat_log`）回到模型后再决定下一个 `cursor`。翻页次数等于页数，中间结果全部留在上下文里。

## eval 与 ECMAScript

中间件向 Agent 增加工具 `eval`。模型不直接操作解释器，只负责写出代码并调用 `eval`。执行链路是：

```text
code → eval → JS 解释器（ECMAScript）
```

1. **code**：模型生成一段 JavaScript 源码，作为 `eval` 的参数
2. **eval**：普通工具调用，进入 `tools` 节点
3. **JS 解释器**：QuickJS 在隔离上下文中执行这段源码，返回最后一条表达式的值（以及可选的 `console` 输出）

解释器实现的是 **ECMAScript**，即「语法 + 标准库」，不是 Node.js，也不是浏览器运行时。

- **语法**：`let` / `const`、`if` / `while` / `for`、函数、`async` / `await`、`Promise`、对象与数组字面量
- **标准库**：`Array`（`map` / `filter` / `sort`）、`Object`、`JSON`、`Math`、`Map` / `Set`、`Promise` 等语言内置对象

下列能力**不存在**，因为它们属于宿主运行时，不属于 ECMAScript 语言本身：

| 运行时 | 常见全局 | 本解释器 |
| --- | --- | --- |
| Node.js | `require`、`fs`、`http`、`process` | 无 |
| 浏览器 | `window`、`document`、`fetch`、DOM | 无 |

因此脚本里不能 `fetch(url)` 去拉退款数据，也不能碰 `window` / `document`。默认同样不能访问宿主文件系统、网络、Shell、包管理器或时钟。解释器里能做的，是纯计算，以及下面两条显式桥接：

- **PTC**：把白名单内的 Agent 工具挂到全局 `tools` 上，供脚本 `await`。工具名转为 camelCase，入参仍按原 schema，故 `get_refund_events_page` 写成 `tools.getRefundEventsPage({ cursor })`
- **`task(...)`**：当前 Agent 带 Deep Agents 的 `task` 工具且 `subagents=True` 时，可在脚本里派生子 Agent

PTC 默认关闭，必须传入 `ptc=[...]` 才会把工具送进 JavaScript。开启之后，上一节那条「调 D → 遍历 → 判断 → 再行动」可以写成 `while (cursor != null) { const page = await tools.getRefundEventsPage({ cursor }); ... }`：翻页、丢掉 `customer_chat_log`、按金额与标签过滤、排序，全部在一次 `eval` 内完成。中间每一页都不回模型；模型只看到最后一条表达式给出的精简数组。

## 一次 eval 完成审计

同一文件换用下面的系统提示词，并挂上 `CodeInterpreterMiddleware(ptc=[get_refund_events_page])` 后重新部署。再次发送同一条用户消息。

````python
system_prompt = """你是一个退款事件审计助手。

禁止直接调用 get_refund_events_page、task 或任何文件系统工具。
必须立刻调用一次 eval，在 JavaScript 里用
await tools.getRefundEventsPage({ cursor }) 完成全部工作。

硬性规则：
1. 整个任务只允许一次 eval。未调用 eval 之前不准回复用户。
2. 用 while 按 next_cursor 拉完全部分页；next_cursor 为 null 立即停止。
3. 禁止自行对 cursor 做 +1 或 +5，必须原样使用返回的 next_cursor。
4. 丢掉 customer_chat_log，只保留 order_id、refund_amount、risk_tags。
5. 筛选、排序、汇总全部在 JS 里完成；最后一条表达式只返回精简结果。
6. eval 结束后根据 JS 返回值直接给出最终答案，禁止再翻页或再 eval。

必须按这个骨架写：
```javascript
const events = [];
let cursor = 0;
while (cursor != null) {
  const page = await tools.getRefundEventsPage({ cursor });
  for (const event of page.events) {
    events.push({
      order_id: event.order_id,
      refund_amount: event.refund_amount,
      risk_tags: event.risk_tags,
    });
  }
  cursor = page.next_cursor;
}
// 在这里按用户条件筛选/排序
events;
```

"""

agent = create_deep_agent(
  model=model,
  tools=[get_refund_events_page],
  system_prompt=system_prompt,
  middleware=[CodeInterpreterMiddleware(ptc=[get_refund_events_page])],
)
````

图上增加 `CodeInterpreterMiddleware.before_agent` 与 `after_agent`。`tools` 节点只出现一次 `eval`；返回的 `<result>` 已是筛选、排序后的四条订单，不含 `customer_chat_log`。分页与过滤发生在 JavaScript 内，不经过父级 `ToolNode`。

Playground 中可见模型发出的 `eval` 代码：`while` 拉页、丢掉聊天记录、按金额与 `duplicate_charge` 过滤并降序。工具结果为 `ORD-2026-0044`（9430）、`ORD-2026-0032`（9310）、`ORD-2026-0020`（9190）、`ORD-2026-0008`（9070）。

## 配置

`CodeInterpreterMiddleware` 提供的是隔离的 JavaScript QuickJS REPL，不是 Python 解释器。

```python
CodeInterpreterMiddleware(
  memory_limit=64 * 1024 * 1024,
  timeout=5.0,
  max_ptc_calls=256,
  tool_name="eval",
  max_result_chars=4000,
  capture_console=True,
  subagents=True,
  ptc=None,
  mode="thread",
  max_snapshot_bytes=None,
)
```

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `memory_limit` | `64 * 1024 * 1024` | QuickJS 堆内存上限，单位为字节，即默认 64 MiB。 |
| `timeout` | `5.0` | 每次调用 `eval` 的最长执行时间，单位为秒。 |
| `max_ptc_calls` | `256` | 单次 `eval` 中，JavaScript 通过 `tools.xxx()` 最多调用工具的次数。设为 `None` 表示不限制；不可信输入下可能出现无限调用，应谨慎使用。 |
| `tool_name` | `"eval"` | 暴露给模型的 JavaScript 执行工具名称。 |
| `max_result_chars` | `4000` | 执行结果和标准输出分别最多返回的字符数；超出会截断，`console` 缓冲区也受此值限制。 |
| `capture_console` | `True` | 是否提供并捕获 `console.log`、`console.warn`、`console.error`；捕获内容以 `<stdout>` 返回。 |
| `subagents` | `True` | 当前 Agent 有 Deep Agents 的 `task` 工具时，是否在 JavaScript 中提供 `task(...)`。设为 `False` 后，子 Agent 只能走普通的父 Agent 工具调用路径。 |
| `ptc` | `None` | Programmatic Tool Calling 工具白名单。传入工具名或 `BaseTool` 列表后，可以在 JavaScript 中通过 `tools.<camelCase>(input)` 调用。 |
| `mode` | `"thread"` | JavaScript 状态保存范围：`"thread"` 跨调用、跨轮次保存；`"turn"` 只在同一轮内保存；`"call"` 每次 `eval` 都重新创建环境。 |
| `max_snapshot_bytes` | `None` | 中间件保存 JavaScript 状态快照的最大字节数。默认等于 `memory_limit`；超过上限时快照被丢弃，后续不能恢复该状态。 |

> **说明：** `ptc` 调用和 JavaScript 内的 `task(...)` 都不走普通 `ToolNode` 路径，因此不会为每一次内部调用触发父级的 `interrupt_on` / 人工审批。
