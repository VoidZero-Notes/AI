动态提示词与动态模型是两类运行时覆盖：每次调用模型前，根据当次 `Runtime.context` 改写系统提示词，或替换本次使用的模型实例（含 `temperature`、`thinking`，以及 Mock Model）。二者都通过包裹钩子 `wrap_model_call` 实现：从 `request.runtime.context` 读取字段，调用 `request.override(...)` 得到新请求，再交给 `handler`。创建 Agent 时登记 `context_schema`；经 Agent Server 时，Studio 的 Assistant 表单写入该 context。

本篇使用的是 03 中的 `@wrap_model_call`（函数式写法，装饰异步函数时等价于类上的 `awrap_model_call`）。`context_schema` 对应 LangGraph第12章 Runtime 的运行时配置通道，不写入图状态。Agent底层逻辑第06章的系统提示词是静态约束；`create_agent` 的 `system_prompt` 仍作默认值，当次追加的提示词来自 `context.system_prompt`。LangGraph第10章用 `configurable_fields` 覆盖模型参数；Chat Model 不读取 `Runtime.context`，本篇改为在中间件里 `init_chat_model`（LangGraph第02章的模型）并 `override(model=...)`。`model_name == "fake"` 时使用 LangGraph第09章的 Mock Model。

文档：[Custom middleware](https://docs.langchain.com/oss/python/langchain/middleware/custom) · [Context](https://docs.langchain.com/oss/python/concepts/context)

| 概念 | 作用 |
| --- | --- |
| `PromptContext` | context schema，字段为当次系统提示词 |
| `ModelConfigContext` | 继承 `PromptContext`，增加 `model_name` / `temperature` / `thinking` |
| `@wrap_model_call` | 函数式包裹钩子，包住每次模型调用 |
| `request.override` | 不可变替换本次请求的字段，返回新的 `ModelRequest` |
| `handler` | 进入内层中间件，或真正发起模型调用 |

## 动态提示词

默认系统提示词在 `create_agent` 时固定。中间件在每次模型调用前，把 `context.system_prompt` 追加到该默认值之后，再覆盖本次请求的系统消息。Studio 为同一张图建多个 Assistant 时，各 Assistant 可写入不同的当次提示词，无需改代码、无需重建图。

框架另有 `@dynamic_prompt`，返回值会整段替换系统提示词。本篇用更通用的 `wrap_model_call`，以便与默认提示词拼接。

### context schema

`langchain_project/schemas/prompt_context_shcema.py`：声明允许写入 context 的字段。文件名沿用工程底稿中的拼写。

```python
from pydantic import BaseModel, Field

class PromptContext(BaseModel):
  system_prompt: str = Field(description="系统提示词", default="")
```

### 中间件

`langchain_project/middlewares/dynamic_prompt.py`：若 `request.system_prompt`（创建 Agent 时的默认值）或 `context.system_prompt` 非空，则依次放入列表，构造 `SystemMessage` 后 `override`。

```python
from collections.abc import Awaitable, Callable
from typing import Any, Callable

from langchain.agents.middleware import AgentMiddleware, wrap_model_call
from langchain.agents.middleware.types import (
  ExtendedModelResponse,
  ModelRequest,
  ModelResponse,
)
from langchain.agents import AgentState
from langchain_core.messages import AIMessage
from langchain_project.schemas.prompt_context_shcema import PromptContext
from langchain.messages import SystemMessage

@wrap_model_call
async def dynamic_prompt(
  request: ModelRequest[PromptContext],
  handler: Callable[[ModelRequest[PromptContext]], Awaitable[ModelResponse[Any]]],
) -> ModelResponse[Any] | AIMessage | ExtendedModelResponse[Any]:
  prompts = []
  if request.system_prompt:
    prompts.append(request.system_prompt)

  if request.runtime.context and request.runtime.context.system_prompt:
    prompts.append(request.runtime.context.system_prompt)
  system_msg = SystemMessage(prompts)
  override_request = request.override(system_message=system_msg)
  response = await handler(override_request)
  return response
```

> **说明：** `ModelRequest.system_prompt` 已弃用，现行字段为 `system_message`。本例仍用前者读取创建时的字符串默认值。`SystemMessage` 接收字符串列表时，多段提示词会一并写入本次请求。

### 注入 Agent

`langchain_project/agents/main_agent.py`：登记 `context_schema=PromptContext`，并把该中间件列入 `middleware`。`system_prompt="输出尽量简洁"` 是默认值，Studio 写入的当次提示词追加在其后。

```python
from langchain.agents import create_agent
from langchain_project.core.config import anthropic_settings
from langchain_project.tools import tools
from langchain_project.schemas.prompt_context_shcema import PromptContext
from langchain_project.middlewares.dynamic_prompt import dynamic_prompt

agent = create_agent(
  model=f"anthropic:{anthropic_settings.default_model}",
  tools=tools,
  middleware=[dynamic_prompt],
  context_schema=PromptContext,
  system_prompt="输出尽量简洁",
)
```

Studio 为图创建 Assistant「翻译」，把当次系统提示词写入 `context.system_prompt`（例如：只翻译、不回答）。用户输入「你好」后，模型按该指令返回 `Hello`。Tracing 的 System 同时包含默认值「输出尽量简洁」与 Assistant 写入的翻译指令。

## 动态模型

`create_agent` 的 `model` 只提供默认实例。中间件在调用前读取 context 中的 `model_name`、`temperature`、`thinking`：三者皆空则原样交给 `handler`；`model_name == "fake"` 则换成 Mock Model；否则按这些字段 `init_chat_model` 再建实例并 `override(model=...)`。`ModelConfigContext` 继承 `PromptContext`，因此与上一节的动态提示词共用同一份 context。

### context schema

`langchain_project/schemas/model_config_context_schema.py`：在 `PromptContext` 上增加模型字段，缺省均为 `None`，表示不覆盖。

```python
from typing import Any

from .prompt_context_shcema import PromptContext
from pydantic import Field

class ModelConfigContext(PromptContext):
  model_name: str | None = Field(description="模型名称", default=None)
  temperature: float | None = Field(description="温度", default=None)
  thinking: dict[str, Any] | None = Field(description="思考", default=None)
```

### 中间件

`langchain_project/middlewares/dynamic_model.py`：无 context 或三个字段均为 `None` 时不改请求。`thinking` 未提供时写入 `{"type": "disabled"}`。未指定 `model_name` 时回退到 `anthropic_settings.default_model`。

```python
from collections.abc import Awaitable, Callable
from typing import Any, Callable

from langchain.agents.middleware import AgentMiddleware, wrap_model_call
from langchain.agents.middleware.types import (
  ExtendedModelResponse,
  ModelRequest,
  ModelResponse,
)
from langchain.agents import AgentState
from langchain_core.messages import AIMessage
from langchain_project.schemas.model_config_context_schema import ModelConfigContext
from langchain_project.core.mock_model import mock_model
from langchain_project.core.config import anthropic_settings
from langchain.chat_models import init_chat_model

@wrap_model_call
async def dynamic_model(
  request: ModelRequest[ModelConfigContext],
  handler: Callable[
    [ModelRequest[ModelConfigContext]], Awaitable[ModelResponse[Any]]
  ],
) -> ModelResponse[Any] | AIMessage | ExtendedModelResponse[Any]:
  context = request.runtime.context
  if not context:
    return await handler(request)
  model_name = context.model_name
  temperature = context.temperature
  thinking = context.thinking

  if model_name is None and temperature is None and thinking is None:
    return await handler(request)

  if model_name == "fake":
    model = mock_model()
    return await handler(request.override(model=model))

  if not model_name:
    model_name = anthropic_settings.default_model

  model_config = {}
  if temperature is not None:
    model_config["temperature"] = temperature
  if thinking:
    model_config["thinking"] = thinking
  else:
    model_config["thinking"] = {"type": "disabled"}

  model = init_chat_model(
    model=model_name, model_provider="anthropic", **model_config
  )
  response = await handler(request.override(model=model))
  return response
```

> **说明：** `if thinking` 把空字典视为未配置，回退到 `{"type": "disabled"}`。Studio 里填写 `{}` 不会开启思考。

### 注入 Agent

`langchain_project/agents/main_agent.py`：`context_schema` 改为 `ModelConfigContext`。`middleware` 列表中 `dynamic_prompt` 在前、为外层，`dynamic_model` 在内层，两次 `override` 都会生效。

```python
from typing import Any, cast

from langchain.agents import create_agent, AgentState
from langchain_project.core.config import anthropic_settings
from langchain_project.tools import tools
from langchain_project.schemas.model_config_context_schema import ModelConfigContext
from langchain_project.middlewares.dynamic_prompt import dynamic_prompt
from langchain_project.middlewares.dynamic_model import dynamic_model
from langchain.agents.middleware import AgentMiddleware

agent = create_agent(
  model=f"anthropic:{anthropic_settings.default_model}",
  tools=tools,
  context_schema=ModelConfigContext,
  system_prompt="输出尽量简洁",
  middleware=[
    cast(AgentMiddleware[AgentState, ModelConfigContext, Any], dynamic_prompt),
    dynamic_model,
  ],
)
```

> **说明：** `dynamic_prompt` 标注的 context 是 `PromptContext`，Agent 登记的是子类 `ModelConfigContext`。类型检查器无法把前者直接放进后者的 `middleware` 列表，故用 `cast`。运行时兼容：子类含 `system_prompt`。

Assistant「加模型」将 `model_name` 设为 `fake` 时，回复来自 Mock Model（配置文件驱动的模拟回复）。另建 Assistant「真模型-高温」，填写 `model_name`、`temperature`、`thinking` 与当次系统提示词后，Tracing 中 System 仍是默认值与当次提示词拼接，模型为 `qwen3.7-plus`。用户索诗时，按诗人设定与较高 `temperature` 生成《夏之颂》。
