优化当前指定的 AI 技术笔记 Markdown：统一为已优化笔记的体例。不补语言类比、不补对照侧代码。

## 输入

- 用户会 `@` 一个或多个待优化的 `.md` 文件
- 若未指定文件，先问清要优化哪几个，禁止瞎猜

## 风格锚点（必须先读）

在同目录（或同级已优化笔记）中，任选 **1～2 个已优化样本** 作为体例标准。

以这些文件的实际写法为准，不要另发明体例。若同目录尚无已优化样本，以当前文件自身的章节逻辑为准，只做格式与结构统一。

## 必须完成的改造

1. **结构体例**
   - 章节之间不要用单独的 `---` 分隔线（与已优化样本一致）
   - 标题一律不带序号：禁止 `## 0. 全景总览` `## 1. 哲学流派` `### 1.1 xxx` 等形式，直接写 `## 哲学流派`、`### 符号主义`
   - 不使用一级大标题（`# 标题`）作为文首标题；文档以一段引言正文开头，再用 `##` / `###` 分节（与已优化样本一致）
   - 保留原有章节逻辑与作业 / 练习；整体按用户的格式和内容走，不要重写成另一篇
   - 不删减教学内容，不借机大改大纲（纠错、补重要缺口、调段落位置除外，见第 6、7 条）
   - 不补 JavaScript / TypeScript / Node.js / Python 等语言类比，不补对照侧代码块
   - 若主题适合总览，可保留或补文首概念表；不要编造「语言对照表」

2. **缩进统一为 2 空格**
   所有代码块内缩进改为 2 空格；删除 Tab；不要混用 4 空格。

3. **空行收敛（结合上下文判断）**
   正文与代码块内都可能出现连续空行。默认：连续空行最多保留 **1 个**（即段落之间、逻辑分组之间用单个空行隔开）。遇到连续 2 个及以上空行时，先判断是否有语义必要，再决定：

   | 判断 | 处理 |
   | ---- | ---- |
   | **没必要**（最常见） | 压成 1 个空行。例如：段落之间多打了空行；代码块里两组示例之间空了两行；标题与正文、正文与代码围栏之间多空了一行 |
   | **有必要保留 2 个** | 仅当空行本身承担「分隔语义」时保留，例如：刻意隔开两段独立 demo、视觉上区分「错误示例 / 正确示例」、或与锚点样本同一位置也用了双空行。不要为了「好看」或「宽松」而保留 |

   规则：
   - **先看上下文，再动刀**：同一代码块内，逻辑相关的小段用 1 个空行分组即可；无关的两大块才考虑更强分隔
   - **代码块内外同一标准**：Markdown 正文里的多余空行、代码块内部的多余空行都要处理
   - **禁止一刀切删光**：不要把所有空行都删掉变成密不透风；该分段的地方仍保留 1 个空行
   - **禁止制造三空行**：任何位置都不要留下连续 3 个及以上空行
   - 拿不准时对照锚点样本同一类位置的写法

4. **代码围栏**
   - 语言标签要准确（如 `python`、`ts`、`js`、`bash`、`json`、`text`）
   - 不要为了「好看」把说明文字塞进代码块
   - 需要补充差异或易错点时用简短引用块 `> **说明：** ...`

5. **笔记互引与跨目录对应**
   - 引用**当前目录**的笔记：可直接写序号，如 `10`、`10 的 ReAct`
   - 引用**其他目录**的笔记：必须写清「目录 + 第几章 + 主题」，禁止只写目录名加数字。正确：`Agent底层逻辑第10章的 ReAct`、`Agent底层逻辑第17章的 Graph Engineering`。错误：`10`、`Agent底层逻辑 10`（看不出 10 是第几章、讲什么）
   - 优化时检查已有引用：跨目录却没写「第几章 + 主题」的，按上面改掉
   - **主动扫描对应关系**（不只改已有引用）：当前篇如果是在用库 / 框架 / 代码**落地**其他目录已经讲过的概念，必须点明「这篇实现的是哪一章的哪项」。做法：
     1. 看仓库其他笔记目录（如 `Agent底层逻辑/`、`LangGraph/`）和 README 目录表、各篇标题
     2. 对照当前文里出现的概念（ReAct、Graph、Tool Calling、会话、Agent…），有专章就标对应，没有就不要硬凑
     3. 在文首或该概念首次出现处用**一句话**写清关系，不要展开复述那一章
     4. 允许补这一句对应，不算大改大纲；禁止借机写成对照长文
   - 写法要同时说出「实现了什么」和「来自哪一章」。正确：`Agent底层逻辑第10章的 ReAct 是一条 while True……；LangGraph 把控制流画成图再编译运行。` / `Agent底层逻辑第17章的 Graph Engineering 是「多个 loop 怎么接线」；LangGraph 是把这件事落地的库之一。` 错误：只提概念不标章节；或硬链到并无对应的篇

6. **纠错与补缺（以用户原文为底）**
   - 发现写错、示例输出不对、概念不成立、或漏了比较重要且本篇主题已经碰到的点：可以直接改、可以直接补
   - **底线**：按用户的格式和内容来。补的是缺口、改的是错处，不是换一套讲法、换一个大纲、把原文替换掉
   - 禁止：整段重写口吻、扩成另一章的教程、借「完善」塞进用户没在讲的旁支
   - 改完必须在结论里**逐条**说明：改了什么、完善了什么、加了什么（原文哪句/哪段 → 改成什么、为什么）。没有内容改动则写「未改内容」

7. **调整段落位置**
   - 某段放在别的小节更合适（例如概念定义散在示例后、该跟图走的说明离图太远）：可以直接挪，不改句子本身也算允许
   - 只调位置、不改含义时，结论里仍要说：哪一段从哪挪到了哪、为什么更合适
   - 挪的时候注意前后衔接，不要挪完读不通

8. **直接改文件**
   原地更新目标 `.md`，不要只输出 Diff 而不写入。

## 自检

写完后快速确认：

- [ ] 无 `\t`
- [ ] 代码缩进为 2 空格
- [ ] 无语言类比、无对照侧代码块
- [ ] 章节之间无单独 `---` 分隔线
- [ ] 标题无序号，且文首无一级大标题（以引言正文开头）
- [ ] 未把原文整篇换掉；纠错/补缺仍贴着用户的章节与讲法
- [ ] 体例与锚点样本一致（若有样本）
- [ ] 跨目录引用已写成「目录 + 第几章 + 主题」；同目录引用可只写序号
- [ ] 已扫描其他目录：当前篇落地了哪一章的哪项，该标的已用一句话标出；没有对应的没有硬凑
- [ ] 连续空行已按上下文收敛：无必要的双空行已压成单空行；确有分隔必要的才保留双空行；无连续三空行及以上

完成后在结论里交代，不要只说「优化了格式」：

1. 改了哪些文件
2. 体例 / 格式类改造（缩进、空行、标题、围栏等）
3. 段落位置：哪一段从哪挪到哪（没有则省略）
4. 内容：逐条写「改了什么 / 完善了什么 / 加了什么」；没有则写「未改内容」
