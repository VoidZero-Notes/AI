优化当前指定的 AI 技术笔记 Markdown：统一为已优化笔记的体例。不补语言类比、不补对照侧代码。

## 输入

- 用户会 `@` 一个或多个待优化的 `.md` 文件
- 若未指定文件，先问清要优化哪几个，禁止瞎猜

## 风格锚点（必须先读）

在同目录（或同级已优化笔记）中，任选 **1～2 个已优化样本** 作为体例标准。

以这些文件的实际写法为准，不要另发明体例。若同目录尚无已优化样本，以当前文件自身的章节逻辑为准，只做格式与结构统一。

## 必须完成的改造

1. **结构体例**
   - 章节之间不要用单独的 `---` 分隔线（与已优化样本一致）
   - 标题一律不带序号：禁止 `## 0. 全景总览` `## 1. 哲学流派` `### 1.1 xxx` 等形式，直接写 `## 哲学流派`、`### 符号主义`
   - 不使用一级大标题（`# 标题`）作为文首标题；文档以一段引言正文开头，再用 `##` / `###` 分节（与已优化样本一致）
   - 保留原有章节逻辑与作业 / 练习；可修正明显笔误
   - 不删减教学内容，不借机大改大纲
   - 不补 JavaScript / TypeScript / Node.js / Python 等语言类比，不补对照侧代码块
   - 若主题适合总览，可保留或补文首概念表；不要编造「语言对照表」

2. **缩进统一为 2 空格**
   所有代码块内缩进改为 2 空格；删除 Tab；不要混用 4 空格。

3. **空行收敛（结合上下文判断）**
   正文与代码块内都可能出现连续空行。默认：连续空行最多保留 **1 个**（即段落之间、逻辑分组之间用单个空行隔开）。遇到连续 2 个及以上空行时，先判断是否有语义必要，再决定：

   | 判断 | 处理 |
   | ---- | ---- |
   | **没必要**（最常见） | 压成 1 个空行。例如：段落之间多打了空行；代码块里两组示例之间空了两行；标题与正文、正文与代码围栏之间多空了一行 |
   | **有必要保留 2 个** | 仅当空行本身承担「分隔语义」时保留，例如：刻意隔开两段独立 demo、视觉上区分「错误示例 / 正确示例」、或与锚点样本同一位置也用了双空行。不要为了「好看」或「宽松」而保留 |

   规则：
   - **先看上下文，再动刀**：同一代码块内，逻辑相关的小段用 1 个空行分组即可；无关的两大块才考虑更强分隔
   - **代码块内外同一标准**：Markdown 正文里的多余空行、代码块内部的多余空行都要处理
   - **禁止一刀切删光**：不要把所有空行都删掉变成密不透风；该分段的地方仍保留 1 个空行
   - **禁止制造三空行**：任何位置都不要留下连续 3 个及以上空行
   - 拿不准时对照锚点样本同一类位置的写法

4. **代码围栏**
   - 语言标签要准确（如 `python`、`ts`、`js`、`bash`、`json`、`text`）
   - 不要为了「好看」把说明文字塞进代码块
   - 需要补充差异或易错点时用简短引用块 `> **说明：** ...`

5. **直接改文件**
   原地更新目标 `.md`，不要只输出 Diff 而不写入。

## 自检

写完后快速确认：

- [ ] 无 `\t`
- [ ] 代码缩进为 2 空格
- [ ] 无语言类比、无对照侧代码块
- [ ] 章节之间无单独 `---` 分隔线
- [ ] 标题无序号，且文首无一级大标题（以引言正文开头）
- [ ] 未删减原有教学内容，未改大纲
- [ ] 体例与锚点样本一致（若有样本）
- [ ] 连续空行已按上下文收敛：无必要的双空行已压成单空行；确有分隔必要的才保留双空行；无连续三空行及以上

完成后用一两句话说明改了哪些文件、做了哪些类改造即可。
